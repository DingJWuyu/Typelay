# TypeLay 产品规格 v1.0（冻结版）

> 状态：Frozen  
> 用途：替代最初的《基本需求.md》，作为当前阶段唯一有效的产品规格基线。  
> 当前验证平台：Windows  
> 后续目标平台：CachyOS + niri（Wayland）  
> 本文只描述已确认的产品行为与交互规则；技术实现、模型选型、框架选择、性能参数与 POC 结论不在本文冻结范围内。

---

## 1. 产品定义

TypeLay 是一个独立于输入法和具体应用的系统级输入框实时翻译增强层。

用户继续使用原来的应用、原来的输入框和原来的输入法。TypeLay 监听当前获得键盘焦点的可支持文本输入区域，在输入框附近显示一个轻量翻译胶囊，并根据用户配置的语言方向，在本机生成实时译文。

核心目标：

> 用户保持原有输入习惯，在任何受支持的文本输入场景中获得实时、可编辑、可接受的第二语言候选，并通过最少操作把译文写回原输入框。

产品面向任何有跨语言文字输入需求的人，不限定职业、行业或软件生态。

---

## 2. 产品原则

### 2.1 不改变原有输入方式

- 不要求用户更换输入法。
- 不修改输入法本身。
- 不要求目标应用主动适配 TypeLay。
- 用户始终在原应用的原输入框中输入。
- 原输入法的候选词、组合输入、快捷键和日常使用习惯应尽量保持原样。

### 2.2 翻译始终由用户决定是否接受

- 自动生成的译文只作为候选。
- TypeLay 不主动替换原文。
- 只有用户明确执行接受操作后，译文才写入原输入框。
- 接受译文后不自动发送消息、不自动提交表单。

### 2.3 本地优先与隐私边界

- 实际输入文本和译文永远不上传到云端。
- 翻译推理全部在本机完成。
- 软件可以联网检查和下载软件更新、模型更新。
- 默认不保存翻译历史。
- 默认不建立用户账号，也不提供跨设备云同步。
- 密码、PIN、银行卡安全码等敏感输入区域完全忽略。

### 2.4 原应用体验优先

- TypeLay 不应明显拖慢原应用的打字、滚动或动画。
- 浮层不得推动原应用布局。
- 浮层不得因为出现、展开或更新而主动抢走原输入焦点。
- 无法可靠支持的输入区域保持安静，不显示误导性 UI。

## 3. 平台范围

### 3.1 第一验证平台

Windows。

Windows 版本用于验证完整核心链路：

1. 检测当前输入框
2. 读取当前文本或当前选区
3. 本地翻译
4. 浮层跟随输入区域
5. 用户查看或编辑译文
6. 用户通过 Tab 接受译文
7. 将译文安全写回原输入框

### 3.2 后续平台

CachyOS + niri（Wayland）。

Linux 支线必须保持相同的产品语义与主要交互，不允许为了实现方便而改变已经冻结的核心产品行为。平台能力差异由技术设计阶段处理。

---

## 4. 核心使用场景

目标场景包括但不限于：

- 即时聊天
- 邮件
- 浏览器网页输入框
- 社交平台
- 团队协作工具
- 普通桌面应用文本框
- IDE 内的自然语言输入区域
- 其他支持文本输入的应用

### 4.1 默认不启用的区域

对于明显属于机器语言输入的区域，默认不启动翻译，包括：

- 代码编辑区
- 终端
- Shell / 命令输入区域
- 明显的程序代码输入控件

IDE 整体不默认排除。IDE 内的聊天框、搜索框、自然语言输入框仍可正常使用。

---

## 5. 全局启用与排除

### 5.1 默认行为

- TypeLay 默认全局启用。
- 用户可以全局暂停。
- 用户可以永久排除某个应用。
- 被排除应用中不显示胶囊、禁用图标或任何其他 TypeLay 痕迹。
- 用户可以临时隐藏当前输入框的 TypeLay UI；下次重新聚焦时恢复。

### 5.2 暂停状态

全局暂停后：

- 输入框旁保留一个弱化的小入口。
- 用户可以从该入口恢复 TypeLay。
- 暂停状态也可从系统托盘控制。

---

## 6. 浮层基础形态

### 6.1 初始状态

当一个受支持的普通文本输入框获得焦点时，即使尚未输入文字，也显示一个小型胶囊。

示例：

```text
中 → EN
```

或：

```text
Auto → EN
```

胶囊用于持续表达当前语言方向和 TypeLay 是否处于工作状态。

### 6.2 默认位置

- 优先位于输入框右上方附近。
- 根据屏幕剩余空间自动调整位置。
- 不强制固定在某一侧。
- 位置逻辑以保持可见、避免越界、尽量靠近输入框为原则。
- 浮层跟随整个输入框，不跟随文本光标左右移动。

### 6.3 展开行为

用户开始输入有效文本后：

1. 胶囊立即开始展开。
2. 展开过程可以显示轻量的准备 / 翻译状态。
3. debounce 后启动翻译。
4. 翻译结果生成后填入展开区域。

展开动画只属于视觉层：

- 不改变原应用布局。
- 不推动页面。
- 不抢焦点。
- 不改变原输入框位置。

---

## 7. 浮层尺寸与长文本

### 7.1 基础尺寸规则

- 浮层宽度大致跟随输入框，但存在合理最小值和最大值。
- 译文达到宽度限制后自动换行。
- 译文区域存在最大高度。
- 超过限高后内部滚动。

### 7.2 扩展模式

达到限高后，用户可主动展开为更大的悬浮编辑面板。

扩展面板：

- 仍然与当前原输入框绑定。
- 不进入独立全屏工作流。
- 用于阅读和编辑长译文。
- 失去当前输入会话后按正常生命周期关闭。

---

## 8. 翻译范围

### 8.1 默认翻译整个输入框

没有选区时，当前输入框中的全部文本作为一个完整语义单元。

例如：

```text
Hi John，关于昨天那个项目，我觉得我们可以明天下午继续讨论。
```

TypeLay 以完整上下文生成目标语言译文。

### 8.2 选区优先

当用户存在文本选区时：

- 只翻译选中的文本。
- 接受译文时只替换原选区。
- 选区以外文本保持不动。

例如：

```text
Hello John, 明天下午见, thanks.
```

选中：

```text
明天下午见
```

接受后目标结果可为：

```text
Hello John, see you tomorrow afternoon, thanks.
```

### 8.3 选区锚点

- 能可靠获得选区坐标时，浮层靠近选区。
- 无法可靠获得选区坐标时，回退到整个输入框的默认锚点。
- 用户拖动扩大或缩小选区时，等待选区稳定后再重新翻译。
- 选区替换完成后取消选中，并把光标放到替换文本末尾。

### 8.4 选区安全

用户进入译文编辑区时，TypeLay 内部记住原选区范围。

如果编辑期间原文本发生变化，且系统无法确认原选区仍然对应同一内容：

- 禁止接受该译文。
- 提示原文已经变化。
- 不按旧字符位置强制替换。

---

## 9. IME 与输入过程

### 9.1 输入法组合态

对于拼音、日语、韩语等输入法尚未提交的 composition 内容：

- TypeLay 不翻译未提交组合文本。
- 等输入法正式提交字符后，再启动 debounce 与翻译。
- TypeLay 不干扰输入法候选过程。

### 9.2 实时翻译节奏

- 用户持续输入时使用短 debounce。
- 不要求每个按键都立即完整重翻。
- 视觉体验应接近实时。
- debounce 的具体毫秒数属于技术参数，不在本文冻结。

---

## 10. 本地翻译行为

### 10.1 模型要求

- CPU-only 设备必须能够运行。
- GPU / NPU 仅作为加速能力。
- 产品层面表现为一个通用多语言翻译能力。
- 用户不需要理解底层模型拆分方式。

### 10.2 模型安装

首次启动流程包括：

1. 说明翻译完全在本机执行。
2. 选择默认语言配置。
3. 下载本地翻译模型。
4. 模型下载完成后进入正常使用状态。

模型下载：

- 可以暂停。
- 可以继续。
- 首次必需模型未下载完成前，不进入正常可用状态。

### 10.3 模型运行策略

默认以低延迟为优先：

- 模型默认常驻。
- 翻译计算不得明显影响原应用输入体验。
- 模型更新由用户决定何时下载。

---

## 11. 语言方向

### 11.1 源语言

支持：

- 固定源语言
- Auto 自动检测

### 11.2 目标语言

目标语言必须由用户明确选择。

### 11.3 Auto 显示方式

Auto 模式下始终显示：

```text
Auto → EN
```

不会因为检测到中文而把界面自动改成：

```text
中 → EN
```

检测结果只用于内部翻译判断。

### 11.4 已经是目标语言

例如当前配置：

```text
Auto → English
```

用户输入：

```text
See you tomorrow.
```

TypeLay 不生成英语改写，胶囊保持轻量状态。

### 11.5 短文本检测

即使文本很短，Auto 模式也允许直接尝试判断语言，不强制等待更多上下文。

### 11.6 语言选择器

- 以搜索为核心。
- 不要求固定展示最近使用列表。
- 支持用户快速选择源语言与目标语言。
- 支持一键交换语言。

### 11.7 交换语言

例如：

```text
中文 → English
```

交换后变为：

```text
English → 中文
```

交换操作只改变语言配置：

- 不把当前译文写回原输入框。
- 不交换当前原文和译文的位置。
- 不暗中修改已有文本。

---

## 12. 翻译风格

### 12.1 默认风格

默认译文目标：

- 自然
- 忠实
- 符合目标语言母语表达习惯
- 保持原意
- 保持原有语气和礼貌程度

### 12.2 可选风格

风格控制放在二级菜单，不占据主浮层。

可包含：

- 自然
- 正式
- 简洁
- 口语

### 12.3 风格持续性

用户选择某个风格后持续生效，直到主动改回。

作用域：

- 有全局默认风格。
- 具体应用允许覆盖全局风格。

### 12.4 当前译文更新

切换风格后：

- 当前自动译文立即重新生成。
- 如果当前译文已经被用户人工编辑，则风格控件锁定。
- 用户需明确执行重新生成后，系统才可以覆盖人工译文。

---

## 13. 混合语言与结构保护

### 13.1 混合语言

例如：

```text
这个 API response 有问题，你看一下 JSON schema。
```

翻译整体语义，同时尽量保留无需翻译的技术 token。

### 13.2 尽量保持原文本结构

以下内容应尽量原样保留：

- URL
- 用户名 / mention
- 时间
- 编号
- issue / PR 编号
- emoji
- 换行
- 段落
- 不需要翻译的技术词
- 明确应保持原样的品牌名和术语

### 13.3 富文本

最终目标支持富文本输入框。

接受译文时：

- 尽量保存段落、列表、链接、mention 和可确定的富文本结构。
- 对能够确定的文字进行替换。
- 无法可靠映射的局部结构不强制猜测。
- 不因为局部格式无法映射就自动把整个输入框降级成纯文本。

---

## 14. 译文展示与编辑

### 14.1 单一主译文

默认每次只生成一个主译文。

不在主流程中同时展示多个候选，避免把每次输入变成选择流程。

### 14.2 译文可直接编辑

用户可以点击译文区域并直接修改。

进入译文编辑状态后：

- 浮层继续存在。
- 原输入框暂时失焦不代表会话结束。
- TypeLay 将“原输入框 + 当前译文浮层”视作同一个产品交互会话。
- 自动翻译更新冻结，避免覆盖正在编辑的内容。

### 14.3 从译文返回原输入框

用户编辑完成后：

- 按一次 Tab 回到原输入框。
- 或者直接用鼠标点击原输入框。

这两种操作都会进入“人工修改译文待接受”状态。

### 14.4 接受人工修改译文

进入“人工修改译文待接受”状态后：

- 下一次 Tab 接受修改后的译文。
- 不依赖双击速度。
- 这是状态驱动的连续操作。

典型流程：

```text
原输入框
    ↓ 点击译文
编辑译文
    ↓ Tab
返回原输入框
    ↓ Tab
接受修改后的译文
```

如果用户通过鼠标返回原输入框，则下一次 Tab 同样接受人工修改后的译文。

---

## 15. 人工译文与原文变化

### 15.1 原文末尾追加内容

如果用户已经人工修改译文，然后只在原文末尾继续追加内容：

- 尽量保留人工修改部分。
- 对新增内容继续翻译并融合到已有人工译文。

### 15.2 修改既有原文

如果用户修改了原文中已经存在的内容：

- 当前人工译文失效。
- TypeLay 重新生成完整译文。
- 不强行把旧人工修改拼接到已经改变语义的新原文。

---

## 16. 自动更新状态

### 16.1 原文继续变化

已有译文时，用户继续输入：

- 旧译文继续显示。
- 旧译文标记为正在更新 / 已过期状态。
- 在新译文完成前禁止使用 Tab 接受旧译文。
- 新译文生成后替换旧译文。

### 16.2 翻译失败

如果新一轮翻译失败：

- 保留上一版译文。
- 明确标记其已过期 / 翻译失败。
- 禁止接受旧译文。
- 不通过弹窗打断用户。

### 16.3 模型未准备好

如果模型正在启动或加载：

- 胶囊和浮层仍正常存在。
- 显示轻量的“正在准备翻译”状态。
- 原应用输入完全不受阻塞。

---

## 17. 接受译文

### 17.1 默认操作

PC 默认使用：

```text
Tab
```

接受当前有效译文。

### 17.2 接受结果

接受后：

- 将当前原输入框文本或当前选区替换为译文。
- 光标返回原输入流程。
- 不自动发送。
- 不自动提交。
- TypeLay 不提供自己的“一键撤销译文”功能。
- 接受后的文本完全属于原应用。

### 17.3 防止自身触发翻译

TypeLay 必须识别由自己执行的文本替换。

接受译文后：

- 不把自己的替换事件当成新的用户输入立即重新翻译。
- 当前展开区域收回到小语言胶囊。

### 17.4 接受后继续输入

例如 `中文 → English`，接受译文后原输入框已经是英文。

如果用户继续输入英文：

- TypeLay 保持安静。
- 不把英文重新改写成英文。

当后续重新出现需要翻译的源语言内容时，再恢复翻译流程。

### 17.5 输入框清空

当用户把当前输入框清空：

- 当前译文立即清空。
- 浮层收回成语言胶囊。

---

## 18. Tab 拦截规则

TypeLay 只有在以下条件同时成立时才允许拦截 Tab：

- 当前焦点属于原输入框。
- 当前存在有效译文。
- 当前译文对应最新原文。
- IME 不处于未提交 composition 状态。
- 用户没有同时按 Ctrl / Alt / Shift 等修饰键。
- 浮层当前处于可接受状态。
- 当前没有处于译文编辑框内部。

其他情况下：

> Tab 必须完整交还目标应用。

所有快捷键后续均允许在设置中配置。

如果用户配置的快捷键与应用冲突：

- TypeLay 提示存在冲突。
- 用户仍可选择强制保存。

---

## 19. 重新翻译

展开 / 更多操作区域提供“重新翻译”。

重翻支持区分两个语义：

### 19.1 严格重算

对当前同一输入重新执行翻译，目标是获得一致、可靠的结果。

### 19.2 换种说法

在保持原意的前提下尝试另一种自然表达。

主浮层不长期展示该操作，避免增加视觉噪音。

---

## 20. 术语表

### 20.1 显式本地术语表

用户可以维护本地术语和固定翻译。

例如：

```text
TypeLay → TypeLay
PR → PR
项目方 → client team
```

### 20.2 作用范围

术语规则支持：

- 全局生效
- 限定特定语言方向

### 20.3 人工修改不会自动学习

用户手动修改译文后：

- TypeLay 不自动把该修改保存成长期规则。
- 不建立隐式个人训练历史。

用户可以主动执行：

```text
加入术语表
```

将某一修改转成明确的长期规则。

---

## 21. 翻译历史

默认不保存翻译历史。

当当前翻译会话结束后：

- 译文内容退出产品运行状态。
- 不建立可浏览的历史记录数据库。

---

## 22. 浮层生命周期

### 22.1 单一当前会话

同一时刻只服务当前获得键盘焦点的一个输入框。

### 22.2 输入框切换

从输入框 A 切到输入框 B：

- A 的未接受译文销毁。
- 不为多个输入框同时保留活动浮层。
- B 建立新的当前会话。

### 22.3 离开应用

用户 Alt+Tab 离开当前应用：

- 当前翻译会话结束。
- 返回后根据当前实际输入状态重新建立会话。

### 22.4 浮层内部焦点

从原输入框点击到 TypeLay 译文区域：

- 不视作会话结束。
- 浮层保持。
- 用户可编辑译文。

只有焦点离开“原输入框 + 当前 TypeLay 浮层”这个整体后，当前内部编辑会话才结束。

## 23. 窗口、滚动与多显示器

### 23.1 窗口移动

原应用窗口移动或缩放时：

- 浮层实时跟随输入框。

### 23.2 页面滚动

输入框滚出可视区域后：

- 浮层隐藏。

如果输入框重新进入可视区域并仍为有效当前输入：

- 浮层恢复。

### 23.3 多显示器

应用从一个显示器移动到另一个显示器：

- 浮层跟随。
- 使用目标显示器对应的缩放比例。
- 不固定停留在主屏。

## 28. 首次使用流程

首次安装并启动后：

1. 告知翻译全部在本地完成。
2. 选择默认源语言模式和目标语言。
3. 下载本地模型。
4. 模型完成后进入实操教程。

教程以实际体验为主，至少覆盖：

```text
正常输入
    ↓
胶囊展开并生成译文
    ↓
Tab 接受
```

以及：

```text
点击译文
    ↓
人工修改
    ↓
回到原输入框
    ↓
Tab 接受修改后的译文
```

教程完成后不持续打扰用户。

## 29. 不支持区域的行为

如果某个输入区域：

- 无法可靠读取文本
- 无法可靠定位
- 无法可靠安全替换
- 明显属于不适合翻译的机器输入场景

则 TypeLay 默认不显示任何 UI。

用户不需要理解底层操作系统或可访问性接口的限制。

## 30. 产品状态机概览

### State 0：No Session

当前没有受支持的输入框。

```text
无 UI
```

### State 1：Idle Capsule

受支持输入框获得焦点，但当前没有需要翻译的文本。

```text
[ 中 → EN ]
```

### State 2：Translating

用户输入有效文本。

```text
胶囊展开
旧译文可保留
状态 = 正在更新
Tab = 不接受旧译文
```

### State 3：Valid Translation

当前译文与当前原文一致。

```text
译文有效
Tab = 接受
```

### State 4：Editing Translation

用户点击译文区域。

```text
人工编辑中
自动更新冻结
Tab = 返回原输入框
```

### State 5：Edited Translation Pending

用户从译文编辑区返回原输入框。

```text
人工修改后的译文待接受
下一次 Tab = 接受人工译文
```

### State 6：Stale Translation

原文变化，新译文尚未完成，或翻译失败。

```text
旧译文继续显示
标记过期
Tab = 禁用
```

### State 7：Paused

TypeLay 全局暂停。

```text
弱化胶囊
可快速恢复
```

### State 8：Unsupported / Excluded

当前区域不支持，或当前应用被排除。

```text
无 UI
```

## 31. 核心成功路径

### 31.1 普通实时翻译

```text
输入框获得焦点
    ↓
出现语言胶囊
    ↓
用户正常输入
    ↓
胶囊展开
    ↓
本地生成译文
    ↓
译文有效
    ↓
用户按 Tab
    ↓
原输入框被替换
    ↓
浮层收回胶囊
```

### 31.2 人工修改译文

```text
生成译文
    ↓
用户点击译文
    ↓
修改译文
    ↓
Tab 或鼠标返回原输入框
    ↓
人工译文待接受
    ↓
Tab
    ↓
修改后的译文写回原输入框
```

### 31.3 选区翻译

```text
用户选中文本
    ↓
TypeLay 翻译选区
    ↓
显示译文
    ↓
用户接受
    ↓
只替换原选区
    ↓
光标停在替换文本末尾
```

## 32. 当前明确不作为产品核心的行为

当前冻结版本不把以下能力定义为核心流程：

- 自动发送聊天消息
- 自动提交表单
- 云端翻译
- 默认保存翻译历史
- 默认同步用户输入
- 强制要求账号
- 同时展示多个主翻译候选
- 自动学习每一次人工修改
- 自动把翻译功能扩展为任意 AI 写作改写
- 在代码编辑区和终端默认工作
- 在无法可靠支持的输入框中强行显示半可用 UI
- 接受译文后提供 TypeLay 自己的一键撤销

## 34. 一句话产品规格

> TypeLay 在用户继续使用原应用、原输入框和原输入法的前提下，为当前受支持的文本输入区域提供完全本地运行的实时翻译胶囊；用户可以查看和直接编辑译文，并通过 Tab 将当前有效译文写回原输入框，全程尽量不改变原应用的输入行为、布局和使用习惯。
