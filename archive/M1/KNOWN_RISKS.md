# 已知风险与发布阻塞

所有“未解决”项都是当前新 MVP 状态，不重写旧 PoC 事实。本工程包不是可对任意用户输入启用的发布版。

## R1 — 跨进程写回不是原子事务（高）

最后一次读取之后，目标应用仍可能改动文本、选区或焦点。`EM_SETSEL` 和 `EM_REPLACESEL` 是分开的消息；UIA 也不普遍提供带原文版本条件的 compare-and-swap。写后确认能发现错误，不能撤销已经对用户输入造成的错误覆盖；不能把重读称为严格消除竞态。

M1 只访问自己的测试 fixture；它可以人为制造竞态以验证保守失败。生产 provider 的事务条件或有限支持范围仍待证明。未知结果隔离、禁止自动重试已经写入内核/adapter，但不等于已经解决 R1。

## R2 — 先吞 Tab 后拒写（高，涉及已冻结产品规则）

低级 Hook 必须很快决定是否放行，后续 broker 校验可能发现候选不再安全。盲目补发 Tab 会影响已经切换的应用；直接吞掉则违反无有效候选必须交还应用的语义。

当前只有纯 permit 判定，没有安装真实 Hook。短 TTL、事件 epoch、禁止过期候选都是必要措施，不是 R2 的充分解。生产启用前需确定可认证的原子决策/输入串行化范围或其他可靠机制；若必须牺牲原定行为，应明确提案获得批准，不能悄悄按“偶发没反应”放行发布。当前不选择强制全局阻塞用户输入来伪装解决。

## R3 — WPF 编辑和回源未实测（高）

持久 TextBox、先绑定焦点组合、返回实际确认是设计，不是成功证据。非激活窗口进入可编辑模式、点击拖选、失焦通知先后、UIA broker 自身事件、系统拒绝前台切换都可能产生新的问题。原型的浏览器模拟与旧 Tk 的试验都不能证明新实现。

## R4 — 外部 IME 信息可用性未知（高）

自有 fixture 的 WM_IME 通知不代表外部应用；UIA TextEditPattern 是否提供完整组合信息需真实 provider/输入法认证。Unknown 不能默认为已提交。未知状态下安静禁用，是安全边界，但某应用长期 Unknown 也不能宣传为受支持。

## R5 — 敏感输入识别不完整（高）

密码样式可以作为拒绝依据，但 PIN/安全码可能是普通文本控件。M1 的显式 fixture 元数据不能泛化；普通应用的分类与排除方案还需实现。默认不从未知字段读取文本后再做内容分类。没有隐私验收前不开放任意应用发现。

## R6 — 浏览器写回、selection 与事件语义（高）

ValuePattern.SetValue 不自动证明可选区替换、caret 正确、页面框架状态同步。页面重建、虚拟化、滚动、DPI、控件 offscreen、React 受控输入重渲染均需独立测；不加 DOM 扩展来悄悄改变“应用无需适配”的产品定义。

## R7 — 模型与分发尚未冻结（中高）

无已接入新进程的真实模型，无 CPU 质量/速度/内存基准，无完整依赖锁文件、模型/依赖许可检查或 OS 级网络隔离证据。Argos 是首个集成建议，不是已签署模型选型。默认风格、Auto、人工追加融合都必须真实验收，不能用接口存在冒充能力完成。

## R8 — 本包未编译、未执行 C# / Windows 测试（高，工程验证阻塞）

当前环境没有 .NET SDK/Windows，SDK 获取受网络限制。静态审阅已做，但可能仍有编译、P/Invoke、焦点或计数器问题。必须先在 Windows 构建与执行新 runner；CI 文件也是尚未运行的配置，不是 CI 绿灯记录。

## 当前原生 adapter 的特殊限制

仅接受测试 runner 启动的进程句柄和 fixture 登记的 HWND/生命周期 cookie。只有 Win32 EDIT；没有 UIA、浏览器、通用进程发现、clipboard 或模拟输入。读写调用有边界超时，但尚未放入独立 broker；只有 M1 测试宿主会调用它，生产 UI 不得直接复用同步调用路径。

InputEpoch / FocusEpoch 为 0；真实事件观察器尚未接入。外部源文 ABA 变化不能因此检测，不能发放生产 permit。核心已有对应 epoch 校验与测试契约，但“契约已写”不代表 OS 观察实现已完成。
