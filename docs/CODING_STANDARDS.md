## 测试

- 对每个受测边界，覆盖缺失或空输入、边界值、每个依赖的失败或超时，以及代码存在重试时的重试行为。
- 对所有输入都成立的规则，例如往返转换、不变量或状态机转移，编写基于属性的测试。属性可能与代码共享同一种误解，因此在 PR 的 Evidence 中列出每项新增属性。

## 界面

负责人在运行中的产品上验收 UI，交付代码应与验收代码一致。产品行为以冻结规格、已接受的 ADR-0002 和两份已确认原型为准。

- 按 docs/design/ 中的已确认原型和其中采用的组件构建界面。设计系统说明用于解释原型，不独立增加产品要求。
- 界面通过现有生产边界获取数据。原生界面使用对应运行时或平台端口；浏览器界面使用对应的真实消息或 API 边界。后端存在时，使用每次测试前重置的受控数据；后端尚未实现时，仅在开发和测试中按合同替代该边界。加载、错误和超时也在相同边界触发。
- 设计未说明加载、错误、超时或空状态时，在 PR 中指出缺口，并由负责人确认涉及的产品行为。获准后优先使用已有组件实现，无法完成的部分列入 PR 的 Out-of-Scope Problems。
- 为变更触及的页面和状态保留截图回归。原生桌面流程使用对应平台的 UI 自动化，浏览器流程使用浏览器测试。基线记录负责人确认的渲染结果，以负责人对变更的批准为依据。
- 意外截图差异按回归处理并修复。仅为预期的界面变化更新基线，由负责人审查 PR 中的图像差异。
- 人工审查形成了超出局部位置的设计规则时，在同一变更中更新对应设计文档。涉及产品行为时，先取得负责人的明确授权。
