# Chrome 商店发布准备

本页供发布者准备 Windows 标准网页字段扩展的商店材料。当前没有正式条目或扩展 ID，以下是待核对的提交草稿，不表示已经发布或通过审核。创建条目、上传、接受协议和提交审核须由所有者另行确认。

## 发布对象与前置条件

- 以 `eng/windows/dev.ps1` 生成的 `browser/chromium` 为扩展来源：Windows manifest、共享 `background.js`、`content.js` 和 `icons`。扩展 ZIP 根目录须直接包含 `manifest.json`，不要上传整个桌面安装包、模型、测试 profile 或日志。[官方打包要求](https://developer.chrome.com/docs/webstore/prepare)
- Windows 与 Linux 当前 manifest 不同。Linux 还加载富文本桥接脚本；本页不能作为两种包已经统一或均通过同一商店条目验收的声明。
- 当前 manifest 已声明复用现役 TypeLay 图案的 16/48/128 PNG，正式扩展身份配置仍为空。核验实际发行包资源并补齐发行身份后，再验证品牌 Chrome 的商店安装、桌面接入和移除；Chrome for Testing 的开发加载不能替代这一步。
- 扩展需要独立安装并运行 TypeLay Windows x64 客户端，以及已准备的本地翻译模型。客户端和模型不包含在扩展 ZIP 中。当前发行模型为中文与英语方向，用户可选择单向或双向；不要将研究中的模型或语言写入商店功能列表。

## 商店文字草稿

名称沿用当前 manifest：**TypeLay local input**。建议主要类别为生产力，主要介绍语言为简体中文；以提交时后台提供的分类为准。

简短描述草稿：

连接本机 TypeLay，在支持的网页输入框中预览翻译或按快捷键替换文字。需要另装桌面客户端和本地模型。

详细描述草稿：

TypeLay 将本机翻译体验带到网页输入框。安装并运行 TypeLay 桌面客户端、准备本地模型后，在客户端的“应用支持”中明确接入扩展。

在支持的普通文本输入框中，可以自动查看译文并主动接受，也可以按需查看预览或直接翻译选区。直接替换不会代你发送消息或提交表单。翻译使用桌面客户端中已安装的本地模型；输入内容会通过浏览器的本地消息通道交给本机 TypeLay 处理。

当前 Windows 接入针对顶层普通 HTTP/HTTPS 网页的文本或搜索 input 和 textarea。Chrome 内部页面、新标签页、嵌套 frame 和富文本编辑器不在本版支持声明内。密码与可识别的敏感字段会被限制；自动识别不能保证识别所有敏感内容，请勿用敏感文字测试开发预览。翻译质量取决于所安装模型，重要内容请自行核对。

你可以在 TypeLay 中暂停功能或移除连接，也可以在 Chrome 中管理扩展的站点访问权限和卸载扩展。仅安装扩展不会下载模型或启动桌面客户端。

## 单一用途与权限说明草稿

单一用途：让用户通过本机 TypeLay 对当前支持的网页输入框进行本地翻译预览和主动替换。

| 现有声明 | 提交说明 |
| --- | --- |
| `nativeMessaging` | 通过 `org.typelay.browser` 与同机 TypeLay 桌面程序交换经过字段校验的翻译请求、译文和操作结果；网页脚本本身不运行模型。 |
| content script 匹配 `http://*/*`、`https://*/*` | 用户在不同网站的普通输入框中使用同一翻译功能，因此在这些顶层文档观察焦点、输入框属性和原次快捷键，按客户端批准读取受支持字段，并在用户操作后显示或替换译文。并非全网页翻译或抓取整个页面。 |

当前 Windows manifest 的 `all_frames=false`，没有独立 `tabs`、`history`、`cookies`、`storage`、`debugger` 或网络拦截权限；不要在说明中声称这些权限存在。站点匹配仍是广泛的页面访问能力，不能描述为只在点击扩展图标后才获得访问。若正式发布缩小权限，须先修改并验证实际代码和安装体验，不能只改商店说明。[官方权限与单一用途说明](https://developer.chrome.com/docs/webstore/cws-dashboard-privacy)

## 隐私披露技术草稿

以下是现有实现的事实基础，供发布者形成公开隐私政策并核对后台选项；不是已生效的法律承诺。

- 读取范围：扩展观察页面与输入框的焦点、选区、输入法/输入事件和字段属性。用于安全判断的元数据包括标签、占位文字、元素 ID、无障碍属性及部分祖先角色。它们本身可能包含用户信息，不能称“完全不读取页面数据”。浏览器后台读取发送页面 URL 来判断 HTTP/HTTPS 协议，当前路由不转发完整 URL、页面标题或浏览历史。
- 正文路径：客户端先批准字段元数据；页面再按当前输入法与时限等条件读取受支持输入框文字及选区，将请求送往本机 TypeLay。捕获可包含整个字段，不只选中文字；超长正文会在读取后被拒绝。自动模式可能在用户正常输入时持续读取和翻译，无需每次再点击扩展。按需模式由用户快捷键发起翻译，但不承诺快捷键之前没有字段读取；读取资格与启动翻译是不同边界。
- 本地处理：当前 Windows 扩展的执行脚本随包分发，浏览器后台只连接本地 native host。现有翻译路径使用本机模型，没有把翻译正文发给云翻译 API 的实现。客户端准备模型需要网络下载，Chrome 自身更新扩展以及网页自身的网络活动不属于这一“本地推理”保证。
- 生命周期：运行中的字段观察、请求和译文会保存在进程内存以完成操作；桌面设置、模型和连接注册持久保存于用户数据位置。暂停或断连会撤销当前操作资格；移除连接不等于删除模型、设置、网页已填文字或用户另行保存的诊断文件，不承诺安全擦除所有内存副本。
- 诊断：浏览器路径的可选 `TYPELAY_TRACE` 使用有界状态码、布尔值、序号、计数与时间信息，不记录输入正文或目标元数据。该结论限本路径；发布包若新增日志、遥测或崩溃上报，须重新检查实际字段，不能由此宣称全部本地文件永远不含用户文字。
- 控制：用户可暂停 TypeLay、移除本地连接或卸载扩展；提交隐私政策时说明这些动作的区别，以及实际联系渠道和设置/模型清理方法。用户选择“复制译文”会写入系统剪贴板；接受译文会修改原网页字段，原网页仍可能按其自身逻辑读取或上传该字段，TypeLay 无法替网页作隐私保证。

后台数据披露至少须认真核对“网站内容”和“用户活动”相关类别；输入文本可能承载用户自填信息，本地处理也不能自动推导为“无数据使用”。只按后台当前定义和最终实现填写，不替发布者勾选认证。隐私政策需覆盖收集、用途、披露和控制方式，且与产品界面、商店说明一致。[官方隐私披露字段](https://developer.chrome.com/docs/webstore/cws-dashboard-privacy)及[用户数据说明](https://developer.chrome.com/docs/webstore/program-policies/user-data-faq)

## 素材与提交前核对

1. 图标已由现役 `typelay-active.svg` 导出到 `src/shared/browser/icons`，128×128 图保留透明边距；维护者运行 `python eng/shared/generate_browser_icons.py --check` 可用脚本注明的工具版本重现，发行构建无需这些工具。仍需准备 440×280 宣传小图及至少一张 1280×800 或 640×400 的真实产品截图。宣传图可使用现有 TypeLay 视觉资产，截图应来自实际发行候选且仅使用合成非敏感文字。[官方图片规范](https://developer.chrome.com/docs/webstore/images)
2. 截图优先展示普通网页预览、一次选区翻译、客户端明确接入/移除。没有通过的功能不放宣传图；测试报告或原型图不能冒充当前产品截图。
3. 确定发布者显示身份、可公开的支持联系方式、隐私政策公开 URL 和桌面客户端下载入口。不要代填个人邮箱；临时 Actions artifact 会过期，不能作为长期商店下载入口。
4. 经所有者批准建立条目后，将实际分配的扩展 ID 和对应商店 URL 固定到发行 `connection.json`，重建并验证同一包的安装、确认接入和移除。禁止拿 CI profile 的随机开发 ID 作为正式身份。
5. 提供审核者可执行的安装说明、模型准备和标准网页复现步骤。明确需要本地桌面程序，无需翻译云账号；附当前支持范围和已知限制。后台若要求额外材料或条款，由所有者确认后处理。
6. 发布前复核 ZIP 实际清单、manifest 版本与权限、脚本和声明一致性，以及隐私 URL 可公开访问。提交和后续审核状态单独核验，不将本页准备完毕称为商店已上线。
