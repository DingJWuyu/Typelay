# TypeLay Windows 预览

TypeLay 在原输入框旁显示本地译文。你可以继续输入、修改译文，再在目标能力允许时主动替换原文。Windows x64 版本仍是开发预览，普通输入框支持和完整产品验收尚未完成。

发行包能力以[包身份与对应证据](#当前可验证候选)为准，后续源码改动不会自动进入旧包。当前开发任务与验证结果由 [GitHub Issues](https://github.com/DingJWuyu/Typelay/issues)维护。

Windows 通用 UI Automation 写回仍有并发覆盖风险，原有实验性 Tab 写回默认关闭。未知输入法状态只允许只读预览。测试实验写回时，只使用已备份的非敏感文字；编译或软件输入检查通过不能替代物理按键和真实输入法验收。

## 安装与启动

1. 从[当前可验证候选](#当前可验证候选)下载产品 artifact，取出内层 `TypeLay-Windows-preview.zip`，核对 SHA-256。
2. 升级前从托盘退出旧 TypeLay。把完整 ZIP 解压到新目录，再双击 `TypeLay.exe`；备用入口是 `Start-TypeLay.cmd`。
3. 打开设置，明确同意准备本地翻译组件与模型。准备完成后，推理在本机 CPU 上运行。
4. 模型就绪后，先用合成文字完成[自有输入框练习](#自有输入框练习)，再检查实际使用的输入框。

产品预览包自带 .NET 运行时，不需要 SDK、Python 或源码。模型、组件和设置位于 `%LOCALAPPDATA%\TypeLay`。托盘提供设置、练习与退出入口。

App、Broker、Practice 和 BrowserHost 必须来自同一完整包。输入组件版本不符时，连接校验会拒绝继续。遇到连接检查失败，先从完整安装目录重新启动；仍失败时重新解压完整包。单独替换可执行文件会破坏组件配套关系。

普通输入框是产品目标，代表性应用只是验证场景。密码、敏感字段、终端、代码区域及无法确认安全状态的字段仍受限制。

## 工作模式与按需操作

在**设置**的**常规**页选择工作模式。设置会保留到下次启动；没有旧偏好的用户默认使用自动模式。

| 模式或操作 | 你会看到的行为 |
| --- | --- |
| 自动模式 | 聚焦后按当前字段能力显示语言胶囊和译文。接受还须满足本次目标、输入法和许可检查。按需快捷键不启用。 |
| 按需模式 | 普通聚焦和输入不显示翻译界面，也不自动启动翻译。 |
| 唤醒翻译，默认 `Ctrl+Shift+F9` | 为当前输入框开启持续翻译；空框显示语言胶囊。进入译文编辑仍属于同一会话。 |
| 直接替换，默认 `Ctrl+Shift+F10` | 从原输入框重新读取并翻译，替换选区或整框。它不接受浮层人工草稿，也不发送消息或提交表单。 |
| 退出，默认 `Esc` | 结束当前翻译会话。离开原输入框后，按需模式需要再次唤醒。 |

只有明确可写的目标才能直接替换。F9 能显示译文，不代表 F10 或 Tab 已具备写入能力。原命令被拒绝时，托盘和快速面板会显示原因；显式唤醒的首次读取失败也会给出一次提示。保持原输入框焦点后主动重试，程序不会自动重放命令。

设置页支持默认 Tab/Esc、无修饰功能键和 Ctrl+功能键。保存前会检查重复键、格式及部分冲突；强制保存只确认当时的精确草稿，不能放行非法或重复组合。保存成功与系统注册成功分开显示。Windows 注册失败时，可在释放占用后使用**重试启用快捷键**；它只重试已保存组合，不应用页面草稿。此入口和完整应用内冲突检测仍需对应桌面验收。

## 自有输入框练习

模型就绪后，在**应用支持**点击**试一试**，也可从托盘进入。自动模式练习预览、接受、修改译文和回源；按需模式练习当前唤醒与直接替换快捷键。

自动练习中，译文出现后还要等待接受提示。点击修改译文后，第一次 Tab 或鼠标回源只返回原框，原文保持不变；重新确认源状态后，第二次 Tab 才能接受人工草稿。练习权限仅属于本次自有输入框，不开放普通外部输入框的实验写回。

按需练习默认用 `Ctrl+Shift+F9` 查看预览，再用 `Ctrl+Shift+F10` 重新翻译原文并直接替换。进度只计算真实预览与已确认的写入回执。重新开始保留输入，但会清除进度；配置变化或关闭也会结束本次进度。只有完成自动练习并成功保存，才记录教程提示偏好。

自有练习的软件输入回归不代替物理按键与真实输入法验收，完整环境覆盖由 [Issue #21](https://github.com/DingJWuyu/Typelay/issues/21)跟踪。

## 暂停与恢复

从常规设置或托盘暂停后，TypeLay 清除当前会话的原文、译文、草稿和接受资格，停止正文采集与翻译。

安全且可确认的输入框旁会显示**已暂停 / 点击恢复**。暂停期间只读取字段身份、位置和安全属性；密码、敏感、只读、排除或未知字段不显示入口。你仍可从常规设置恢复。

恢复保留工作模式、语言与快捷键。按需模式恢复后仍需主动唤醒。旧字段的恢复入口会失效；保存失败时保持暂停并说明原因。托盘或快速面板保存失败也会保留上次确认的设置，模型状态刷新不会抹掉错误。

## 模型准备失败后的恢复

当前源码在可信空库存上，默认准备 Index Translate 2B Q4_K_M。准备需要用户确认，覆盖中文与英、日、韩、法、西、德、葡的十四个直接方向。已有 Argos/Hy 安装、当前选择和语言偏好继续保留；正常启动不下载模型，修复不自动换模型或补方向。

自动识别先判断源语言。同语时无需翻译；缺少方向时会提示补充，直接替换保留原文。安装、加载与翻译质量是不同条件，模型就绪不等于各方向质量已经放行。

准备失败后，在**应用支持**的准备卡查看原因，再使用对应的重新准备入口。网络、空间、文件访问、完整性、自检和未知故障分别显示；只有用户主动暂停才显示**继续准备**。安装诊断仅显示固定类别和阶段，不包含输入文字、原始异常或本地路径。

完整性失败会清除已确认损坏的对应下载。若清除受文件占用或访问限制阻挡，先解除提示中的阻塞再重试。候选安装通过自检和真实模型握手后才切换，失败会保留仍可用的旧安装。不要清空整个数据目录；库存损坏时，目前仍缺少用户可执行的完整恢复入口。

### 可选 Hy 中英预览

新装默认 Index，已有 Argos/Hy 不会自动迁移。包含 Hy 生产组件的包提供 Hy 准备入口，首次安装仍为原十二方向。

在已安装 Hy 行选择**补充中英方向…**，明确确认后才复用本地已验证权重补充中英双向。取消不改变库存；修复和模型选择不会自动补方向。补充保留当前模型与语言，仍在使用 Argos 时需要另行选择 Hy。

Hy 中英预览尚未开放风格与术语能力，译文可能错译或漏译。启用补充方向后，不承诺直接降级旧版本；你可在当前版本切回已安装的 Argos。移除模型或普通卸载不构成跨版本恢复承诺。实际安装、冷启动与质量边界见[模型能力边界](../../engineering/model-runtime.md#模型能力边界)。

## Chrome 合作扩展接入

当前发行配置没有正式商店 ID 或链接，使用用户手动开发加载。设置会从标准 Chrome 安装记录中发现与本包目录唯一匹配的 ID。浏览器策略不允许开发加载时，这条路线不可用。

1. 打开**设置**的**应用支持**页，进入 Google Chrome 详情。复制扩展管理地址，在 Chrome 打开，亲自开启开发者模式。
2. 点击**加载已解压的扩展程序**，选择**复制组件目录**给出的 `browser/chromium`，确认网页访问权限。
3. 保存浏览器工作，正常退出并重新打开 Chrome，让安装记录落盘。回到 TypeLay 刷新状态。
4. 点击**接入**，核对确认窗口中的扩展 ID 和本地程序路径，再确认当前用户注册。你无需填写 ID 或修改发行配置。
5. 保存网页工作后刷新普通 HTTP(S) 网页，在原生 `input` 或 `textarea` 中检查连接与翻译。
6. 停止合作时，在同一位置选择**移除连接**并确认。扩展本身仍由你在 Chrome 中卸载。

**已注册，尚未连接**只证明本地注册存在。**已连接**也不直接授予当前字段写权限。新标签页、浏览器内部页、嵌套 frame 和富文本不因接入而获得 Windows 扩展支持声明。物理输入与品牌 Chrome 的最终安装体验仍需验收。

连接管理不依赖模型就绪或启用状态。关闭设置不会取消已确认操作。移除先停止新授权和原连接，再删除精确匹配的当前用户注册；失败会保留真实状态。注册仍在时，重启 TypeLay 可能重新连接。移除不终止 Chrome，不删除模型或设置，也不覆盖另一安装。

升级、移动目录或换 ID 前，先在旧安装移除连接，再移除旧扩展并加载新目录。保留正在使用的组件目录。注册位置及身份检查见[Chrome 接入管理](architecture.md#chrome-接入管理)；发布者使用[商店发布准备](chrome-store-release.md)核对正式材料。
