# 在 Linux 上使用 TypeLay

TypeLay 在输入框旁显示本地译文。你可以先预览和编辑，再将确认的译文写回原输入框。Linux 客户端面向 CachyOS x86_64、niri 和 Wayland，目前仍是预览版。

首次使用需要完成三件事：安装客户端、明确准备本地模型、连接目标应用。模型就绪只表示翻译服务可用，应用还需要对应的输入接入方式。

## 当前可用范围与验收边界

当前源码提供以下接入路径。普通输入框是产品目标，表中的控件范围描述当前实现，不是永久应用支持名单。

| 你要在哪里使用 | 当前接入方式 | 使用边界 |
| --- | --- | --- |
| Chromium、Chrome 或 Firefox 网页 | 安装[浏览器扩展](browser.md)并注册本地主机。 | 支持顶层 HTTP(S) 标准 input/textarea，以及已实现事务接口的 Tiptap 单段文字和 marks。 |
| GTK3、GTK4 桌面应用 | 使用[Fcitx 合作接入](fcitx.md)，通过私有输入法会话启动应用。 | 支持标准 Entry 和纯文本 TextView。普通未合作 GTK 字段保持输入法状态 Unknown，不读取正文或拦截接受键。 |
| Qt6 桌面应用 | 使用包含匹配组件的[Qt 接入包](qt.md)。 | 当前实现覆盖标准 QLineEdit 和 QPlainTextEdit。 |
| VS Code 文档 | 使用[手动翻译命令](vscode.md)，预览后确认替换。 | 这是独立的手动功能，不监听通用输入框，也不接管 Tab。 |

GTK 非标准控件、带 tags 或嵌入对象的 TextView、Qt QTextEdit/富文本/自绘控件，以及 Electron/VS Code 自动浮层仍有实现缺口。终端和命令区默认排除。系统自动切换和恢复输入法也尚未实现。

Linux 尚未完成完整产品验收。当前架构改动已有构建、共享回归和局部消费者证据，但 GTK3 成功捕获、编辑与接受，GTK4/Qt GUI，以及物理输入法、真实撤销、多屏与视觉表现仍需目标环境验证。GTK3 的隔离 Unknown 拒绝检查不能代替成功翻译链。具体提交、原件和未测范围统一见[当前开发状态](../../engineering/development-state.md)。

### 与 Windows 的功能对齐

两端共用会话、设置和模型编排，遵循同一[产品验收基线](../../../README.md#产品验收入口)。平台实现与验收分别判断，Windows 的缺陷不是 Linux 应复制的行为。

| 产品行为 | Linux 当前实现与限制 |
| --- | --- |
| 自动与按需翻译 | 已接入共享双模式。自动模式持续预览；按需模式等待明确唤醒。输入能力仍取决于实际接入字段。 |
| 编辑与接受 | 人工草稿不会被自动刷新覆盖。默认第一次 Tab 回源，重新核验后第二次 Tab 才接受。 |
| 直接替换 | 任务始终绑定触发时的原字段。实现了部分同窗后台路径，具体控件范围见 [Fcitx](fcitx.md) 与 [Qt](qt.md)；不会改写后来聚焦的字段。 |
| 快捷键 | 设置共用唤醒、直接替换、接受和退出四键。接入组件必须确认当前配置，旧组件缺少能力时拒绝接管。 |
| 设置、托盘与练习 | 已实现四页设置、暂停恢复、模型准备、应用接入及真实输入框练习。练习进度与写入权限分别核验。 |
| 模型与高级能力 | 新装默认准备 Index，保留已有 Argos/Hy 选择。术语仅对已登记的固定 Index profile 开放中英双向；风格、换种说法和组合质量门仍关闭。 |

更多产品缺口见[产品说明](../../product/README.md#当前共同开发缺口)。源码中的实现、隔离测试通过和用户桌面验收是不同结论。

## 获取发行包

从对应 GitHub Actions 运行下载 `typelay-linux-<commit>` artifact，解开外层 ZIP，取得 `TypeLay-Linux-preview-x86_64.tar.gz` 及其 `.sha256`。完整桌面包已经附带匹配的合作组件。setup-only 包不含这些组件，适合设置和基础安装检查，不能作为完整桌面接入包。

下载前查看该提交的 Linux 检查和组件封装结果。封装成功只说明产物已生成，Windows 检查也有独立结论。发行包自带 .NET 运行时；GTK、PyGObject 和托盘库仍由系统提供。需要自行构建时，按[Linux 开发说明](development.md#构建)操作。

## 安装、启动与首次配置

先查询系统依赖。以下命令只检查已安装的软件包：

```sh
pacman -Q python python-gobject gtk3 json-glib libayatana-appindicator binutils
```

桌面合作接入还依赖匹配的 Fcitx 组件和数据，具体版本与检查步骤见[Fcitx 预检](fcitx.md#预检)。缺包或版本不匹配时先解决依赖，不通过重装翻译模型修复桌面环境。

进入同时包含 tar.gz 和 `.sha256` 的目录，校验并安装：

```sh
sha256sum -c TypeLay-Linux-preview-x86_64.tar.gz.sha256
tar -xzf TypeLay-Linux-preview-x86_64.tar.gz
cd TypeLay-Linux-preview
python install.py install
~/.local/bin/typelay --settings
```

安装使用当前用户权限，不需要 sudo。程序位于 `~/.local/lib/typelay/releases/`，启动器位于 `~/.local/bin/typelay`，安装器会添加应用菜单入口。重复安装同一版本会校验已有文件。若已有版本损坏，先退出所有 TypeLay 会话，再从完整解压包卸载和安装；默认保留设置与模型。

### 准备本地模型

在设置的“应用支持”页点击“准备本地翻译…”并确认下载。也可以明确执行：

```sh
~/.local/bin/typelay --install-models
```

可信空库存的默认准备项是 Index Translate 2B Q4_K_M。准备流程下载私有 Python、运行依赖和模型，校验后启动实际 worker，握手成功才切换到新版本。下载需要网络和磁盘空间；普通启动不会自动下载，失败保留原可用版本。已有 Argos/Hy 库存、当前选择和方向子集不会因默认模型变化而重置。

Index 提供中文与英、日、韩、法、西、德、葡的十四个直接方向。实际语言选项由已安装、平台可用的模型决定；缺少所选方向时，客户端会拒绝翻译或接受。显式的旧中英准备入口是 `typelay --install-models argos`，其它包操作从设置中的对应模型行确认。

“暂停下载”会停止本次安装并保留可验证的进度。再次安装时，资源身份、长度和缓存校验一致才续传。修复保留已安装方向，不会补充新方向；“使用此模型”只切换已安装模型；“移除”只允许删除非当前模型。

### 可选多语言预览模型

随包原生组件齐备时，设置提供 Hy-MT2 1.8B Q4_K_M。新安装包含中文与日、韩、法、西、德、葡的十二个方向。中英双向需要在已安装行单独确认“补充中英方向…”。补充复用已验证权重，不改变当前模型或语言设置，也不会在软件升级或修复时自动发生。

Hy 中英预览暂不支持风格和术语表。预览译文可能错译或漏译，接受前需要核对。不支持的高级请求会明确拒绝，不会静默改为普通翻译。模型握手和单句输出不代表所有方向的质量合格，现役结论见[模型能力边界](../../engineering/development-state.md#模型能力边界)。

没有 Hy 原生组件的包会明确显示不可用，反复安装模型不能补齐发行文件。启用新增方向后不支持直接降级旧软件；可以在当前版本切回已安装的 Argos。未安装 Argos 时还需要另行确认下载，删除 Hy 或普通卸载也不构成跨版本恢复承诺。

模型许可和预览限制显示在模型详情中。Argos 的本地归档摘要用于完整性核验，不等于上游发布者签名。下载量也不等于安装所需空间，准备流程会另外检查缓存、候选版本和保留版本的空间预算。

## 连接目标应用

浏览器用户按[浏览器说明](browser.md)安装扩展和注册本地主机。桌面用户从“应用支持”选择“桌面普通输入框”，完成以下步骤：

1. 确认“安装接入组件…”。完整包会把已校验组件展开到用户数据目录，这一步不切换输入法，也不让已打开的应用自动获得能力。
2. 记下原输入法的启动方式。若页面提示 Fcitx 或 IBus 已占用，先完成或取消候选并保存工作，再自行退出原输入法。若原服务会自动重启，先处理它的启动来源。
3. 点击“检查连接”，再确认“开始练习…”。TypeLay 会启动自有私有输入法会话和练习窗口。练习使用独立配置与词库，不复制个人输入法数据。
4. 按窗口选择自动翻译与编辑练习，或按需快捷键练习。切换全局工作模式需要明确确认；取消不改设置，关闭练习不恢复旧模式。若窗口未获焦点，先切到练习窗口并点击输入框。
5. 需要普通应用时，点击“选择应用…”，搜索已注册应用，再确认“通过 TypeLay 打开”。应用已经运行时，先保存并正常退出，再从这里启动。启动成功与字段已连接分别显示。
6. 结束时关闭应用、练习及其子窗口，再确认“结束本次连接…”。之后按第 2 步记下的方式恢复原输入法。使用用户服务或桌面监督启动的用户应恢复原方式，避免额外启动第二份输入法。

“选择应用…”当前接受可确认的本机 ELF 启动项。脚本、shell/env 包装、Flatpak/Snap、终端和不能确认的启动方式仍需各接入页的方法。列表里出现应用不表示它的所有控件都可用，字段能力始终来自实际观察。

退出 TypeLay 不会关闭受管应用，也不会停止私有输入法。“结束本次连接…”保留组件、模型、设置与练习配置；“移除接入…”另行删除接入组件。还有进程使用组件，或无法证明进程归属与退出时，客户端会拒绝结束或移除。两项操作都需要你手动恢复原输入法。

受管练习的授权仅覆盖本次已确认的自有字段，不打开全局实验替换。进度只承认实际预览和确认完成的写回；重新开始、配置变化、关闭或重启会使旧进度失效。独立 `typelay --tutorial` 只提供本地试译与指引，完成或跳过不能当作应用验收。

高级逐应用启动方法见 [Fcitx](fcitx.md) 和 [Qt](qt.md)。普通 `typelay launch 原命令` 只启用 GTK 模块诊断，不会使未合作字段获得读取或写回能力。

## 翻译、编辑与快捷键

自动模式会在已连接的普通字段旁显示胶囊，输入后生成译文。只有浮层明确提示可以接受时，接受键才由 TypeLay 使用。点击译文可以编辑，默认第一次 Tab 返回源框，重新检查原字段后第二次 Tab 接受人工稿。回源本身不会写入。

按需模式不会因聚焦自动翻译。默认 `Ctrl+Shift+F9` 唤醒当前字段，`Ctrl+Shift+F10` 直接翻译当前选区或整段文本。直接任务始终绑定原目标，原文变化、关闭或权限失效时拒绝写回，不把译文转写到新焦点。唤醒后读取失败会提示你保持焦点并主动重试，客户端不自动重放命令。

在“快捷键”页修改四键后，点击“保存修改”。接受和退出可选择默认 Tab/Esc、F1-F24 或 Ctrl+F1-F24，目前两者须使用不同主键。四个完整组合不能重复。更新后需要使用同版接入组件，并按各接入说明重启应用。

普通 GTK、Qt、Firefox、富文本及旧浏览器组件的自动接受需要在“常规”中明确开启“原生输入框替换”，默认关闭。已明确接入的 Chrome/Chromium 顶层标准字段，在确认版本 1 字段能力后可不经该实验开关自动接受。所有路径仍须核对原字段、输入法、配置和短期许可，详见[浏览器接受条件](browser.md#使用与卸载)。输入法状态未知时不会猜成空闲，组合中的按键也不会被当作 TypeLay 命令。

需要合成器全局快捷键时，在自己的 niri `binds` 中加入以下内容，并换成真实绝对路径：

```kdl
binds {
    Ctrl+Shift+F9 repeat=false { spawn "/home/你的用户名/.local/bin/typelay" "--wake"; }
    Ctrl+Shift+F10 repeat=false { spawn "/home/你的用户名/.local/bin/typelay" "--direct"; }
}
```

全局命令仍只操作已连接、已批准的字段。没有目标、观察过期或输入法未知时会失败。TypeLay 不修改 niri 配置，设置中的快捷键变化也不会自动更新这些绑定。

## 设置与托盘

设置分为常规、语言、快捷键和应用支持四页。普通开关、模式、语言和浮层主题即时保存；快捷键与排除列表共用一份待保存草稿，切页不会丢失修改。保存失败会保留草稿，关闭时需要明确放弃才丢弃。排除列表按应用可执行文件名生效，可以从已注册应用选择，也可以展开高级编辑手动填写。

浮层主题只改变翻译浮层，设置窗口明暗跟随 GTK 桌面主题。自动识别只用于源语言；选择固定源语言后才能交换方向。没有明确保存回执时，客户端提示结果未确认，你需要打开设置核对。

托盘提供暂停恢复、工作模式、语言、交换方向、模型状态、设置和退出。中键打开设置。TypeLay 使用 Ayatana AppIndicator 注册托盘；Waybar 用户需自行启用 `tray` 模块。没有托盘面板时，应用菜单和以下命令仍可使用：

```sh
~/.local/bin/typelay --settings
~/.local/bin/typelay --background
~/.local/bin/typelay --quit
```

## 诊断与登录启动

运行以下命令查看安装、桌面依赖和当前会话状态：

```sh
~/.local/bin/typelay --doctor
```

诊断不包含输入正文、译文、窗口标题或进程参数。`desktopDependencies` 用于检查 GTK3/GDK3 类型库和 Python 事件循环，缺失时按 `desktopDependencyHelp` 处理。`trayAvailable` 表示托盘库存在，`trayConnected` 表示已注册到面板；两者都不证明图标显示正确。原生连接数也不表示全部字段支持读写。

“登录 niri 时启动”使用 XDG autostart，需要桌面启动对应的自动启动目标。若你的 niri 启动方式不执行 XDG autostart，可以改用自己的配置：

```kdl
spawn-at-startup "/home/你的用户名/.local/bin/typelay" "--background"
```

换成真实路径，并只选择一种自动启动方式。客户端按 Wayland 会话保持单实例，重复后台启动不会额外打开设置。

配置、组件和缓存分别位于 `$XDG_CONFIG_HOME/typelay`、`$XDG_DATA_HOME/typelay`、`$XDG_CACHE_HOME/typelay`。未设置这些变量时，对应 `~/.config/typelay`、`~/.local/share/typelay` 和 `~/.cache/typelay`。会话 socket 与锁位于 `$XDG_RUNTIME_DIR/typelay`，只允许同一用户访问。

## 卸载

先关闭受管应用和练习，在“应用支持”中移除接入，再恢复原输入法。高级手动会话按[Fcitx 恢复说明](fcitx.md#恢复原输入法)结束。随后退出所有 Wayland 会话中的 TypeLay，从原桌面终端进入完整解压包执行：

```sh
python install.py uninstall
```

默认保留设置、模型、缓存和练习配置。需要一并删除这些 TypeLay 数据时，明确执行：

```sh
python install.py uninstall --purge
```

卸载需要原会话有效的 `XDG_RUNTIME_DIR`。仍有活动会话或组件安装占用时会拒绝操作，不要猜测运行时目录或按进程名批量结束程序。手动添加的 niri 启动项需要自行移除，安装器不改写 shell 或 niri 配置，也不删除目标应用。
