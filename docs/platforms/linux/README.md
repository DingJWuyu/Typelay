# TypeLay Linux 客户端

目标环境：CachyOS x86_64、niri、Wayland。Linux 与 Windows 在 `trunk` 共用单份 Core、Runtime、Protocol 和 Python worker；分支规则见根 `AGENTS.md`。Linux 构建不会修改 Windows 安装包或用户数据。

## 当前可用范围与验收边界

这是正在完成桌面验证的预览客户端，不是已通过完整产品验收的 Linux 正式版。[产品验收入口](https://github.com/DingJWuyu/Typelay/blob/trunk/README.md#产品验收入口)统一规定冻结基线与已接受增量；本页能力表描述实现和证据，不降低产品要求，也不构成永久应用支持名单。

当前推荐包与检查范围集中记录在[当前可验证候选](#当前可验证候选)。隔离桌面检查不代表物理键盘、用户输入法、所有普通应用或模型翻译质量通过，实际质量边界见[共同产品缺口](../../product/README.md#当前共同开发缺口)。

GIMP 3.2.6 的 Comment 字段原生不支持本页测试中的撤销：直接替换与原生粘贴后各两次 Ctrl+Z 均未恢复原文。TypeLay 不自供撤销，这不是新增 Undo 支持。

现役输入路径：

- [浏览器扩展](browser.md)：顶层 HTTP(S) 普通 input/textarea，以及已验证事务接口下的 Tiptap 单段文字/marks。Chromium/Firefox 已有实际扩展、本地主机和 Wayland+niri+真实模型链路证据，短租约续期空窗仍是风险；物理输入法、真实网页状态与撤销语义仍须验收。
- [Fcitx 合作 GTK](fcitx.md)：标准 GTK3/GTK4 Entry 与纯文本 TextView，通过真实输入上下文与事务状态授予能力；需用户明确切换到私有 daemon 并逐应用启动，结束后手动退出私有会话并恢复原输入法。通用未合作 GTK 路径保持 Unknown，仅描述非正文元数据，不捕获正文、不授予写入能力、不拦截 Tab。
- [合作 Qt6](qt.md)：标准 QLineEdit/QPlainTextEdit，复用同一宿主、模型与会话；可选包已通过实际构建、中文空格目录搬迁和 `launch --qt6` 的模型及同窗单行后台写回验证。Arch 同上游 Qt/GTK 版本的结果不代表用户 CachyOS 发行修订或实机验收。
- [VS Code 手动命令](vscode.md)：选择文字或明确选择整篇文档，经本地模型预览并确认替换。它是额外的手动功能，不监听通用输入框、不接管 Tab，不计入自动浮层对齐。

GTK 非纯文本/非标准控件、Qt QTextEdit/富文本/自绘控件、Electron/VS Code 自动浮层、更广富文本和输入法事务能力仍是开发缺口，不能标成“只需真机验证”。终端/命令区按产品策略默认排除。GTK 父窗口定位契约见 [ADR-0004](https://github.com/DingJWuyu/Typelay/blob/trunk/docs/platforms/linux/adr/0004-native-anchors.md)。

共同安装恢复、模型准备、受管组件准备/练习/退出/移除已有实际搬迁包与桌面链路证据。浏览器 DOM、Chromium/Firefox 本地主机和 Qt 完整模型流程已有通过记录；短许可仍会因调度和观察时效安全拒绝。GTK 接受使用 100ms 许可，Qt 唤醒/直接任务的入口观察限制与它不同，不能用一次通过消除偶发不可用风险，详见各适配器页。

设置、教程、注册应用与排除等实际检查范围见下方推荐候选。保存失败仍保留草稿；接入详情保留私有输入法恢复步骤。上述验证使用 CI 嵌套 niri 与合成输入，真机缩放、物理输入与用户环境仍须分别验收。

快捷键默认在已连接的输入适配器中处理，也可将 niri 全局按键绑定到下述 --wake/--direct 命令。全局触发不会为没有输入后端的应用伪造读取或写入能力。

当前源码在显式唤醒已接受、首次读取输入框失败或抛出异常时，按原目标和本次命令给出一次提示。请保持焦点后主动重试；此提示不代表读取成功率已经改善，也不会自动重试。

托盘修改设置遇到保存错误时，会保留上次确认的状态并显示提示，模型状态刷新不会抹掉错误。检查目录权限或磁盘空间后，重新选择原控件即可重试；收到成功结果才清除提示。Linux 若未收到明确回执，会提示操作结果未确认，应打开设置核对，不能据此判断保存成功或失败。

## 安装、启动与首次配置

先核对 CachyOS 系统依赖。发行包自带 .NET 和私有合作组件，但不安装系统桌面包；设置需要 Python、PyGObject 和 GTK3，原生合作组件需要 JSON-GLib，托盘需要 Ayatana AppIndicator，已注册应用识别需要 binutils。

```fish
pacman -Q python python-gobject gtk3 json-glib libayatana-appindicator binutils
pacman -Q fcitx5 fcitx5-chinese-addons fcitx5-gtk libime opencc
```

受管练习和应用接入同样要求系统 `fcitx5-chinese-addons 5.1.14`、`libime 1.1.16` 及匹配的官方 pinyinhelper 数据，发行修订号可不同。独立会话配置不免除此检查，详见[合作组件预检与数据校验](fcitx.md#预检)。缺包、版本或数据不匹配时先停止接入，不盲装滚动最新版或自行降级系统。以上查询不切换输入法，也不修改全局配置。

先解开下载的 Actions 外层 ZIP，再进入其中同时包含下列 tar.gz 与 `.sha256` 文件的目录，执行：

```fish
sha256sum -c TypeLay-Linux-preview-x86_64.tar.gz.sha256
tar -xzf TypeLay-Linux-preview-x86_64.tar.gz
cd TypeLay-Linux-preview
python install.py install
~/.local/bin/typelay --settings
```

安装是用户级操作，不使用 sudo、不改 fish 配置。启动器位于 `~/.local/bin/typelay`，应用代码位于 `~/.local/lib/typelay/releases/`，`current` 指向当前版本。安装会写入应用菜单入口，并在重复安装同一版本时校验已安装文件。若已有版本损坏，安装会拒绝复用，不覆盖可能仍被运行中进程使用的文件；退出所有 TypeLay 会话后，从完整解压包先卸载再安装，默认保留设置和模型。未将 `~/.local/bin` 加入 PATH 时，可继续使用以上完整路径。

在设置窗口点击“准备本地翻译…”并确认下载，或显式执行：

```fish
~/.local/bin/typelay --install-models
```

此命令会从 Astral 下载私有 CPython 3.13.16、从 PyPI 安装固定直接依赖及解析后的传递依赖，从 Argos 下载 1.9 版中英双向模型。需要网络和数 GB 可用空间。下载、提取与真实双向翻译自检完成后，才原子切换到新组件目录；失败保留原版本。命令行安装会请求同一会话中已运行的客户端接管新组件；没有运行中的客户端时，由独立宿主验证并发布，下次启动即可加载。设置窗口发起的安装也须经当前服务确认接管。

默认首次准备仍安装中文与英语两个方向，可在“安装方向（可选）”中只选一个方向。模型包管理版在已有库存后改用准备卡中的具体模型行：缺少的 Argos 方向可“下载并使用”，已安装包可修复或使用；不会用旧方向修复入口覆盖包库存。旧候选包仍使用原“补齐另一方向”入口。自动识别先判断源语言，同语无需翻译；缺少所需方向时提示，直接替换不会写入原框。命令行旧默认安装仍为中英双向。

### 可选多语言预览模型

源码中的准备卡提供 Hy-MT2 1.8B Q4_K_M 预览包，支持中文与日语、韩语、法语、西班牙语、德语、葡萄牙语直接互译，共十二个方向。只有随包 Hy native 文件闭包检查通过时，才显示可执行的下载/使用操作；普通未包含该闭包的发行包会明确说明不可用，不能靠反复安装模型启用。固定 revision 的模型与许可证共下载约 1.13 GB；缓存、新旧安装代和运行组件还会占用额外空间，安装器在准备前检查实际空间预算。

- “下载并使用”经过确认后下载该包并明确切换；保留原 Argos 库存及语言设置
- “使用此模型”只切换已安装包，不联网下载。切回 Argos 会使用现有中英包，不自动把已保存的语言改回英语
- “移除”只用于非当前包。先切换到另一个已安装模型，再确认移除
- 当前模型与实际就绪方向分别显示。只安装但未通过 worker hello 的包不会标为就绪；当前模型不含已选语言方向时会提示
- 新增语言选项只随实际安装且平台可用的 Hy 包开放；离线或切包后保留已保存值，未安装包不会仅凭目录被视为能力

模型许可与预览风险位于行内详情。预览译文可能漏译或表达不准确，应核对后再接受。安装/切换生命周期检查与翻译质量是不同门：Hy 的十二方向握手、单句非空输出不代表十二方向质量通过。当前检查范围见[当前可验证候选](#当前可验证候选)，质量结论见[共同产品缺口](../../product/README.md#当前共同开发缺口)。下载量不能当作安装所需空间，单次运行的资源峰值也不是所有设备的保证。

Argos 发布源未提供可用的固定发布者摘要时，安装器记录所用本地归档（含命中缓存）的 SHA-256，并在后续加载时检查文件完整性。这不能替代独立发布者签名，也不应表述成已验证供应链真实性。依赖锁、模型库存清单、自检结果保存在组件版本目录中。旧组件代次可能在安全退出后清理，不应依赖旧代自检文件永久留存。

设置中的“暂停下载”会停止本次安装进程族并保留已验证下载进度；再次安装时，仅在资源验证器、长度及缓存校验一致时续传，否则安全重下。退出期间不会切换未完成的组件，已有可用版本继续保留。

准备区按实际下载、暂停、启动和失败阶段展开原因与主要操作，已有可用模型不会盖掉本次准备失败；模型就绪后保留简短状态，展开它可找到修复，下一步仍是“选择接入方式”。本机输入服务状态与模型、目标应用接入分别显示，连接恢复不会清除操作结果未知的提示。当前设置检查已在真实 GTK 中完成单向安装、补齐、模型就绪后的管理区展开收起，并核验接入入口在视口内完整可见；后续设置阶段的失败与未运行范围见上文。完整首屏布局、准备失败与滚动场景仍须分别验收，单张截图不代表全界面通过。

安装失败会区分连接、空间、文件完整性、权限、运行环境或尚未确定的原因，并保留首个失败提示。安装诊断仅记录固定类别/阶段、系统错误编号及可用空间数字，不记录输入正文、译文、下载 URL 或任意异常内容；提供诊断时仍应先检查其它程序产生的日志。

首次使用从“应用支持”开始：先准备模型，再点击“选择接入方式”，按桌面接入指引打开受管练习。窗口提供“自动翻译与编辑”和“按需快捷键”：前者练习自动预览、接受和人工修改，后者保留当前配置的唤醒/直接替换快捷键。与当前工作模式不同的练习须明确确认才保存全局模式；取消不改设置，关闭不恢复旧模式。模型未就绪、已暂停或源目标语言相同时，先修正这些前置条件。

从设置明确确认打开练习时，客户端会请求一次标准桌面启动激活。旧版 GTK、不支持的桌面协议、启动较慢或合成器拒绝请求时，窗口仍可能未获得键盘焦点。请切到“TypeLay 实操练习”窗口并点击输入框再输入；字段内部的光标不一定表示整个窗口已在前台。客户端不会反复拉回窗口，手动聚焦后的流程验证不代表自动激活已通过；隔离桌面中的热重开已通过合成器前台窗口与输入框焦点检查；冷准备流程使用了明确手动切窗，不能算作自动激活通过。热重开后的单次 ASCII 真实键入，以及切换设置后正文与选区保持，也已在隔离桌面验证；用户桌面和通过真实输入法提交中文的热重开链仍需分别检查。

当前源码新增受管练习的两步进度：仅计算本客户端启动并确认身份的练习框生成的预览，以及随后一次直接替换的 Verified 回执。重新开始、配置变化、关闭或客户端重启会清除进度；重新开始保留输入和选区，准备期间撤下旧进度；确认本次练习框后显示“练习进度已重置”，再按窗口第 1 步重新生成预览。若准备失败，按提示检查后重试；旧请求的回复不应恢复之前的完成状态。隔离桌面已通过旧回复隔离、失败重试、关闭后迟到回复及原文选区保留的真实 GTK 控件回归，不代表短期快捷键许可已修复。“完成并关闭”只在本次两步完成后可用，并关闭以后的教程提示；提示偏好不是完成证据。[此前桌面验证](https://github.com/DingJWuyu/Typelay/actions/runs/38650565562)已完成重新开始后的一次真实 F9 预览、独立 F10 替换并核验两步进度、拒绝非自有客户端冒领完成，以及完成关闭与提示偏好保存。后续热重开未继承旧进度，真实 ASCII 输入与设置刷新保选区已通过；关闭客户端保留练习、正常关闭练习释放占用也已验证。受管练习正常关闭后的显式停止、移除组件，以及用户原配置、模型、设置和练习配置保留，已有[隔离桌面证据](https://github.com/DingJWuyu/Typelay/actions/runs/38694649702)；这不代替新增普通应用选择启动路径或用户原输入法恢复的验收。嵌套 XTest 不能以外层临时 Unicode 键盘映射替代真实中文输入法提交，此测试样本不限定产品支持语言。

独立本地试译仍可通过 `~/.local/bin/typelay --tutorial` 打开，它显式生成译文而不改写原文。完成或跳过只保存用户选择的提示状态，不能当作真实应用验收完成。

推荐先用下一节的设置入口完成受管练习。高级命令行方式也可使用同一正式后台和标准 GTK 输入框：按 [合作组件说明](fcitx.md) 明确启用私有会话后，从该包目录运行：

```fish
python fcitx-cooperative.py launch ~/.local/bin/typelay --practice
```

练习窗继承这次明确启动的输入法环境，不自动切换 daemon。普通 `typelay --practice` 不会被收养为受管目标，也不会获得练习专属写回授权。自动练习的授权仅覆盖本次已验证的自有 GTK3 字段，不开启全局实验替换。当前[隔离桌面验证](https://github.com/DingJWuyu/Typelay/actions/runs/38868475276)已完成真实输入后的首次接受、第二句翻译与重新绑定、点击译文编辑、实际改稿、第一次 Tab 零写入回源，以及重新核验后的第二次 Tab 精确接受人工稿，两次写回均为 Verified。随后已通过真实完成按钮快捷键自然关闭、仅保存教程提示偏好、释放自有进程占用，以及客户端重启读取该偏好。此项通过不代表整套桌面验收通过。步骤仅由本次目标的实际 Verified 回执完成；关闭、重启、离开原输入框与译文编辑器的焦点范围、断连或真实配置变化会退役授权。暂停或改设置涉及活跃练习时，先等原生撤销确认，再提交设置；未确认结束时禁止新授权并给出失败提示。保存完成偏好失败可以重试，保留的完成证据不能恢复写权限。

设置默认请求 790 × 560 窗口，实际尺寸由桌面决定。左侧按四个实际功能组导航，每页独立滚动；可用上下方向键切换侧栏选项，再用 Tab 进入本页控件：

- 常规：先显示启用/暂停、工作模式与三种翻译浮层主题预览，其后是启动、实验性替换及接入练习入口。主题预览是原生单选项，仅改变翻译浮层；设置窗口明暗跟随现有 GTK 桌面主题。
- 语言：源语言与目标语言支持搜索，选项按实际安装且平台可用的模型包动态显示；默认 Argos 为中文/英语，Hy 预览范围见上节。自动识别只用于源语言；选定固定源语言后可用“⇄”一次交换并保存两个方向。
- 快捷键：唤醒、直接替换、接受与退出四键，说明显示当前已保存的实际键值。
- 应用支持：模型准备、真实练习、应用接入、原输入法手动恢复指引及应用排除列表。首次使用未完成，或首次打开设置时模型未就绪，都会定位到这里。

普通开关、模式、语言与浮层主题即时保存，失败恢复上次确认的值。四个快捷键及排除列表是同一份草稿，切页不清空；有未保存修改时，窗口底部在各页显示同一个“保存修改”入口。保存失败保留草稿，关闭时默认继续编辑，明确放弃才丢弃。保存排除时仅应用本次增删，保留其它入口对未修改项的更新。排除列表逐项显示可执行文件名，可从“添加应用…”按已注册应用名称选择，或逐项移除；都需保存后生效。“高级编辑”默认折叠，可手工逐行填写。自动添加只使用可确认的直接本机 ELF 进程名，解析符号链接后取文件名并转小写，不要求 GTK/Qt 依赖；带实际启动参数的条目、脚本、解释器、包装启动器和沙箱应用无法确认时保留手工入口；单独的文件占位符可省略。既有项的顺序与大小写不批量修改。需要实验写回的路径须在“常规”启用“原生输入框替换”；密码、敏感字段及未知输入法状态仍不能绕过安全约束。该开关默认关闭，控制普通合作 GTK、Qt，以及 Firefox、富文本和旧浏览器组件的自动接受；这些路径的写回桌面检查显式启用了该开关，自有受管练习的授权独立。明确接入的 Chrome/Chromium 顶层 HTTP(S) 标准 input/textarea 在确认版本 1 字段能力后，无需开启该开关即可自动接受；仍须满足当前字段、输入法、配置及许可校验，详见[浏览器使用说明](browser.md#使用与卸载)。

已发布源码已将风格与术语设置接入语言页，浮层操作和仍关闭的质量门见上方能力表；这不增加字体或关于页。侧栏与跨页草稿回归属于真实 GTK 桌面流程，须在具备 AT-SPI 和显示服务的环境运行，并另行检查滚动裁剪与目标桌面视觉；静态检查不能替代。

## 连接目标应用

首次桌面练习按以下顺序进行：

1. 设置“应用支持”中先准备本地翻译组件，再选择“桌面普通输入框”并确认“安装接入组件…”。
   接入页主面显示当前连接、字段能力和此时必要的切换或结束要求；完整说明在“查看详情”中。先确认已自行记下原输入法的启动方式；确实未运行过输入法时，可选择对应确认。它只是你的确认，TypeLay 不会据此执行恢复命令。
2. 如提示 Fcitx 已占用，先完成或取消候选、保存正在编辑的内容，再在原 Fcitx 托盘中选择退出。若它被自动重新启动，先查明并由你暂停原启动方式；不要反复启动第二份输入法。记下原来是桌面自动启动、niri 配置还是用户服务，恢复时仍使用原方式。
3. 点击“检查连接”刷新状态，再确认“开始练习…”。这一步启动受管私有输入法会话并打开 TypeLay 自有练习。按窗口选择自动翻译/编辑或按需快捷键，确认所需模式后操作；两种受管练习都不要求开启全局实验替换。模式确认会明确说明对所有应用的影响。
4. 结束时先正常关闭练习和子窗口，再在同一页确认“结束本次连接…”。这只结束 TypeLay 自有私有输入法会话，保留接入组件、模型、设置和练习配置，下次不必重新准备组件。不再需要组件时，另选“移除接入…”。仅退出 TypeLay 客户端不会停止练习或私有输入法。
5. 私有会话结束后，按第 2 步记下的方式恢复原输入法。原本手动启动系统 Fcitx 的用户可重新运行 `/usr/bin/fcitx5`；使用用户服务或桌面监督启动的用户恢复原服务/启动项，不能再额外启动一份。最后在普通应用检查原输入法候选是否正常。

“检查连接”会只读观察当前 Fcitx 的启动来源；只有实际进程、用户服务与独占进程组相符时才提示专用用户服务。来源尚未确认时保留手动指引，这项检查不会停止服务，也不授予切换或恢复权限。

系统自动切换和自动恢复尚未实现。不要把“组件已准备”或练习成功当作所有已打开应用都获得支持；已注册的本机 GTK/Qt 应用可使用下述选择入口；其他启动方式仍按各自接入说明处理，浏览器需要扩展批准。

包含 `support/desktop/component.json` 的完整发行包可在“应用支持”中选择“桌面普通输入框”，确认安装后准备随包合作组件。准备过程只校验和展开文件到用户数据目录，保留源码与许可证，不下载组件、不执行包内程序或切换当前输入法。安装来源的信任来自你取得的完整 TypeLay 主包，文件清单不是发布者签名。没有附带该组件的 setup-only 包继续提供手动接入说明。

“已准备”尚不表示应用已连接。准备后可明确选择“开始练习…”进行 TypeLay 自有 GTK 输入框练习：这会启动本包的私有输入法并打开随包练习窗口，使用独立练习配置和词库，不复制个人输入法数据。已有 Fcitx/IBus 时会先解释占用，必须由你保存工作并自行退出原输入法；当前入口不会切换现有会话，也不会让已经运行的其他应用自动获得支持。普通应用可在同一连接区域点“选择应用…”，搜索已注册的本机应用，再确认“通过 TypeLay 打开”。选择本身不启动进程，启动回执也不表示连接成功；只有本次受管直接子进程的真实连接才计入所选应用状态，其他练习窗口或应用的连接不能代替。当前字段能力仍来自新鲜的实际观察。若应用已经运行，请保存工作并正常退出，再通过 TypeLay 打开；不会自动关闭现有进程。

选择入口目前只接受标准 `.desktop` 注册中的直接 ELF 命令和固定参数，支持完整双引号、字面 `%%` 及零文件时独立的 `%f/%F/%u/%U`。静态工具包识别使用系统 `/usr/bin/readelf` 的直接依赖，不执行候选、不使用 `ldd` 或递归推断。脚本、shell/env 包装、Flatpak/Snap、终端、工作目录设置及其他字段代码暂不支持；发现列表不代表已经支持，选中后才检查启动方式。高级手动应用启动仍见下列合作组件说明。

关闭 TypeLay 不会关闭受管应用、练习窗口或结束该私有输入法。正常关闭这些窗口及其子窗口后，可在同一设置页确认“结束本次连接…”：只停止已验证由 TypeLay 启动的私有输入法，保留组件、模型、设置及练习配置。只有检查确认可安全停止时才提供该动作，执行时仍重新核验归属和子进程。若要删除受管组件文件，另选“移除接入…”。这两种操作都不会自动恢复原输入法，需要你自行启动。运行中应用仍使用组件时拒绝结束或移除。监督进程异常退出、无法证明后代已结束时，本次系统启动内保持使用中保护，重启系统后再移除，不能据锁文件空闲猜测安全。准备失败保留原组件版本，可以从完整主包重新准备。

若使用浏览器输入路径，请按 [浏览器连接说明](browser.md) 安装扩展并注册本地主机，再运行 TypeLay。

单独运行 `typelay launch 原命令` 只启用 GTK 模块诊断，不会使通用 GTK 字段获得读取或替换能力。需要合作路径时，按 [Fcitx 说明](fcitx.md) 通过已验证的私有会话与逐应用启动器运行。启动器仅为子进程添加 GTK3_MODULES，保留已有模块与输入法配置，不全局更改桌面环境或替换用户输入法。

自动模式：聚焦支持的输入框后显示胶囊，输入后按共享防抖规则翻译。绿色就绪且底部明确显示“Tab 接受译文”时，Tab 才由 TypeLay 接受；否则仍属于原应用。当前源码顶部保留“译文就绪”等简短状态，编辑入口由译文控件的悬停、键盘焦点和无障碍名称呈现；进入编辑后显示“编辑中”。可编辑不表示已有写回许可。点击译文编辑，第一次 Tab 返回原输入框，第二次 Tab 才接受。展开/收起、重译、Esc 隐藏和语言方向设置位于浮层。

按需模式：聚焦时不自动显示或翻译。Ctrl+Shift+F9 唤醒当前输入框；Ctrl+Shift+F10 冻结当前选择范围或整段文本并直接翻译替换，不改变工作模式。即使用户随后切换输入框，也不会把结果写入新的焦点；原目标内容改变、关闭或失去写入权限时拒绝写回。

Qt 显式命令使用原目标的限时授权，真实异步输入退休并重新证明 Clear 后才捕获正文；取消、超期或原文变化都不能转读新焦点。具体待捕获与后台写回规则见 [Qt 路径](qt.md#输入法与写回边界)。

在“设置 → 快捷键”选择接受/退出键，再点“保存修改”；四键共用原保存流程，失败保留草稿及原设置。接受/退出支持默认 Tab/Esc、F1–F24 和 Ctrl+F1–F24，目前须使用不同主键。Ctrl 配置覆盖本页现役合作 GTK、Qt、浏览器标准字段及已支持的 Tiptap 单段 marks；不新增 Electron/VS Code 自动浮层能力，VS Code 的独立手动确认命令不受影响。更新后须使用同版合作组件和浏览器扩展，并按原流程重启受管应用；缺失握手能力不提供组合接受，也不会静默改用默认键。

输入法组合中的按键不会被当作 TypeLay 命令。输入法状态不能被确认时，不以“看起来没有候选窗”作为替换许可。

需要合成器级快捷键时，可自行在 niri 配置的 binds 区块加入以下内容，路径替换为自己的绝对路径：

```kdl
binds {
    Ctrl+Shift+F9 repeat=false { spawn "/home/你的用户名/.local/bin/typelay" "--wake"; }
    Ctrl+Shift+F10 repeat=false { spawn "/home/你的用户名/.local/bin/typelay" "--direct"; }
}
```

命令只使用触发时窗口对应的已批准目标与短期原生租约，再由目标事件线程核对字段身份、原文/焦点版本及 IME。切焦点、超期、未知输入法或尚无已连接字段时返回非零，不改为读取后来聚焦的控件。此配置由用户决定；程序不改写 niri 配置。更改设置中的应用内快捷键不会自动修改 niri 中的绑定。

## 托盘与快速操作

客户端通过 `libayatana-appindicator` 向当前 D-Bus 会话的 StatusNotifier 托盘面板注册。使用 Waybar 时，需要在自己的 Waybar 配置中启用 `tray` 模块；TypeLay 不安装面板、不修改 Waybar 或 niri 配置。已有面板配置应保留，只添加缺失的模块。

托盘菜单提供启用/暂停、自动/按需模式、源/目标语言、交换语言、模型就绪状态、设置和退出。暂停时保留灰色图标和恢复入口，不把“暂停”变成“退出”。中键打开设置。自动检测不能作为目标语言，因此源语言为自动识别时，交换入口不可用；选定固定源语言后再交换。上述操作只修改共享运行时的设置，不写入任何输入框，不改变原生写回的安全约束。

没有托盘库或没有运行托盘面板时，设置窗口明确提示原因；应用菜单、`--settings` 和 `--quit` 仍可使用。面板稍后启动或重启时由 Ayatana 重新建立连接，不需要重启翻译服务。托盘图标随包提供，不依赖用户图标主题恰好包含某个图标。

## 诊断、退出、登录启动

```fish
~/.local/bin/typelay --doctor
~/.local/bin/typelay --background
~/.local/bin/typelay --settings
~/.local/bin/typelay --quit
```

`--doctor` 输出安装、niri 版本和本会话的服务状态，不包含正文、译文、窗口标题或进程参数。源码中的诊断还会用启动器相同的系统 Python 检查设置需要的 GTK3/GDK3 类型库与 `gi.events`，即使没有显示服务器也能输出 `desktopDependencies`；缺失时给出 `desktopDependencyHelp`，并返回非零状态。请按提示检查系统 `python`、`python-gobject`、`gtk3` 包，不要通过重装翻译模型修复桌面依赖。它不会安装系统包、切换输入法或初始化 GTK 显示；类型库存在与事件循环可加载也不代表 GTK 原生库、桌面连接或实际设置窗口已验证。`trayAvailable` 表示托盘库可用，`trayConnected` 表示与面板完成注册，不代表图标已通过视觉验收。它不是兼容性认证；`nativePeers` 大于零只说明有应用连接，不代表该应用的全部控件可读取或替换。

“登录 niri 时启动”写入 XDG autostart 文件，需要当前 niri 会话启动 XDG 自动启动目标。使用 `niri-session` 的 systemd 集成路径可按 niri 的官方集成文档配置；其他启动方式可在 niri 配置中显式加入：

```kdl
spawn-at-startup "/home/你的用户名/.local/bin/typelay" "--background"
```

必须替换成真实绝对路径，不要同时配置两种自动启动方式。启动器有每个 Wayland 会话的单实例锁，重复后台启动不会额外打开设置。

数据位置遵循 XDG：配置 `$XDG_CONFIG_HOME/typelay`（默认 `~/.config/typelay`），组件 `$XDG_DATA_HOME/typelay`（默认 `~/.local/share/typelay`），缓存 `$XDG_CACHE_HOME/typelay`（默认 `~/.cache/typelay`）。运行时 socket 和锁位于 `$XDG_RUNTIME_DIR/typelay` 下的会话目录，仅同一用户可访问。

## 卸载

卸载前先结束桌面接入：

1. 如使用了受管“开始练习…”或“通过 TypeLay 打开”，先正常关闭应用、练习及其子窗口，再在设置的“应用支持”页确认“移除接入…”，结束受管私有输入法会话。
2. 私有会话结束后，按[连接目标应用](#连接目标应用)的原启动方式恢复系统输入法。仅退出 TypeLay 客户端不会结束受管练习或私有输入法；高级手动合作会话按 [Fcitx 退出与恢复说明](fcitx.md#恢复原输入法)操作。
3. 退出所有 Wayland 会话中的 TypeLay。从原桌面会话终端进入完整解压包执行；终端须保留该会话的有效 `XDG_RUNTIME_DIR`，不要手动猜测或改用其它运行时目录：

```fish
python install.py uninstall
```

默认保留设置、模型、缓存和练习配置。显式删除这些 TypeLay 数据：

```fish
python install.py uninstall --purge
```

卸载只删除 TypeLay 程序及其菜单/自动启动入口，不删除通过 `launch` 启动的目标应用，也不修改用户的 fish/niri 配置。已安装启动器缺失时仍可从完整解压包卸载，但活动会话的锁检查不会跳过。`XDG_RUNTIME_DIR` 缺失、为相对路径或不指向现有目录时，卸载会拒绝操作并提示从原桌面会话终端重试。手动加入 niri 的 `spawn-at-startup` 或应用启动命令需要同步移除。仍有会话占有锁时，卸载拒绝操作；组件安装占有锁时，`--purge` 拒绝删除组件数据，不使用进程名批量杀死其他程序。
