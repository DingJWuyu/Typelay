# ADR-0002：按需激活与原输入框后台写回

状态：接受，用于 Windows 开发预览。此决策不关闭通用 UIA 写回和真实输入法验收风险。

## 背景

已确认的增量需求增加自动 / 按需两种模式。按需唤醒需要复用原有持续翻译体验；直接替换则必须是一项独立的一次性操作。用户可以在翻译期间切换焦点，结果仍只尝试写回最初的输入框，不抢焦点、不发送。

通用 UIA 的读取、比较和 SetValue 是独立远程调用，不能因为绑定了 HWND 或做了写后核验，就宣称解决并发覆盖。也不能把恢复焦点、模拟粘贴或整框重写作为后台任务的后备路径。

## 决策

`TranslationActivation` 只控制进入原有 Session 的资格。工作模式持久化在设置中；唤醒状态只属于当前目标生命周期，在离开焦点家族时结束。编辑 TypeLay 浮层不是离开原输入框。自动模式不注册两个新增快捷键。

`DirectTranslation` 保存触发时的源快照、选区和语言方向，生成一次性计划，不创建持续会话。控制器把前台会话生命周期与该任务分开：焦点变化结束前台体验，但不会仅因此取消直接翻译。设置变化、暂停或释放控制器会使尚未派发的任务失效；已派发写入不能假装已撤回。并发直接命令不会堆积为一串过期替换。

快捷键入口依靠新鲜的焦点、输入和鼠标选区版本确认触发来源。只读预览的唤醒资格与直接写回资格分开；Unknown IME 可显示现有普通值预览，但仍是 Unknown，不产生写回权限。快捷键回调不等待模型或 UIA。

新增 `TypeLay.NativeInput` C DLL 只服务 Windows x64 中运行时确认的原生系统 `Edit` 控件。Broker 经显式 `CaptureDirect` 请求获取该能力；不能把任意 UIA 读值改标为支持直接写回。DLL 在目标 GUI 线程上校验目标身份、生命周期 cookie、原文、控件属性、IME、选区范围和长度，再执行替换与结果核验。被替换窗口过程、密码、只读、受限样式或无法确认的控件拒绝此路径。

`direct-write` 只使用计划中的原目标，独立重读该目标的安全元数据。它不读取后来聚焦的控件来替换目标，不调用 SetFocus / SetForegroundWindow，不使用剪贴板、Enter、Tab 或 UIA SetValue 作为后备。原生选区替换保留选区外内容并请求保留撤销记录。

绑定数量、有效期和远程调用期限有界。源正文只在一次调用所需的私有共享内存与模型任务中存在，不进入绑定元数据或诊断日志。已完成交换清零共享缓冲区；超时视为可能尚在执行，不能清零后假装安全取消，更不能自动重试。未知结果隔离该目标生命周期。

## 不变的边界

原有 `ExperimentalWriteback` 仍默认关闭。限定原生控件中的协调写入，不等于解决通用 UIA 的 B-01，也不证明物理按键所有权。浏览器、富文本、自绘控件、其他架构和真实中文 IME 需要各自的后端与验收证据。无法可靠写回时安全失败是本增量允许的结果，不以扩大成功率为由放宽限制。

## 构建与验证

DLL 使用既有 LLVM 工具从源码构建，随 App / Broker 一同分发，不提交二进制。App 桌面测试按构建依赖复制真实 Broker 和 DLL，不把测试支持库引入生产依赖。测试依赖锁由 NuGet 生成并提交，CI 使用锁定还原与纯检查，不先格式化来掩盖未提交变更。

Core 行为测试覆盖模式、激活、一次性计划、选区、安全拒绝与空胶囊。App 桌面回归用真实 WPF、控制器和生产 Broker 验证静默、快捷键唤醒、焦点切换和设置持久化；注入按键仅在显式测试模式使用。生产 Broker 进程回归在独立的真实系统 Edit 控件中验证后台选区 / 整框替换、B 的内容与焦点不变、撤销、文本冲突、身份失效、排除和不提交。

这些是分层证据，不是“真实模型推理 + 物理键盘 + 任意第三方应用”的完整验收。发布包还必须通过迁移到独立目录后的进程与分发 E2E；历史未测或失败项不得改写为通过。
