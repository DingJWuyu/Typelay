# 产品行为与验收基线

两端共同按[冻结规格 v1.0](TypeLay_产品规格_v1.0.md)及已接受的[ADR-0002：自动/按需与一次性直接替换](../adr/0002-on-demand-and-direct-write.md)验收。增量与冻结基线重叠时，以该已接受增量为准；其余原要求继续有效。本文提供阅读入口与操作摘要，不改写冻结正文。

[统一应用接入与双端体验](application-support.md)是已接受的后续产品增量：设置中的支持管理、状态/动作与用户文案由双方真实消费同一共享定义，Windows/Linux 分别完成相同体验验收。不能用一个平台的完成状态代替另一个平台。

“工作模式”是设置项总称，选项是“自动模式”和“按需模式”。Windows/Linux 的实现范围、测试证据与缺口不是产品要求的替代品。已确认的[浮层原型](../design/TypeLay_UIUX_Prototype.html)和[托盘/设置原型](../design/TypeLay_Tray_Settings_Prototype.html)是交互基线，不是客户端验收证明。

## 工作模式与按需操作

在“设置 → 常规 → 工作模式”选择模式，重启后保留。升级时没有此偏好的用户仍使用自动模式，已有应用排除项不会因新增偏好失效而被清除。

| 模式或操作 | 行为 |
| --- | --- |
| 自动模式（默认） | 聚焦后按原有规则显示语言胶囊、生成译文与接受译文。两个新增快捷键均不启用。 |
| 按需模式 | 正常聚焦、输入时不显示翻译 UI，也不自动运行翻译。 |
| 唤醒翻译 UI：默认 `Ctrl+Shift+F9` | 为当前输入框开启持续翻译体验；空框显示语言胶囊。正常编辑 TypeLay 译文不算离开；转到其他输入框后结束，返回原框也需要重新唤醒。 |
| 直接翻译并替换：默认 `Ctrl+Shift+F10` | 有选区时只处理选区，否则处理当前输入框文本。一次性操作，不显示预览、不需要 Tab、不发送或提交。 |

唤醒、直接替换与接受译文均不会更改工作模式。直接替换绑定触发时的原输入框和文本；翻译期间可切换输入框或应用，任务不会仅因焦点变化取消。结果只尝试写回原控件，不抢回焦点，不修改后来聚焦的输入框。目标失效、原文冲突、输入法状态不明确或结果未知时安全拒绝或隔离，不进行有风险的重试。

## 暂停与恢复

暂停会清空当前翻译会话、候选和编辑草稿，并撤销新的接受资格。在可确认的普通输入框旁保留弱化的“已暂停 / 恢复”入口；敏感、排除、身份不明或失焦字段不显示该入口，托盘和设置仍可恢复。

点击恢复会重新核对当前字段并保存启用状态，不更改工作模式。按需模式仍需使用配置的唤醒快捷键；旧候选不会恢复。设置保存失败时保持暂停并说明原因。暂停前已经发出的写回仍按真实回执报告，结果未知时不自动重试。

## 当前共同开发缺口

已有实现、局部测试通过与产品交付是三件事。以下区分必须闭合的用户流程、已声明支持范围和后续覆盖目标，不自行增加无限兼容要求；物理键盘、用户输入法、多屏 DPI 等现场验收另行进行，不能相互替代。最近核对的验证基线为 [`245339db`](https://github.com/DingJWuyu/Typelay/actions/runs/39498694524)，该运行已结束：Windows 分发 smoke 与两端桌面完整检查仍失败，各阶段结果见平台说明。

- 共同用户流程尚须完成当前候选的实际验收：[应用支持增量](application-support.md)要求两端分别从完整安装包与设置入口，接入至少一个普通浏览器网页字段和一个普通桌面自然语言字段，验证约定的预览、接受、编辑回源、直接替换及取消恢复。不能只有 fixture 或一端结果；也不能从“受支持输入场景”推成所有自绘控件都必须实现。Windows 通用 UIA 非原子写回仍默认关闭，未合作字段、Electron/VS Code 自动浮层及其它原生富文本属于当前覆盖限制，须如实说明，不得用安全拒绝掩盖已承诺的真实路径故障。
- 富文本仍须保留规格 §13.3 的结构安全要求；已有浏览器富文本路径应逐端验证支持的结构和选区，不能因没有某个 GTK/Qt 控件实现就说富文本完全未做，也不能将不支持的结构静默整框扁平化。扩大具体控件覆盖不是无边界的本次交付前置。
- 浏览器接入必须有合法、普通用户能完成的真实路径，开发加载不能冒充正式 Chrome 商店安装；Chrome 正式扩展身份与商店条目仍空，因此该特定发行路线不能宣称可用，但增量没有把 Chrome 商店设为所有浏览器接入的唯一前提。Linux 的手动退出原输入服务、使用私有会话、手动恢复流程已在[已确认设置原型](../design/TypeLay_Tray_Settings_Prototype.html)中明确呈现，必须验证告知、用户选择、原配置保留与安全恢复；不能据此宣称已经达到无需切换、完全保留原输入体验的最终目标，也不应擅自把重写整条输入栈加入本次验收。具体支持与恢复步骤见平台说明。
- 规格 §18 的验收以四个快捷键动作可配置、默认 Tab 安全规则、冲突提示和可强制保存为准。[已确认设置原型](../design/TypeLay_Tray_Settings_Prototype.html)明确：接受/退出使用默认 Tab/Esc、F1–F24 或 Ctrl+F1–F24，并须使用不同主键；按需唤醒/直接替换使用 Ctrl/Alt（可加 Shift）与字母、数字或功能键的组合，F12 不用于这两个全局动作。当前四动作已实现配置，另外已有 Shift+功能键的窄增量；不把“所有动作可配置”扩成“任意修饰组合必须支持”。保存前已加入常用组合风险提示、精确草稿确认与强制保存；Windows 另检查按需组合的当前注册可用性。未发现冲突不代表穷尽检测了应用内快捷键，强制保存也不授予输入或写回权限。共享/Host 合同已有验证，新增目标桌面交互仍须实际回归；既有 Ctrl+功能键的源接受及按键配对红项也必须修复，不能用新增组合掩盖。旧组件或配置不一致继续拒绝未经确认的消费。各平台实际结果见其说明，软件输入不替代物理键盘与输入法验收。
- 规格 §5.2 的弱化恢复入口已接入共同状态与双端实现；Windows 真实渲染、点击恢复和失效四项已通过；ce4ca0f 已实际完成 GTK3/GTK4 原生恢复按钮、暂停时零捕获/模型/写回和只恢复启用状态的检查。各平台剩余边界仍按对应桌面结果验收，不能用共享测试或另一端结果代替。
- 规格 §12 的风格持续/应用覆盖、§19.2 换种说法和 §20 显式术语表已在[开发源码 `b114469b`](https://github.com/DingJWuyu/Typelay/actions/runs/39434470371)接入真实模型后端、双端设置及浮层操作，三项质量发布门全部关闭。这些是尚未满足的交付要求，不是可以省略的可选实现。[最近显式质量运行 d372](https://github.com/DingJWuyu/Typelay/actions/runs/39482300330)已完成 53 次实际响应：Argos 换种说法 32 次、Hy 风格 16 次、术语 5 次；沿用冻结样本，各 worker 正常退出。包内实物与源码摘要已核对，确实运行了新候选；采集完整不等于质量通过，原报告的人工审核字段仍未签署。当前审阅结论如下：
