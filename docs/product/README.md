# 产品行为与验收基线

两端共同按[冻结规格 v1.0](TypeLay_产品规格_v1.0.md)及已接受的[ADR-0002：自动/按需与一次性直接替换](../adr/0002-on-demand-and-direct-write.md)验收。增量与冻结基线重叠时，以该已接受增量为准；其余原要求继续有效。本文提供阅读入口与操作摘要，不改写冻结正文。

[统一应用接入与双端体验](application-support.md)是已接受的后续产品增量：设置中的支持管理、状态/动作与用户文案由双方真实消费同一共享定义，Windows/Linux 分别完成相同体验验收。不能用一个平台的完成状态代替另一个平台。

“工作模式”是设置项总称，选项是“自动模式”和“按需模式”。Windows/Linux 的实现范围、测试证据与缺口不是产品要求的替代品。已确认的[浮层原型](../design/TypeLay_UIUX_Prototype.html)和[托盘/设置原型](../design/TypeLay_Tray_Settings_Prototype.html)是交互基线，不是客户端验收证明。

## Index 默认模型

用户已确认采用官方 Index Translate 2B Q4_K_M 作为新用户明确准备时的默认方案，范围限于现有十四个直接翻译方向。已有 Argos/Hy 安装、active 选择和方向子集保留，启动不下载、不自动换代。模型切换不改变输入、焦点、预览、写回或 Undo 的产品安全条件。模型能力与质量门见[模型运行架构](../engineering/model-runtime.md#模型能力边界)。默认采用不代表质量全面放行，也不改变既有发行包身份。

## 手动启用 Hy 中英预览

这是用户已批准的可选预览增量，不自动改变已有模型选择或源/目标语言；新用户默认方案现为下述已采用的 Index。Hy 新安装仍只登记中文与日语、韩语、法语、西班牙语、德语、葡萄牙语互译的十二方向；更新软件、修复或重新选择已安装 Hy 都不会自动增加中英。

在“设置 → 应用支持”的已安装 Hy 行选择“补充中英方向…”，阅读并明确确认后，才复用本地已验证权重补充中文与英语双向。取消不改变库存；准备失败保留可用旧代。补充不自动选择 Hy，仍使用 Argos 的用户可在准备完成后手动选择 Hy；语言设置保持原值，实际加载成功后才声明新增方向可用。

**中英预览暂不支持风格和术语表，可能出现错译或漏译，须核对译文。** 不支持的高级操作明确说明原因，不悄悄改为普通翻译；原十二方向的技术能力不因补充中英被整体删除，已有质量发布门仍关闭。小样本比较与双向 smoke 不代表质量全面通过，平台真实 GUI、冷启和退出仍按对应候选证据验收。

**启用中英预览后不支持直接降级旧版本；可在当前版本切回 Argos 继续使用。** 若未安装 Argos，需先明确确认下载安装；不保证离线可切回。切换模型、移除 Hy 或普通卸载软件都不构成跨版本恢复承诺，不手工裁剪库存方向或更改安装标记。

## 工作模式与按需操作

在“设置 → 常规 → 工作模式”选择模式，重启后保留。升级时没有此偏好的用户仍使用自动模式，已有应用排除项不会因新增偏好失效而被清除。

| 模式或操作 | 行为 |
| --- | --- |
| 自动模式（默认） | 聚焦后按原有规则显示语言胶囊、生成译文与接受译文。两个新增快捷键均不启用。 |
| 按需模式 | 正常聚焦、输入时不显示翻译 UI，也不自动运行翻译。 |
| 唤醒翻译 UI：默认 `Ctrl+Shift+F9` | 为当前输入框开启持续翻译体验；空框显示语言胶囊。正常编辑 TypeLay 译文不算离开；转到其他输入框后结束，返回原框也需要重新唤醒。 |
| 直接翻译并替换：默认 `Ctrl+Shift+F10` | 有选区时只处理选区，否则处理当前输入框文本。一次性操作，不显示预览、不需要 Tab、不发送或提交。 |

唤醒、直接替换与接受译文均不会更改工作模式。直接替换绑定触发时的原输入框和文本；翻译期间可切换输入框或应用，任务不会仅因焦点变化取消。结果只尝试写回原控件，不抢回焦点，不修改后来聚焦的输入框。目标失效、原文冲突、输入法状态不明确或结果未知时安全拒绝或隔离，不进行有风险的重试。

## 接受后主动切换应用时的 Tab

用户已明确选择：译文接受后仍按住 Tab，并主动切换到另一个应用时，后续重复按键和松键按 Windows 正常规则交给新应用，TypeLay 不跨应用持续拦截到松键。这是对冻结规格 §18 的已接受澄清，不要求为未合作的新接收者保留整次按键的全局消费权。

留在源应用内的重复按键与松键仍沿原接受按次处理，不重复接受、不重复写入。切换应用不改变原写入目标，不给新应用授予写权限，也不放宽原文、目标身份、IME、回执和显式撤销的安全要求。此澄清不解决 UIA 非原子写回或首键低级 Hook 超时泄漏，普通 Windows 自动写回仍默认关闭。

## Windows 接受译文的辅助输入兼容范围

用户已明确允许：Windows 认可的 UIAccess 辅助输入工具可以代替用户按键接受译文，普通程序模拟按键继续拒绝。这是接受译文的输入来源范围，不是给 TypeLay 提权、修改系统安全策略、注册输入服务或开放生产写回的授权；也不改变按需快捷键及其它平台的既有输入政策。

允许的来源类别可以同时包含硬件与 UIAccess 软件输入，因此不能承诺每次接受都来自物理键盘或真人当场操作。原目标、最新正文、IME、有效按次、消费/写入协调和回执条件仍须满足；来源未知或不能确认对应本次接受消息时拒绝。具体平台分类与尚未完成的机制见 [Windows 输入来源资格](../platforms/windows/architecture.md#输入来源资格)。

## 暂停与恢复

暂停会清空当前翻译会话、候选和编辑草稿，并撤销新的接受资格。在可确认的普通输入框旁保留弱化的“已暂停 / 恢复”入口；敏感、排除、身份不明或失焦字段不显示该入口，托盘和设置仍可恢复。

点击恢复会重新核对当前字段并保存启用状态，不更改工作模式。按需模式仍需使用配置的唤醒快捷键；旧候选不会恢复。设置保存失败时保持暂停并说明原因。暂停前已经发出的写回仍按真实回执报告，结果未知时不自动重试。

## 当前共同开发缺口

未完成工作及其证据由 [GitHub Issues](https://github.com/DingJWuyu/Typelay/issues)维护。工程验证任务完成不代表冻结产品全部交付。

共同验收仍保留以下边界：

- 两端分别从完整安装包与设置入口接入普通网页和桌面自然语言字段，完成预览、接受、编辑回源、直接替换和取消恢复。代表性应用是验证样本，不构成无限控件兼容承诺。
- 富文本保持规格 §13.3 的结构与选区安全。不支持的结构明确拒绝，不静默整框扁平化。
- 浏览器接入使用合法且普通用户可完成的安装路径。开发加载不代表商店安装；Chrome 商店也不是所有浏览器的唯一接入方式。
- Linux 输入服务切换须告知用户，保留原配置并支持安全恢复。合作组件与私有会话不能证明冻结规格的透明接入目标已经完成，该差距继续[阻塞最终产品验收 #20](https://github.com/DingJWuyu/Typelay/issues/20)。
- 规格 §18 的四动作配置遵循已确认设置原型。接受与退出支持默认 Tab/Esc、F1–F24 或 Ctrl+F1–F24，且使用不同主键；既有 Shift+功能键增量保留。按需唤醒与直接替换使用 Ctrl/Alt，可加 Shift，配合字母、数字或功能键，但不使用 F12。冲突提示与强制保存不授予读写权限，也不承诺检测全部应用快捷键。
- 术语、按应用风格和换种说法分别受模型、方向及固定 profile 的[采用条件](../engineering/model-runtime.md#模型能力边界)约束。保存偏好、界面回归和模型握手均不开放质量门。
- 规格 §28 的教程由真实输入、接受和完成操作推进。模型准备、提示偏好与练习进度都不授予源字段权限，旧窗口、配置或迟到结果不得继承完成。
