# 统一应用接入与双端体验

状态：已接受的产品增量。与[冻结规格及已接受增量](README.md)共同验收；不改写冻结正文，也不降低字段身份、输入法、期限和写入安全要求。

## 一个产品，两种平台实现

Windows 与 Linux 提供相同的产品功能、设置入口和用户流程。差异由底层平台适配承担，不要求用户了解 UIA、GTK、Qt、Fcitx 或 native messaging 才能使用 TypeLay。

新增支持类型、状态、操作和用户文案必须有单份共享定义，并被两个平台真实消费。设置中的分组、项目顺序、状态含义、能力说明、动作和失败恢复流程不能在两套界面中独立硬编码。原生 WPF/GTK 负责渲染与无障碍操作；平台负责检测、安装、权限衔接和应用连接。只有真实跨平台消费者的逻辑进入共享层，系统专属实现仍留在对应平台。

双端可以因实现或验证耗时短暂先后，但一端完成不代表该产品增量完成。未接入、受限和未验证必须显式保留，不能把缺失功能悄悄归为平台差异。实现范围和现场验收记录仍见各平台现役文档。

## 设置中的共同流程

统一入口为“应用支持”，按以下顺序组织：

1. **准备翻译**：检查本地组件、模型与实际自检结果，复用已有安装、暂停、继续和修复功能。
2. **连接应用**：选择需要使用的支持类型，检查内置能力或可选接入组件，显示检测依据、具体阻塞和下一步操作。
3. **试一试**：在实际应用输入框完成预览与已允许的替换，确认当前字段的真实能力。
4. **失败恢复**：在原入口查看原因、重新检查、修复连接或移除用户选择的接入方式，不要求用户记住外部命令、内部目录或插件标识。

准备区按实际阶段突出一个主要操作：尚未准备时准备组件，下载中可暂停，暂停后继续，失败后保留原因并重新准备；已有模型可用不能盖掉本次准备失败。模型就绪且没有待恢复的准备操作时突出下一步，修复作为次级管理操作。按钮文字必须描述实际动作：直接打开练习可用“试一试”，仅展开接入步骤应写“选择接入方式”。本机输入服务、模型可用性和所选应用接入分别显示；连接状态变化不能清除上次操作失败或结果未知的提示。

模型准备完成、安装器返回成功、注册文件存在、打开练习窗口均不能代表应用连接或完整教程已经完成。每一步允许取消、离开和返回继续；成功标记必须描述已经实际完成的步骤。

## 默认简单，详情按需展开

优先自动发现用户已经在用的应用，主视图说明当前能做什么，并给一个最有用的下一步。尚未使用的应用集中在次级入口；未知状态须能重新检查，不能因为未发现就隐藏实际问题。

不让用户阅读适配器矩阵、选择底层协议或填写插件标识。能力、版本、路径和诊断保留在可展开的详情中。共享呈现定义决定默认分组、主要动作和用户文案，两端不各自选择不同的产品流程。

普通状态变化不反复确认；真实权限、影响其它应用或系统输入的操作仍解释影响并取得必要批准。每个按钮应对应具体用户任务，不能只因为底层提供了接口就展示为设置项。

## 设置保存

普通有效的开关和选择在操作成功后即时持久化。失败时恢复界面中的实际值并说明原因，不显示虚假的保存成功。快捷键等必须整体校验的输入保留草稿，用一个明确动作提交；状态刷新不得覆盖草稿，关闭时应明确处理未保存的修改。安装、授权和有实际系统影响的操作仍是独立显式动作，必要的实验功能警告予以保留。

## 连接状态与操作

支持类型由共享定义列出，平台报告实际事实。内置接入不虚构安装步骤；可选组件分别说明尚未安装、需要用户授权、需要重新打开应用、已经连接或需要修复的情况。注册完成与组件实际连接必须区分，未检测到应用不能显示为连接正常。

界面优先给出下一步可执行动作，而不只展示底层错误：检查连接、安装或启用、完成用户授权、重新检查、修复连接、移除接入。动作能否执行取决于真实状态；不提供没有实现的成功按钮或一键承诺。

- 浏览器或操作系统要求的批准由用户完成。TypeLay 引导至对应页面和明确步骤，不绕过权限、签名或安全提示。
- 路径、注册内容和启动参数由 TypeLay 管理；必须选择已有组件时使用文件选择与校验，不让用户手写内部参数。
- 选择组件目录只授权读取和检查文件，不授权执行其中的脚本、程序或动态库。自带清单与文件哈希一致仅说明完整性，不证明来源可信或运行兼容；缺少可信来源验证时只提供检查结果和官方接入引导。
- 输入法或应用进程的切换具有实际影响时，先解释影响和恢复方法，再由用户明确选择。不能悄悄结束用户进程、修改全局环境、自动启动项或个人输入法配置。
- 修复和移除默认保留用户设置、模型及个人数据。不能覆盖不属于 TypeLay 的注册项或把系统包伪报为私有组件。
- 可选扩展仍是 TypeLay 的内部接入方式，不成为用户需要分别管理的另一套产品。

## 当前字段的能力

组件连接不代表每个输入框都可写。对当前应用和字段分别说明三项能力：

- 显示译文
- Tab 接受译文
- 直接翻译并替换

自动/按需是工作模式，不是上述能力的等级。仅手动预览确认的接入方式不能冒充自动浮层、Tab 或 F10 已完成。

密码、敏感字段、未知输入法、失效目标和原文冲突继续拒绝。未知状态不能为了改善安装体验而变成可用；更不能把之后聚焦的字段替代命令触发时的目标。

## 稳定操作与清楚反馈

候选和“Tab 接受”提示应与实际可接受状态一致。正常稳定输入框不应要求用户碰运气赶上几毫秒窗口；优化应依据真实发布、到达、刷新和写前检查时序，不能通过重复按键、盲目延长期限或放宽安全断言制造通过。

用户明确执行唤醒或直接替换时，未执行、取消和失败必须提供简短可理解的原因与下一步。无目标、接入未就绪、输入法组合、原文已变、许可过期、模型故障等不能全部表现为没有反应。反馈绑定该次操作；旧配置、迟到或重复回执不得覆盖新的操作状态。失败通知不抢焦点；系统通知服务不可用时保留最近操作状态，不把通知请求已提交说成用户已经看见。普通输入过程不弹出反复打断用户的错误窗口。

## 双端完成条件

共同增量须在两端分别走真实链路，并用同一组用户结果验收：

- 从完整安装包打开设置，完成模型准备，检查应用连接；取消后可以恢复。
- 通过设置选择并接入至少一个普通浏览器网页字段与一个普通桌面自然语言字段；实际连接结果与页面显示一致。
- 无标点的已提交文本可按现有近实时要求生成预览；输入法组合与已提交内容仍按安全边界区分。
- 自动/按需、唤醒、Tab 接受、编辑后两阶段 Tab、直接替换遵守共同产品要求；触发不成功时反馈可理解。
- 需要用户批准、应用重启或组件修复时，入口和下一步清晰，既有用户配置不被覆盖。
- 卸载、失联、字段变更及取消后状态正确恢复，不保留虚假的可用或完成标记。

共享行为测试、平台真实控件验证、发行包搬迁和用户实机体验各自提供不同层次证据。构建成功、源码复用、模拟适配器或一端的桌面测试不能代替另一端的真实验收。
