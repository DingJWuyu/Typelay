## 优先级与覆盖关系

用户本轮确认的产品变更 > 冻结规格中对应旧 UI 规则；未修改行为继续按规格执行。两个 HTML 是视觉/交互参考，不是 Win32 焦点、Hook、IME 或真实翻译证据。原始报告是事实记录，项目层面“基础路线通过、带风险结项”的阶段决定不改写报告结论。

| 冻结规格旧表述 | 本轮执行基线 |
|---|---|
| 空输入显示语言胶囊 | 空框安静，不提前显示 Auto → EN |
| 优先右上、选区可另行锚定 | 统一当前输入框正上方附近，适当间隔、避边界，不覆盖输入区域 |
| 旧结果 / 已过期提示 | 用户统一看“正在翻译”，黄色点，Tab 交还应用 |
| 有效译文 | “译文就绪”，绿色点；只有全部安全条件成立才显示接受提示 |
| 接受后收回语言胶囊 | 接受后静默收起，无 toast / 通知 / 成功反馈 |
| 选区失效提示原文变化 | 内部取消或重算，界面不解释工程原因 |
| 准备/IME 状态 | 不展示 IME；提交后走普通翻译；用户可见生成态统一 |
| 复制 / 重翻 / 更多操作 | 不进入当前 MVP 核心浮层 |
| 暂停后保留弱胶囊 | 按 Tray 原型：暂停只保留托盘入口，不显示输入框 UI |
| 原型 Esc 模拟离开应用 | 正式 Esc 仅结束 TypeLay，不强制 blur 或切应用 |

仍保留：全文/选区准确替换、原文与目标绑定、状态驱动的两次 Tab、人工编辑后追加原文尽量保留与融合、修改既有原文则重译、已经是目标语言不做改写、CPU-only、本地隐私、模型未就绪不冒充可用、风格人工编辑锁定、应用排除。尚未实现不等于批准删除。

## PoC 事实与证据边界

收尾报告记录：Windows 原生 smoke 13/13；真实 Edge 中中文→真实本地 Argos→物理 Tab 原位写回→Submit count = 0 成立；点击译文后的编辑流程失败；真实中文 IME 与浏览器失效保护未执行。最终旧自动回归 98/98 是**报告记载**，不是新工程结果，也不是本轮重跑所得。

本轮实际执行了旧源码的 `tools.provenance.source_identity()` 指纹计算，得到：

```text
source_sha256 = 4b3123feb45e4e64a11a6190a14ec400ccb3c4a9dc0e4289124928f8eef6d962
source_file_count = 47
```

这与收尾报告环境部分完全相同。逐文件结果保留于 `evidence/poc-source-identity.json`。

另有一个包装一致性问题：压缩包内独立 `PACKAGE_MANIFEST.sha256` 的 `typelay/ui.py` 条目校验失败；其余列出的条目未报告失败。完整的最终源码指纹却与报告一致。可确认的是**独立 manifest 与最终源码存在不一致**，不能仅凭此断言篡改或修复历史。保留原件，记录问题，不修改旧代码或补签旧结论。

## 复用决定

| 旧模块 / 内容 | 审阅结论 | 新工程处理 |
|---|---|---|
| `model.py` / `safety.py` | 原文、目标、选区及安全断言值得保留 | 用 C# 不可变记录与 WriteSafety 重写，并重新写测试 |
| `gate.py` / `platforms/hooks.py` | permit、注入标志、按下/抬起/重复键知识有价值 | 移植判定思想；不直接移植 Python Hook。实际全局 Hook 尚未实现 |
| `engine.py` / `ipc.py` | 请求版本、过时结果丢弃、进程 watchdog / 单任务队列思路适合复用 | Core 先实现版本检查；IPC/worker 后续正式实现 |
| `platforms/windows.py` / `win32.py` | 原生 EDIT 读写、字段排除、UIA 的能力边界有参考价值 | 定向 Win32 API 重新绑定，当前仅在已注册 fixture 内开放 |
| `ui.py` | Tk 主循环、焦点识别与浮层绑定曾暴露真实失败 | 不复用；设计 WPF 持久控件 + 明确焦点组合 + 回源确认 |
| `translators.py` | 本地 Argos 集成、断网测试与模型预热经验有价值 | M2 用隔离 worker 重新接入，不拷贝网络 monkeypatch 当沙箱证明 |
| `browser_fixture.py` | 独立 Edge 窗口启动和超时预算经验可保留 | 后续启动器复现；不能把旧探测预算当接受许可 TTL |
| `tests/` / `windows_smoke.py` / `collect_evidence.py` | 边界用例、准备步骤回读、run_id、源码前后指纹、提交计数可复用 | 建新 C# 测试与新取证入口；旧“通过”不继承 |
| 两个 HTML | 确认信息密度、位置、文案、结构与用户流程 | 不直接作为正式 UI，不复制 DOM 全量重渲染、trim 或模拟失焦语义 |

本次**没有把旧 Python/Tk 代码直接并入新生产程序集**。复用的是知识、断言和设计约束；未来接 Argos 可以重新封装非常小的 Python worker，不能据此退回整个旧应用架构。

## 不能原样沿用的安全判断

1. 增加 UIA worker timeout 可以减少误判超时，但不能让旧文本/目标的接受许可保持几秒有效。
2. `SetSelection → Replace → Verify` 不是跨进程原子事务；修改选区后失败也不能自称“完全没有改变输入框”。
3. Tab 在 Hook 中吞掉后才做 UIA 检查，存在拒写但丢掉按键的窗口；不得对新焦点盲目回放。
4. provider 不提供 composition 信息时必须是 Unknown，不能用英语键盘布局或没收到事件直接宣告 Clear。
5. 测试页面固定 ID 是定位线索，不是网站可信身份和敏感内容分类的安全边界。
6. 原型避免某次重渲染失焦，不证明 Windows HWND 激活与跨应用返回已解决。
