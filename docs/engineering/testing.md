# 为变更选择验证

先用最接近用户的路径观察问题，再在能观察同一故障的边界保留回归。本页帮助你选择验证范围和判断完成条件。命令环境见[开发流程](development.md)，测试归属见 [tests/AGENTS.md](../../tests/AGENTS.md)，产品要求见[产品验收基线](../product/README.md)。

## 实际价值判断

选择改进、扩展诊断、增加测试或设置发布门前，在当前任务说明中回答以下问题：

1. 用户正在完成什么任务，预期结果是什么？
2. 已观察到什么故障，哪些风险仍是假设？
3. 故障预计多常发生？没有数据时写“未知”。
4. 故障会给用户带来什么影响，严重程度如何？
5. 实现、验证和长期维护需要承担什么成本，预期收益是否值得？

优先处理真实用户路径中已观察到的故障。仅理论可达、实际罕见且收益低的强化，不自动成为需求或发布阻塞。风险富集测试的失败比例不能当作日常发生率。

可信的数据丢失、隐私泄漏和错误目标写入风险仍需安全门。说明风险机制与证据，不能因发生率未知而取消保护，也不能将所有体验细节都升级成安全合同。

用户明确改变范围后，同步更新需求与专属测试。仍保护有效行为的回归应保留；已无现役消费者的测试应退役。测试失败时先区分需求、测试构造和产品根因，再决定处置。

用可观察的用户收益或明确证据判据结束工作。没有新假设或新证据的重复探针应暂停，并写清恢复条件。无需建立评分平台或额外报告。

## 先选择能证明目标的边界

选择下面最接近目标的入口。较低层的成功只证明该层合同；平台、模型、桌面和视觉结果仍需各自证据。

| 你要确认的行为 | 首选入口 | 结果能证明什么 |
| --- | --- | --- |
| 会话、候选、人工草稿和接受资格 | `tests/shared/TypeLay.Core.Tests` | 公开操作序列中的状态与安全拒绝。 |
| 宿主编排、异步失效和设置持久化 | `tests/shared/TypeLay.Runtime.Tests` | 生产控制器配合受控端口的行为，以及真实临时文件的保存语义。 |
| 帧协议、库存、文本结构和 worker 退出 | `tests/shared/TypeLay.Protocol.Tests` 与 `tests/shared/worker/` | 协议和无模型进程边界。替身输出不能证明翻译质量。 |
| Windows 目标身份与 Broker DTO | `tests/windows/TypeLay.Windows.Contracts.Tests` | 可跨平台运行的 Windows 契约，仍不证明 WPF 或 UIA。 |
| 平台输入、浮层、设置或编辑交互 | [Windows 测试](../platforms/windows/testing.md)或 [Linux 验证](../platforms/linux/development.md#验证) | 对应真实进程、受控宿主或桌面路径，范围须逐项标明。 |
| 安装、启动或部署路径 | 平台说明中的发行包验证 | 搬迁后实际 ZIP 或 tar.gz 的入口与生命周期。 |
| 模型输出是否保义、术语或风格是否有用 | [翻译质量采集与评审](translation-quality.md) | 固定身份和输入上的实际响应及人工评审，不能由协议通过推断。 |
| 物理输入法、按键、Undo 或视觉表现 | 对应目标平台的真实桌面验收 | 用户实际交互。软件注入、嵌套合成器和截图各有独立范围。 |

普通输入框是产品目标，代表性应用只是验证样本。未知输入法状态、焦点身份和写入安全必须保持拒绝，不能为通过测试猜测状态。

## 沿失败路径修复

1. 在最接近原用户路径的环境复现一次故障，保存命令、提交 SHA、平台、退出码和最小失败输出。
2. 提出可证伪的原因，一次只改变一个相关因素。先取得失败证据，再修改实现。
3. 用同一可观察边界验证修复，并检查受影响的邻近行为。
4. 运行对应工作区检查，删除临时探针，保留有效回归。

控制器状态与原生焦点属于异步观察。等待实际用户结果，不以一个进程的状态通知代替另一个进程已经完成操作。确定性时间由测试显式驱动；端到端测试使用有界等待和自身资源清理。

测试只操作自己的进程、隔离配置和合成文本。端到端回归不修改真实用户设置，也不自行下载模型。失败时保留原件，不用任意等待、无上限重试或放宽断言掩盖问题。缺少目标环境时如实记录未测。

## 修复交接检查清单

修复交付或子代理交接时，在交付说明中逐项说明以下内容。无需另建报告文件。

- 列明受影响的既有测试、fixture 和消费者，以及它们依赖的旧行为假设。新增回归不能代替这项核对。
- 新增或拆分 partial 源码、修改 `Compile Include/Link` 时，检索所有显式链接该源码的项目，核对并构建受影响消费者。默认 glob 项目通过不能覆盖手列 Link 的 fixture。
- 测试 helper 读取持久化配置时，按正式反序列化语义检查完整对象、空对象和稀疏字段。只有缺失字段可使用正式默认值，显式非法值仍须拒绝。
- 说明既有回归为何保留、更新、替换或退役。退役时指出原行为由何处覆盖，或为何已无现役用途。
- 给出同一边界的修复前后证据、邻近验证和未测项。区分静态检查、受控端口与实际桌面结果。
- 核对本次变更替代的实现、重复逻辑、无用文件、过期文档和依赖。同步清理引用，保留有效安全合同，不扩展成无边界重构。

## 共享行为与协议

运行 `pwsh -File ./dev.ps1 shared-check` 可验证共享行为及可移植 Windows 契约。该入口不运行 WPF、UIA、Hook 或真实模型，完整平台检查仍按变更选择。

维护共享回归时，按以下行为边界保留证据：

- 会话回归区分只读预览、接受候选、人工草稿与写入许可。短期许可到期不应使编辑入口闪烁；浮层是否完整显示文本仍需平台渲染验证。
- 设置回归区分文件保存与配置变化通知。相同有效值仍需真实保存并暴露写入失败，但不应因此重配会话。稀疏字段、外部数组修改、旧表单和保存后的通知失败沿正式消费者验证。
- 风格与术语回归分别验证保存、当前源的应用资格、迟到响应及人工草稿保护。风格只重绘时不应广播普通设置重配；术语变更仍需检查 Append 已冻结前缀和 Direct 提交边界。
- worker 的 `test_stdio.py` 启动真实隔离进程，验证噪音隔离、帧输出和退出。Windows 的 `WriteFile` 分支须在 Windows 执行；Linux 结果不能替代。
- 高级能力回归分别检查库存、精确 hello、方向范围、原生符号和独立质量门。单项能力不授予组合资格，拒绝时不能改发普通请求作为降级。结构与指定译法的受控输出不证明真实推理或保义。

这些回归使用生产公开边界。仅在现有边界无法观察问题时增加接口；不要用源码字符串、实现反射或假模型证明产品可用。

## 手动 Hy 中英预览接入合同

修改 Hy 安装、方向或能力协商时，同时保留旧十二方向和显式十四方向路径。正式 catalog 可列十四方向，但新装默认仍为十二方向；更新、Repair 和 Select 不补方向。用户通过“补充中英方向…”明确确认后才扩展。

验证确认与取消、候选失败后恢复精确旧代、同代冷启、中英双向普通预览，以及切回和移除。目录存在、受控文件复制、管道 peer 或 native ABI 检查，均不能代替真实安装后的 Host 和 GUI 激活。

中英预览仍不支持风格和术语，质量尚未全面通过。旧目录必须明确拒绝十四方向，不自动删除方向。切回 Argos 也不能证明跨版本恢复；真实中英产品链、整代恢复和语言质量分别验收。

## Index 默认切换的验证边界

修改默认模型或 Index 集成时，先验证结构、库存和原生接口，再执行对应平台的正式包生命周期。`test_index_integration.py` 覆盖 whole 单次调用、非翻译片段、逐槽术语与源布局；`test_index_native.py` 和 Linux `test_index_runtime.py` 维护原生身份及资源边界。

实际模型验证使用正式安装器、宿主和同一 worker，覆盖多个不同源、结构要求以及失败或取消后的隔离。两端入口见平台开发说明。预算保持总计 600 秒、单请求及加载 60 秒、退出清理最多 7 秒；每阶段分别记录结果。旧 Hy 或输入链的失败不因 Index 成功而关闭。

对同代码、同输入的失败不作语义重试。定位并修改实现后才验证新候选，保留旧失败原件。Index 的固定推理配方由模型锁和 profile 维护；集成结构校验不等于原始模型与研究基准的质量或延时相同。

## 结果表述

在任务回复或 CI 结果中，分别报告构建、行为/协议、分发/进程、模型推理、桌面交互和视觉结果。每项使用 `passed`、`failed` 或 `not-run`，并写明实际范围与对应提交。

结果只属于执行时的代码与环境。编译不能代替行为执行，受控端口不能代替桌面，采集完成不能代替语言质量。缺失原件时标记不可核实，不能用摘要补造结果。

将 TRX、日志、截图和原始响应保存在被忽略的 `artifacts/` 或对应 CI artifact。未完成任务保留必要证据；完成后清理临时文件。当前安排统一维护在[开发状态页](development-state.md)，不新增仓库内验收报告或空白模板。
