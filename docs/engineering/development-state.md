## 怎么安排，谁负责

下面的负责人是工作角色，不是“已有多少代理在运行”的声明。协调者在开工、交接、出现新失败和发布时核对本页，给每个活任务指定实际执行者；没有在运行的工作标为待做，不计作进展。

常态编排为 **五个负责人 + 一名集成协调者**，保留一个机动位置做独立审查或候选模型接入，不为每个新想法继续增加并行任务。

| 责任线 | 当前职责 | 本轮交接证据 |
| --- | --- | --- |
| Linux 维护与安装 | 维护现有支持路径，改善首次安装、依赖诊断与恢复；暂不做可选应用扩展 | 最小改动、对应回归与新包验证结果 |
| Windows 主开发 | 逐项关闭下表桌面失败，验证已合并的 Ctrl 消费端；不陷在无新证据的反复运行 | 本地验证、独立审查、当前提交桌面 CI |
| Argos 调优 | 已准备 repetition penalty 1.05/1.0 单因素普通对照，下一步完成审查与执行接线 | 固定输入/配置/预算；实际运行后提供原响应与逐句比较 |
| Hy 调优 | 普通翻译对照与 cache-only 入口已接入，下一步显式触发有界实验 | 普通 A/B harness、CI/cache-only 路径审查；之后才有真实推理证据 |
| 替代模型研究 | 只读筛选最多三个候选，比较语言方向、许可证、资源和接入可行性 | 有来源的候选比较及采用/不采用建议，不把宣传分数当产品质量 |
| 集成协调 | 分配资源、审查证据、顺序合并发布、追踪 CI，并更新本页 | 候选、检查、发行包身份一致，任务有下一动作和关闭条件 |

研究、代码和审查可以并行；**同一机器上的重模型推理串行运行**，由协调者分配 CPU、内存、缓存与预算，避免互相争资源造成假性能结论。找到替代候选后先评估，再使用机动位置做一个有限接入；不是找到一个就立即下载并新增常驻负责人。

```text
Linux Qt 修复 ─────────┐
Windows 已收敛测试修复 ├─→ 集成负责人审查 → 发布下一候选 → 双端 CI → 按失败证据继续修复
Windows 定位所需诊断 ─┘                                      └→ 核对包与支持范围 → 提供体验

Windows Ctrl 组合键：共享合同 → Windows 消费端 → 独立审查 → 实际桌面验证 → 后续候选
Linux 安装体验：核查首次安装/恢复 → 选定实际摩擦点 → 最小改进 → 对应安装验证
Argos 调优 ────→ 固定单因素对照 ─┐
Hy 调优 ──────→ 普通翻译对照入口 ├→ 分配推理资源 → 真实采集 → 逐句复核 → 决定是否采用
替代模型研究 ──→ 最多三个候选 ──→ 评估 → 机动接入与验证
```

**先发布已经收敛的修复，不让未完成的独立任务阻塞整批。** Ctrl 与安装小改进若在批次关闭前完成审查和联合验证可一同纳入；模型研究不作为该批前置。 集成与发布由一名负责人顺序执行，独立任务在不同工作区并行。CI 等待期间可继续审查、补回归或推进独立任务；CI 结果出来后优先核对，不把等待当成整项停工。

### 翻译质量：先算清做过什么，再做有效对照

负责人：Argos 调优、Hy 调优、替代模型研究各一人，集成协调者统一安排实际推理资源。应用层只承担有依据的保护和异常处理，不以修提示词代替模型质量验收。

- **已核对的尝试**：Argos 至少实跑 beam2、beam4 两套普通/另述配置，beam4 未解决“20 分钟”保义问题，已撤回。Hy 至少实跑 greedy 与固定 seed `20261020` 的 sampling（temperature 0.7、top-k 20、top-p 0.6、repetition penalty 1.05），但该对照仅覆盖自然/正式任务。普通翻译目前只核实官方 prompt + greedy 一套，没有普通任务的多 prompt/模板公平 A/B。40/69 次请求不是配置方案数，不能声称已穷尽尝试。
- **已知范围**：Argos 当前项目仅中英双向、无 prompt；生态中有更多语言包，不等于本项目已经启用。Hy 是带翻译提示与模板的可选模型；当前普通翻译与风格实验均不能证明整体质量过关。Index 的有限对照有改善也有退化，尚未采用。
- **Argos 当前任务**：先核实已有模型缓存和能够独立改变的参数，再确定一个单因素对照；保留现行默认作为基线，不混入模型版本、分句或保护逻辑变化。缓存不可用时先报告资源选择，不自动重复下载。新配置尚无真实推理结果。
- **Hy 当前准备**：普通解码 A/B 与 CI comparison 的普通模式、cache-only 路径已完成实现、独立审查和联合测试，没有调用真实模型。发布后由协调者显式触发一次同提交的 quality-only 对照，先核缓存命中和身份，缺缓存即停止、不补下载。full 与 quality-only 已分为两个固定并发组，实际并发效果仍待运行核验。harness 通过不增加已实际尝试的配置数。执行协议归入[测试协议](testing.md)，以合入后的普通翻译解码对照入口为准。
- **替代模型当前任务**：只读研究最多三个候选，优先核对官方来源、许可证、目标方向、CPU/内存/下载成本和现有适配接口；给出是否值得试的建议。接入和推理另经评估与预算安排，不在研究阶段宣称效果优于现有模型。
- **Hy 明确待做的最小对照**：固定 Hy 1.8B、官方对话模板与同一组八句普通翻译难例，先只比较解码配置；再固定解码，比较官方 prompt 与一套保义约束 prompt，另用留出样本复核。预先确定采样 seed，不挑选有利结果。执行渠道与资源预算确认后才运行；目前这是计划，不是已跑证据。每句检查否定、数量、承诺程度、方向和结构，优先回答已有失败能否改善，不无限扫配置。
- **每轮停止条件**：运行前固定样本、配置、seed、请求数、时间/资源上限和退出清理要求；完成预定矩阵或触及上限即收束该轮，记录失败与未跑项。结果不理想先分析原响应，再决定下一轮，不反复换 seed 挑好结果、不自动扩大预算。只读研究得到最多三个可比较候选及结论即交接；没有合适候选也可形成有效结论。
- **替代模型当前筛选**：MADLAD-400 Q4K 有不同的多语言 encoder-decoder 路线，但已核 Candle 初始化权重加反量化 embedding 就超过当前 2.5 GiB 预算，暂不下载；这不是质量失败。M2M100-418M 保留为单包多语言的低成本对照候选，尚无胜过 Hy 的证据。TranslateGemma-4B 暂缓资源与条款核查。三者均未实跑，不因候选存在就扩张生产模型目录。
- **完成条件**：保留每组模型/配置身份、失败与退出证据、原响应及独立逐句评价；报告改善和退化，达到对应产品质量门才开放功能。emoji 等保护修复只证明结构处理改善，不算语义质量过关。

具体质量证据与发布门见[产品共同缺口](../product/README.md#当前共同开发缺口)，采集方法见[测试协议](testing.md)。本页不另复制实验历史。

## 每条线都要做的维护

1. **保持原行为与安全门。** 遵守 [AGENTS](../../AGENTS.md) 和产品基线；未知焦点、输入法、目标身份或结果继续拒绝/隔离。不能为通过测试延长期限、反复重试、跳过失败或降低断言。
2. **代码、测试、文档一起收尾。** 修改行为时逐项判断相关旧测试：仍有效则保留，假设过时则更新，需求/接口真正退役才删除；修测试须说明保留了什么安全行为。失效接口、重复逻辑、无用文件和引用一起清理，遵循既有结构，不为整理重写全库。
3. **证据分层。** 每项写清“代码已实现 / 本地检查通过 / 当前提交 CI 通过 / 用户真机确认”。编译不等于 GUI，通过采集不等于质量合格；未运行不是通过。产品缺陷、测试问题、缺诊断、未支持功能和真机待验分别标记。
4. **失败后换取新证据。** 相同失败再次出现而没有新证据时，先写清假设、观察位置和下一判定条件，再运行；不盲目重跑，也不让一条线的问题停止无关工作。确需用户选择或授权时指出具体动作，其余独立工作继续。
5. **维护这个入口。** 集成负责人在实质结果或安排变化时更新基准、任务行和下一证据；问题关闭后删掉执行细节，将仍有用的限制放回平台说明。发布后核对候选提交、CI 和包一致，不新增阶段快照。README、平台说明和本页冲突时先按实际提交及证据校正，不能任选更乐观的结论。
