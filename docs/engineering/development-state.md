## 怎么安排，谁负责

职责不是实时活跃代理人数。Windows 按问题分派；Linux 维护现有功能；模型方向独立推进，集成者统一合并、验证和发布。

- **包内说明修正已验证**：CI458 包从同一份文档生成本包身份段，不再推荐旧包；包外相对文档链接固定到源码基准，四份离线文档保留。包字节、哈希与使用范围见 [Linux 使用说明](../platforms/linux/README.md)。

### 翻译质量：有界实验，不盲目扫配置

- **Argos**：已有 beam2/beam4 证据未解决保义问题；repetition penalty 1.05/1.0 单因素对照已准备，尚无新推理。当前启用中英双向，不等于整个生态语言包已接入。
- **Argos 安装合同**：CI457 两归档共 145,224,423 字节，全 ZIP 声明量共 171,778,261 字节。本批 archivePin 严格绑定归档 SHA、压缩和展开量；这是项目审核固定值，不是上游签名。Python/Linux 新装同盘推导预算为 2,531,595,196 字节，缺 pin 保留保守路径；旧库存与 runtime 依自身完整性和实际复制预算，不冒称被新 pin 认证。Windows 同步身份与写出限制，并计入归档、解包与暂存副本同时存在的峰值：无 pin 保守 5GiB，有 pin 取 3GiB 与归档量加两倍展开量的较大值，runtime/旧复制量另计。两端重复键、错层或损坏 pin 均拒绝；150 worker、103 setup、1212 Runtime 及联合编译通过，WPF 新安装回归未实际运行。隔离新装按同源码真实 App/worker 准备和激活，不造 current/Ready；真实安装前重核空间/内存。
- **Hy**：实际配置为官方 instruction+greedy、同 instruction+固定 seed sampling、greedy+保义 instruction。前两者固定四句开发子集未明显改善；第三种覆盖八条已见难例，独立复核为 1 条明确严重错误、3 条未决、4 条未见严重错误。承诺、主体及范围风险未闭合，本轮不采用。
- **证据缺失须明示**：旧完整八句 A 曾因 60s 截止中断，四句子集不能覆盖失败；环境重置后旧临时 A 原件丢失，派生对照不冒充原件。保义 B 八句的两份原件仍在持久目录。后续源码和不可再生证据只存持久工作区。
- **Qwen3-0.6B Q8_0**：官方非思考固定采样与原生 greedy 两套，各八条均真实 EOG 完成；仍有主体、数量、日期或承诺改变。greedy 仍有 6 条明显严重问题，不进行第三套盲扫。两套改变的是整个解码配方，不宣称单参数因果。
- **Qwen2.5-1.5B Q4_K_M**：官方普通 ChatML、相同八句和保义指令、原生 greedy。八条均以实际 EOG 151645 完成，总 50.073s，峰值地址空间约 1.205GiB；独立复核为 3 条严重错误、2 条明确改义/遗漏、3 条未见重大错误。周五改为周初、改票请求改成已改成功、周二改为下周五，不能替换 Hy。原生 EOG 集与官方 generation_config 有差异，但八条实际均使用共同终止 token，未据此虚构提前截断。
- **Qwen3-1.7B Q8_0**：已核官方固定 revision、1,834,426,016 字节及 SHA，模板非思考实际分支与八条输入逐字核对，原生 probe 不改；单套 greedy 八条均以实际 EOG 151645 完成，总 87.096s，峰地址空间约 1.949GiB，零重试、进程退出及身份保持已核。独立复核为 3 条严重错误、1 条明确改义、1 条未决、3 条未见重大错误。随后仅删通用长约束的短提示 B：前两句完成但分别仍严重/明确改义，第3句在60s边界终止且无 EOG，4–8未跑。不能归因提示导致超时，也不是完整八句 A/B；本轮两套均不采用。
- **新 Hy 精度假设**：官方同 revision Q6_K 为 1,474,785,120 字节；当前 Q4_K_M 为 1,133,080,448 字节。Q6 仍须核文件级完整 tokenizer/模板与原生加载预算，不能先声称唯一变化是量化；原 Q4 单句曾接近60s，Q6有真实时限风险。未下载或运行，不把估算当成功。
- **缓存与证据**：已关闭 Qwen 候选仅回收可按固定官方 revision/SHA 重新取得的权重缓存，所有原始输出、清理记录、manifest、模板和复核保留。历史完整性结果是当时的检查，不宣称已回收缓存仍存在。
- **统一限制与采用条件**：共同保持两核 CPU affinity、模型 worker 硬地址空间2.5GiB、单请求60s、总推理600s及有界清理，失败停止、0推理重试，生产身份不变。Hy/Qwen 使用 context1024、output192；Argos 沿原生产输入384 pieces拒绝界与512输出拒绝界，固定beam2，两臂只改repetition penalty。两核affinity不等于两个CT2线程，实际线程数须记录。保存模型身份、模板、参数、原响应、失败和退出证据；逐句复核否定、数量、主体、条件和承诺。八条是已见开发集，局部改善只支持继续验证，不直接改默认。
- **其余方向**：MADLAD 初始化已核超出现预算；M2M100 的 CT2 支持不代表转换峰值可控，现无已证明的预算内转换路径；TranslateGemma4B 暂缓资源与条款核查。未实测的候选不写成质量失败。协议见[测试方法](testing.md)，共同要求见[产品缺口](../product/README.md#当前共同开发缺口)。

## 每条线都要做的维护

1. **保持原行为与安全门。** 遵守 [AGENTS](../../AGENTS.md) 和产品基线；未知焦点、输入法、目标身份或结果继续拒绝/隔离。产品许可期限不放宽；外部准备与产品计时分开，不能靠重试、跳过失败或降低断言制造通过。
2. **代码、测试、文档一起收尾。** 修改行为时逐项判断旧测试：有效则保留，假设过时则更新，需求/接口真正退役才删除；修测试须说明保留的安全行为。失效接口、重复逻辑、无用文件和引用一起清理，不为整理重写全库。
3. **证据分层。** 区分代码实现、本地检查、当前提交 CI、用户真机。编译不等于 GUI，采集完成不等于质量合格；缺陷、测试问题、缺诊断、未支持功能和真机待验分别标记。
4. **失败后换取新证据。** 相同失败再现而无新证据时，先写清假设、观察位置和下一判据，不盲目重跑，不让一条线停止无关工作。确需新增权限或用户选择时指出具体动作，其余独立工作继续。
5. **维护唯一入口。** 实质结果或安排变化时更新本页；关闭后删掉执行细节，将有效限制放回平台说明。发布后核候选、CI和包一致，不新增阶段快照。文档冲突按实际提交及证据校正，不任选更乐观的结论。
