## 怎么安排，谁负责

常态为 **五个负责人 + 一名集成协调者**，保留机动位置供独立审查或经评估的模型接入。这里是职责，不是实时活跃代理人数；未运行的工作不得计作正在实验。

| 责任线 | 当前下一动作 | 交付证据 |
| --- | --- | --- |
| Linux 维护与安装 | 验证 Qt 探针修正，核对发行包；维护安装恢复，不做可选应用扩展 | 原有安全回归、实际桌面结果及包身份 |
| Windows 主开发 | 按下表修复已知测试问题，补足尚未确定根因的诊断 | 当前提交的真实桌面结果，不只编译 |
| Argos 调优 | 可移植性检查已完成；核实正式安装的磁盘准入预算，再安排真实采集 | 固定参数、输入、预算与原响应 |
| Hy 调优 | 定位本地普通 A/B 首句超时及同机资源争用，再决定下一轮 | 安装身份、真实响应、退出清理与逐句复核 |
| 替代模型研究 | 完成最多三个候选的来源、资源及接入可行性比较 | 采用或暂缓理由，不以宣传分数代替质量 |
| 集成协调 | 顺序审查、合并、验证、发布和跟踪 CI；维护本页 | 候选、检查、下载包身份一致，失败有下一动作 |

研究、代码、审查可并行；**同机重模型推理串行**，由协调者分配 CPU、内存、缓存与预算。独立未完成任务不拖住已收敛修复；远端执行受限时推进已授权的本地路径，不把所有工作停在一次远端调用上。

```text
Linux 探针修正 ──────┐
Windows 修复与诊断 ──┴→ 集成审查与联合检查 → 发布候选 → 双端 CI → 核对包 → 体验
                                                         └→ 依新证据修复
Argos 参数对照 ──┐
Hy 普通翻译对照 ─┴→ 分配资源 → 真实采集 → 逐句复核 → 决定采用或下一轮
候选模型研究 ──────→ 资源与接口评估 → 有限接入验证
```

### 翻译质量：有界实验，不盲目扫配置

负责人：Argos、Hy、候选模型研究各一人；协调者分配实际资源。

- **实际尝试基线**：Argos 已核实 beam2/beam4 普通与另述对照，beam4 未解决保义问题；Hy 已有自然/正式对照；本轮普通翻译固定四句开发子集也实际完成 greedy 与 seed 20261020 sampling 两配置。请求次数不是配置方案数，不能声称穷尽尝试。
- **Argos**：repetition penalty 1.05/1.0 单因素普通对照的 Windows 可移植性修正 `08b22f8` 已完成并集成，共享 146 项及 Linux 真实受控进程 1 项通过；没有真实模型输出。保持现行默认作基线，不同时改变模型、分句或保护逻辑。项目当前启用中英双向，生态其他语言包不等于项目已支持。
- **Hy**：本地正式安装器产生的未激活 generation 已完成四句普通翻译解码对照。三句逐字相同，一句仅增“方案”，独立复核未解决原有承诺偏移等问题，保留生产 greedy 默认并收束该固定 seed 方向。原八句矩阵仍因生产 60 秒期限未完成，失败不被子集结果覆盖；四句按可完成性选择，是已见开发集，不是留出或整体质量验收。
- **Hy 下一实验**：固定 greedy、模型和聊天模板，仅改变 ordinary 的通用保义 instruction；复用已锁定的四句 A 原始结果，避免无变化基线反复推理，不作非同期速度比较。新 B 四次请求，构建与采集同属 600 秒总预算，生产单请求 60 秒不变；任意失败即停，保持输入/派生源码/实际 native 身份可核验。准备完成但尚未运行，协调者在联合编译结束后分配独占推理窗口。
- **替代模型**：MADLAD-400 Q4K 的已核初始化内存超过当前 2.5 GiB 预算，暂不下载，不记作质量失败；M2M100-418M 已核现有 CT2 可支持，但转换峰值与原权重/输出所需磁盘当前不足，保留多语言候选，TranslateGemma-4B 暂缓资源与条款核查。均无实跑优于当前模型的证据，不因找到候选就扩张生产目录。
- **验收**：保存模型/配置身份、原响应、失败与退出证据，逐句检查否定、数量、主体、条件和承诺程度，记录改善与退化。harness 通过或采集完成不等于质量合格，不以应用层保护处理替代语义验收。

质量门见[产品共同缺口](../product/README.md#当前共同开发缺口)，执行方法见[测试协议](testing.md)。本页不复制实验历史。

## 每条线都要做的维护

1. **保持原行为与安全门。** 遵守 [AGENTS](../../AGENTS.md) 和产品基线；未知焦点、输入法、目标身份或结果继续拒绝/隔离。不能为通过测试延长期限、反复重试、跳过失败或降低断言。
2. **代码、测试、文档一起收尾。** 修改行为时逐项判断相关旧测试：仍有效则保留，假设过时则更新，需求/接口真正退役才删除；修测试须说明保留了什么安全行为。失效接口、重复逻辑、无用文件和引用一起清理，遵循既有结构，不为整理重写全库。
3. **证据分层。** 每项写清“代码已实现 / 本地检查通过 / 当前提交 CI 通过 / 用户真机确认”。编译不等于 GUI，通过采集不等于质量合格；未运行不是通过。产品缺陷、测试问题、缺诊断、未支持功能和真机待验分别标记。
4. **失败后换取新证据。** 相同失败再次出现而没有新证据时，先写清假设、观察位置和下一判定条件，再运行；不盲目重跑，也不让一条线的问题停止无关工作。确需用户选择或授权时指出具体动作，其余独立工作继续。
5. **维护这个入口。** 集成负责人在实质结果或安排变化时更新基准、任务行和下一证据；问题关闭后删掉执行细节，将仍有用的限制放回平台说明。发布后核对候选提交、CI 和包一致，不新增阶段快照。README、平台说明和本页冲突时先按实际提交及证据校正，不能任选更乐观的结论。
