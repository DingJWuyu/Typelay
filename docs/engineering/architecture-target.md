# 保持产品行为的架构改进目标

本页定义目标架构，尚未实施。代码基线为 `work/linux-usability` 的 `48baf7fe59a65a67a7a981470e259f01fdc7b4a4`。当前实现仍以 [architecture.md](architecture.md) 和生产代码为准，独立评估及本轮完成状态见[架构评估](architecture-assessment.md)。

用户授权主代理与每轮全新上下文 advisor 自主选择、质询和修订方案，只由 advisor 按[固定 rubric](architecture-rubric.md)评分。本阶段完成后等待下一步，不开始代码重构。目标是让产品动作对应的知识集中在少量清楚的 module 中，使 interface 隐藏复杂性，增加 locality 与真实跨平台 leverage。

## 产品依据保持不变

共同依据为[冻结规格](../product/TypeLay_产品规格_v1.0.md)、[已接受增量入口](../product/README.md)、[应用支持增量](../product/application-support.md)、[浮层原型](../design/TypeLay_UIUX_Prototype.html)、[设置与托盘原型](../design/TypeLay_Tray_Settings_Prototype.html)及[设计系统](../design/system/README.md)。有效 ADR 为 [工作区与分发](../adr/0001-workspace-and-delivery.md)、[按需与直接替换](../adr/0002-on-demand-and-direct-write.md)、[共享运行时](../adr/0003-cross-platform-runtime.md)和 [Linux 原生锚点](../platforms/linux/adr/0004-native-anchors.md)。

| 产品行为 | 基线位置 | 重构中保持的语义 |
| --- | --- | --- |
| 在原输入框内工作 | 规格 §2、§4、§6、§23 | 原输入方式、浮层锚点、滚动/多显示器行为和不抢焦点要求保持；现有合作输入限制不是产品范围 |
| 自动与按需 | ADR-0002、产品 README | 自动跟随；按需由明确快捷键开启原字段的持续体验；离开焦点家族按原规则结束 |
| 一次性直接替换 | ADR-0002 | 选区优先，否则当前原框；绑定触发源，可跨焦点变化完成；不预览、不抢焦点、不发送 |
| 文本、选区和实时更新 | 规格 §8、§9、§16 | 结构、选区外文本及 IME 要求保持；旧预览可显示，但不能凭旧结果取得新接受资格 |
| 人工草稿与回源 | 规格 §14、§15、原型 | 模型不能覆盖人工稿；第一次 Tab 回源，下一次 Tab 接受；原文追加与既有内容变化保留各自规则 |
| 接受与 Undo | 规格 §17、§18 | 原目标、按次、输入法、版本和时效重新确认；源端已经执行的回执不触发第二次写入 |
| 暂停、排除和退出 | 规格 §5、§22、§29 | 敏感字段先于正文读取拒绝；暂停和退出撤销新操作，已派发写入仍须结算 |
| 语言、风格、术语与重译 | 规格 §11、§12、§19、§20 | 保留设置、来源范围与人工稿关系；高级能力未交付项继续作为需求，现有质量门不因重构开放 |
| 本地模型与隐私 | 规格 §10、§13、§21、产品增量 | 本地推理、结构保护、无默认历史；模型安装需明确选择；Index 默认及旧 Argos/Hy 库存按已接受规则保持 |
| 设置、托盘和外观 | 规格 §24 至 §27、设置原型 | 即时设置与需整体提交的草稿各自保留；焦点、文案、尺寸、主题、动效和可访问操作以原型为准 |
| 应用支持 | 应用支持增量 | 双端共享状态与动作语义；模型可用、接入连接与当前字段能力分别报告 |
| 首次使用与练习 | 规格 §28、原型 | 模型准备、真实用户动作和练习完成分开；重新开始、取消、保存进度和撤权条件保持 |

本目标覆盖结构改进，既有 B-01/B-02/B-03、模型质量和真实输入验收缺口继续在现役平台文档中记录。保持安全拒绝不能替代恢复已承诺的合法用户路径，重构也不能将未完成需求改成可选功能。

## 探索依据

最近 50 次提交的热点集中在设置视图、原生浮层、共享控制器和 Linux 宿主。该事实用于选择阅读范围，不代表用户故障发生率。静态探索发现以下四处摩擦，日常发生频率未知：

| 候选 | 直接证据 | 预期收益与代价 |
| --- | --- | --- |
| 编辑返回和重译的生命周期 | `SessionController.ReturnFromEditor/Capture/StopSession` 与 `ISessionView`、`InputContext` 同时理解专用交接 | 集中一次操作的知识；迁移必须保人工稿、原生证据及迟到结果处理 |
| Linux 源字段状态所有权 | `Overlay.current_record/render/return_glossary_to_source` 访问或修改 Input 的内部字典 | 统一操作记录的构造、验证与退休；保留不同信任位置的必要复核 |
| 交互身份与显示内容 | Overlay、GTK/Qt、浏览器通过完整视图和中文提示比较决定保留交互 | 文案与菜单刷新不再驱动授权推断；跨语言协议迁移须配套处理 |
| 设置提交的结果 | `SettingsWindow.SaveAsync` 推断提交点，Linux Program 重复保存编排 | 一处解释持久化结果和副作用，减少视图协调；需保持所有现役设置入口 |

`Core`、`ModelClient`、`ModelLoadPlan`、平台原生写入与模型库存切换已经隐藏了实际复杂性。删除这些 module 会把知识摊回多个消费者，因此默认保留。对其它候选也按 deletion test 判断，文件拆分本身不计为改善。

## 设计树

探索与 advisor 质询选择了四个深化目标。先确定编辑与重译寿命，再确定呈现身份和 Linux 源字段所有权；设置提交可以独立迁移。以下各项决定共同构成后续实施目标，评分不进入这些定义。

| 决定 | 选择与理由 | 保留的差异 |
| --- | --- | --- |
| 会话与直接任务 | 延续一个前台译文会话及一个独立的直接任务所有者，不建立通用工作流引擎 | 切换焦点结束前台体验，但不能仅因此取消已绑定原字段的直接任务 |
| 操作生命周期 | 将编辑回源、重译确认、术语及配置交接集中到 Runtime 内的具体操作对象 | 不把原生证据抽成一个无语义的成功布尔值 |
| 输入接入 | 保留异步输入与同步按键两个 interface；Linux 内由源字段 module 独占平台交互记录 | Windows、GTK、Qt、浏览器各自解释身份、IME、锚点和按键 |
| 呈现 | 共享产品投影和交互身份，renderer 管理原生控件、焦点与视觉 | Linux 原生父窗口浮层及浏览器页面浮层保留；本轮不重新选 UI 框架 |
| 设置 | 共享一次提交的协调与结果，视图不推断提交点 | 平台登录启动与应用标识仍由实际 adapter 处理 |
| 教程 | 教程进度观察用户完成的事实，自有源权限留在输入 adapter | 练习完成仍等待原源撤权确认，进度不能代替权限 |
| 模型与进程 | 保留现有 ModelClient、加载计划、库存和平台进程管理 | 不因目录统一重写原生模型、下载或退出机制 |

## 目标整体结构

```text
用户在原输入框输入、预览、编辑、接受
                      |
        Windows / Linux / 源应用内 renderer
                      |
           共享呈现 module 与用户意图
                      |
     译文会话 module          设置提交 module
     Core 产品状态              SettingsStore
     Runtime 操作寿命           既有副作用 adapter
        |          |
   源字段 adapter  本地翻译 module
   原生事实与执行  现有 ModelClient + worker
        |
 原应用、原控件、原输入法

直接翻译任务拥有独立寿命，复用输入与模型 interface。
教程进度观察已确认结果，自有练习源仍走真实输入 adapter。
```

这些 module 是责任划分，不要求每个建立一个项目或常驻进程。沿用 Core、Runtime、Protocol 和双方宿主，保持现有依赖方向；不引入事件总线、依赖注入容器、插件框架或持久工作流。

## 每项事实只有一个权威所有者

| module | 拥有的事实与 implementation | interface 的调用者得到什么 | 不承担的事实 |
| --- | --- | --- | --- |
| 译文会话的 Core | 原源快照、候选、人工草稿、产品会话状态及纯判定；同一 Runtime 实例持有一份 Session | 观察、编辑、生成计划及完成回执后的产品状态 | 平台焦点的真实性、进程连接、UI 控件 |
| 译文会话的 Runtime | 当前异步请求、具体交互操作、结果代次和副作用安排 | 宿主提交已验证意图、观察或回执，取得只读呈现及待执行动作 | 不再复制 Core 的正文/草稿权威，也不直接解释 HWND 或 native peer |
| 直接翻译任务 | 触发时的原字段、选区、配置和任务阶段 | 一次命令的进度与最终反馈 | 不借用当前前台会话的目标和寿命 |
| 源字段 adapter | 原生身份、连接寿命、焦点/IME 证据、原生按次与执行记录 | 当次观察、有明确语义的回源结果、能力和写入回执 | 不推断风格、术语和教程的产品规则 |
| 共享呈现 module | 从既有产品状态生成文案、菜单、动作可用性与显示投影 | renderer 获得完整呈现值；意图携带实际展示的身份返回 | 不持有新授权，不根据文案判断交互有效性 |
| 设置提交 module | 草稿基线、准备/提交阶段、原子文件保存结果与通知结果 | 所有保存入口取得明确结果及实际配置 | 不操作原生窗口或决定平台注册表/XDG 细节 |
| 教程进度 module | 当前练习步骤和已确认里程碑 | 教程展示进度、发起已有练习动作 | 不拥有接受许可、原文或写入资格 |
| 本地翻译 module | 保留 ModelClient 的连接、请求、冻结加载计划和模型发布结果 | 译文、明确失败和实际能力 | 不拥有源字段焦点、按键或写入权限 |

源端需要保留执行所需快照和许可副本，这是原生操作的独立证明，不构成第二份产品会话真相。renderer 的本地编辑控件负责即时输入；共享人工草稿通过带版本的真实编辑通知更新，旧回显不能覆盖控件中的新稿。

## interface 隐藏什么

以下定义职责和结果语义，具体类型名在实施时沿用现有领域命名。每条 seam 都有现役生产消费者，不新增仅供测试使用的 interface。

| seam | 调用者提交与取得的内容 | module 内部吸收的复杂性 |
| --- | --- | --- |
| 宿主与译文会话 | 提交真实观察、固定种类的用户意图及原请求结果，取得不可变呈现 | 具体操作的开始、异步等待、回源重验、退休和迟到结果分派；没有字符串命令加任意字典的通用调度入口 |
| 会话与异步输入 | 沿现有 Capture、Return、Write 等操作，结果明确关联原请求 | 平台原始句柄、连接、文档和焦点证据；回源确认、明确未派发、已知拒绝、失权和未知不能压成同一 false |
| 会话与即时输入 | 读取当次观察、消费真实命令通知、发布或撤销短期许可 | 按次归属和源线程同步执行；即时路径不等待模型或远程调用 |
| 呈现与 renderer | 接收显示值、显示序号和本次交互关联；返回实际事件及当时显示的身份 | 产品文案、菜单与动作资格集中投影；控件编辑、IME、几何和原生事件真实性仍由 renderer/adapter 提供 |
| 所有保存入口与设置 | 提交变更、期望版本、既有确认和取消状态，取得实际提交版本及分类结果 | 等待退休、重验、持久化、通知和副作用事实；窗口失效只影响展示和未提交意图 |
| 教程与会话/输入 | 发起已有练习动作，消费带原 run/计划身份的已确认里程碑 | 教程只拥有进度；自有源 adapter 独占真实绑定及退休确认，Core 独占草稿与源文基准 |

调用者可以知道某次操作被拒绝的原因，但不需要知道操作对象内部目前走到哪个回调。`InputContext` 的教程和编辑重译可选字段，在相应消费者迁完后由具体操作的请求关联替代；不能先删除这些证据再让旧 adapter 猜测。

## 选中的四个深化目标

### 1. 译文会话 module 管理具体交互的寿命

保留 Core.Session 的纯产品状态，Runtime 管理等待异步结果的操作阶段。把当前 `_sourceReturn`、浏览器重译、源端重译、术语交接和自有练习回源的散落字段收进对应的具体操作对象。操作对象拥有本次身份、原目标、原期限、回执匹配与退休逻辑。

同一视图/草稿的控制性操作遵循现有互斥规则；模型请求、直接任务和已派发写入有各自寿命，不能为了一个枚举而串行化全部工作。具体操作通过已有串行事件循环与 Core 协作，异步继续体不直接修改其它操作的私有状态。

`SessionController` 最终只负责接收事件、选择当前操作、调用 Core、调度既有输入/模型 interface 和发布结果。开始、回源回执、fresh capture、取消及停止由该操作解释，主 Capture/Stop 路径不再枚举每个教程或浏览器细节。`ISessionView` 留下显示、编辑及用户意图；源窗口证明和回源有效性转给源字段 adapter 的具体操作结果。

deletion test：删除会话协调会使状态时序摊回全部宿主，因此保留；删除散落的专用字段后，复杂性集中到相应操作，而不转移到调用者。depth 的证据是修正一个回源分支只需修改该操作及其真实 adapter；其它交互只依赖稳定结果。

### 2. Linux 源字段 module 独占平台交互记录

在现有 Linux desktop 内深化 Input，集中拥有 peer、绑定观察、原生操作、返回关联和撤权记录。Overlay 取得不可变的当前呈现记录，提交明确的显示/编辑意图；不再访问 `peers`、`bound_observation` 或创建 `editor_regenerate`、`source_glossary_return` 字典。

异步输入 interface 与同步按键 interface 保留不同职责。源端同步接受在真实事件线程消费原按次并执行原计划，Runtime 仅结算其回执；异步写回由 Runtime 发起后等待回执。Linux 可以在一个实际 module 中实现两个 interface，不能用一条异步 RPC 代替同步按键所有权。

GTK3/4 共用的纯协议解码和交互身份比较移入已有 native/common，真实控件和 IME 生命周期留在各自 adapter。Qt 和浏览器保留其语言及事件线程；共同语义通过共享投影、明确协议及少量合同场景保持，不建立跨语言代码生成框架。

locality 的目标是观察身份或断连规则的宿主侧修改留在 Input；Overlay 只处理显示。跨进程接收者的最终身份、焦点、版本和 IME 检查保持，每次必要复核仍由能观察该事实的 adapter 执行。

### 3. 呈现 module 区分显示刷新与交互身份

扩展现有 Presentation 类，集中构造完整显示投影。当前 SessionViewToken 继续表示产品会话/命令上下文；增加明确的交互关联和显示刷新序号，替换通过 JSON 整体相等、文案或菜单提示推断有效性的做法。

显示刷新序号仅用于丢弃乱序画面。交互关联表示一次已受理的编辑、术语、配置或重译操作，绑定原目标、原上下文及实际操作身份。共享 module 决定产品层面的继续或退休，原生 adapter 可以立即因真实失活而退休；宿主后续回显不能复活已退休的本地操作。

菜单可用性、状态文案或颜色变化只更新显示；原文、设置或相关草稿版本变化按该操作的现有规则处理。真实草稿变化即使改回原值，也通过单调版本识别；旧稿回显不能伪装成未编辑。明确的撤权可以保留必要的只读交互展示，但不会保留旧许可。

每个 renderer 仍核对真实控件、连接、字段、IME、按次和自己的原期限。交互关联不授予读取、编辑、按键消费或写入权限，也不能续租。严格 schema 拒绝未知行为字段，显示字段与行为字段分开编码。协议采用配套 host/adapter 升级，旧连接按既有重连/重启方式退休，不能将未知版本降级解释成已支持。

| 变化 | 显示与交互的处理 |
| --- | --- |
| 文案、颜色、菜单反馈更新 | 更新显示序号，不据此更换操作身份，不续租 |
| 当前稿的精确回显 | 真实编辑版本不变时只同步显示；不覆盖 renderer 中更新的稿 |
| 实际再编辑，包含改回原文的 ABA | 推进稿件版本；废弃依赖旧稿的 Replace 意图，保留当前合法人工稿 |
| 本次表单导致动作资格单向撤销 | 撤销相应动作；原来允许继续的表单仍可显示，旧许可不保留 |
| 源文、配置、模型或窗口事实变化 | 由对应操作按原产品规则退休或继续；仅显示刷新不可以冒充这类变化 |
| 旧连接、旧视图或旧动作的晚到消息 | 原所有者已退休时拒绝；匹配已派发写入的回执仍交原结算者处理 |

每条连接协商一种已知协议语义。开发迁移时，可让尚未迁移的真实消费者继续走其原有完整路径；不能让同一交互同时受新旧两套身份判断支配。新路径逐消费者通过后删除相应旧比较；配套发行不能把旧 schema 猜成新能力。需要重启的应用或扩展沿已有应用支持入口说明，不增加另一套用户配置流程。

leverage 的目标是修改菜单文案、添加状态反馈或修复显示回显，只修改共享呈现和实际需要改变布局的 renderer，不再同步修改多份字符串身份判断。

### 4. 设置 module 提供完整提交结果

保留 SettingsStore 的默认值、升级、深快照比较和原子文件替换，在 Runtime 内集中保存编排。设置页、托盘、首次设置、语言设置与高级设置调用同一提交入口；视图只负责本次草稿、确认选择和窗口仍有效的事实。

提交输入绑定期望的设置版本、具体变更与显式确认范围。先做既有规范化和校验，必要时等待会话/自有源退休；等待完成后重核版本和取消，再在原串行循环内进入同步提交点。外观、风格、术语与一般设置继续使用各自已定义的影响范围，不能改成所有保存都清空会话。

结果明确区分未提交、无变化但文件保存成功、已提交、已提交但通知失败，以及外部副作用结果未知。结果携带实际提交版本和已知副作用事实。调用者无需通过 Revision 差值和异常类型猜测提交点；已提交结果不能被关闭窗口或晚到取消改写成未提交。

登录启动仍沿现有副作用顺序迁移，文件和系统设置不被宣称为一个原子事务。文件保存失败而登录启动已改变时，结果同时记录两件事实；原设置反馈入口显示实际持久化值和需要核对的系统状态，不自动重复执行副作用。保存失败后的草稿、关闭确认和原生焦点恢复按现有原型保持。

| 提交场景 | 唯一结果与现有 UI 的处理 |
| --- | --- |
| 等待源退休时取消或基线版本变化 | 未提交；不执行后续副作用或文件写入，合法草稿按原规则保留 |
| 登录启动已成功，随后文件保存失败 | 文件未提交、内存仍为旧持久值、系统副作用已发生；通过现有失败/详情入口如实显示，不自动补偿或重试 |
| 登录启动调用抛错且平台不能证明是否生效 | 文件不进入提交；外部结果未知，当前原入口要求核对实际状态，不能归为确定未改变 |
| 文件替换成功，通知观察者失败 | 已提交并返回真实版本；提示通知问题，既不再次写文件，也不把旧草稿覆盖回去 |
| 规范化后与持久值相同 | 仍执行原文件保存并报告其失败；成功不触发无意义的会话重配或系统副作用 |

文件替换成功是持久化提交点。该点之后的取消只影响通知/界面，不改变提交事实。副作用的重试只能来自新的明确用户动作，并重新读取当前基线；不新增失败后自动恢复流程。

locality 的证据是修正提交结果或新增一种设置影响，只改变共享提交 module 及实际平台副作用 adapter；两个宿主的 UI 不再重复存储事务判断。

## 必须通过的交互走查

| 场景 | 负责者与关键顺序 | 保持的用户结果 |
| --- | --- | --- |
| 自动预览更新 | adapter 先核字段元数据再取快照；Runtime 固定请求；Core 接受当前结果；呈现 module 更新投影 | 新原文不被旧请求覆盖，旧预览继续按原状态显示但不可接受 |
| 编辑后两次 Tab | Core 保留人工稿；回源操作撤销旧许可；adapter 返回真实回源结果；Runtime 新捕获；Core 校验后才重新提供接受资格 | 第一次只回源，下一次接受；鼠标回源遵循同一语义 |
| 浏览器重译确认期间继续编辑 | renderer 的真实编辑通知推进稿件版本；旧 Replace 意图退休；回源回执仍按原操作收束 | 后来人工稿保留，旧确认不丢弃新稿，不重发旧动作 |
| 术语表单导致菜单或提示变化 | 共享交互关联保持本次表单，显示序号更新；原生目标和期限仍逐次核对 | 文案变化不误关表单；真实源变化仍立即使旧操作失效 |
| 直接任务期间切换应用 | 直接任务保存原字段和快照；新前台会话独立变化；写前由原 adapter 重验 | 结果只尝试写回原框，不抢焦点、不修改新框、不发送 |
| 源端同步接受后迟到回执 | 原生线程已经执行；Runtime 用原计划身份结算，不调用第二次 Write | 切换视图不复活旧候选，终态结果不因新会话而丢弃 |
| 暂停、设置变化或断连发生在写入后 | 撤销新许可；保留已派发写入的有限结算事实；未知结果隔离原目标 | 不把取消当成撤回，不自动重试；旧回执不更新新视图 |
| 教程完成或重新开始 | 教程进度消费已确认里程碑；自有源 adapter 撤权并确认；确认后记录完成或允许下一练习 | 原文不因重启练习被清空，未撤权时不显示完成 |
| 保存设置后观察者失败 | 设置 module 先记录实际提交事实，再通知；失败返回已提交及通知问题 | 草稿与反馈不伪装成从未保存，用户不会因错误重试重复副作用 |
| 模型切换、准备失败与退出 | 既有安装所有者持锁；ModelClient 核真实候选与退出；平台证明进程族释放 | 保留可用旧库存，未知发布不当作成功，不删除仍被使用的模型 |

Runtime 的已派发写入记录在当前进程内有界保存，不建立持久操作日志。每条记录绑定原目标、计划、执行路径和代次；同步源回执与异步返回只能使同一操作终结一次。终态先结算，再决定当前会话是否可呈现；未知结果的隔离按原目标寿命保留，不能随视图退休而消失。关闭时先撤新许可与显示，再按既有原生回执/Quiet/进程退出机制释放，无法证明退出时保留未知结果，不自动重放。

具体结算责任留在 Runtime 的写入操作记录内，Core 的 Applying/候选状态是产品状态投影，不是另一份终态权威。adapter 独立证明真实执行结果，Runtime 校验结果与原计划一致后记录唯一终态；Core 只对仍匹配的当前会话应用该终态，原目标隔离即使会话已退休也须保持。

| 阶段 | 源端同步接受 | Runtime 发起的异步写回 |
| --- | --- | --- |
| 建立关联 | 在发布原计划和许可之前登记原目标、计划和执行者关联；登记不授予权限 | 在实际派发之前登记原目标、计划和执行者关联 |
| 可以发生写入后 | 发布后可能已被源线程认领，撤权不意味着未执行 | 调用进入提交路径后，超时、异常和取消都不能推断没有写入 |
| 终态到达 | CompletedReceipt 只结束该记录，不再调用 Write | 原 WriteAsync/WriteDirectAsync 的匹配回执结束该记录 |
| 退休或重复回执 | 旧视图退休不丢记录；已记录终态不被重复回执再次应用 | 同左；新会话不能认领旧结果 |
| 释放 | 终态或确切的未执行证明与原执行者 Quiet/寿命结束按现有机制配合；Quiet 单独不是成功回执 | 保留原调用实际退出/完成的证明；未知结果不能触发重试或改写新目标 |

记录沿现有在途操作上限和退休机制有界保存，不增加命令队列。退出依次撤销新许可、停止发新操作、结算或标记尚未确认的原操作、等待/交还平台既有退出机制，再释放本机资源。进程崩溃后的回执恢复不是本目标新增的能力，不能为了记录而持久化正文。

具体操作对象在调用 Render 或开始 await 前先登记自身身份，避免真实 UI 回调重入后旧操作仍继续派发。操作退休后只能处理自己已发出的结果，不能清理后来接替的操作。普通 Tab/鼠标回源、自有源 Keep、Replace 分别保留原有成功和可恢复拒绝分支；原动作期限不延长，也不施加给整段人工编辑寿命。

### 回源操作如何交还结果

这些是 Runtime 内部的具体操作合同，不建立统一工作流基类，也不把内部阶段暴露给宿主。共享结果区分可继续编辑、已确认回源等待新观察、完成产品确认、明确失权和结果未知；实际证据仍由对应 adapter 解释，不能由一个 bool 推断。

| 路径与当前入口 | 开始与等待的事实 | 完成后交给 Core 的动作 | 拒绝、失权与晚到结果 |
| --- | --- | --- | --- |
| 普通 Tab：`ReturnFromEditor` | 当前人工稿仍合法；先登记操作、撤许可，再 `RequestSourceReturn`，通过原 `ReturnToSourceAsync` 请求回源；匹配确认后重新 Capture | 新快照交 `ConfirmSourceReturn`；只有仍匹配原编辑基准才进入待接受，第一次 Tab 不写入 | adapter 明确没有完成返回且原编辑器仍合法时，`CancelSourceReturn` 并继续原编辑；源变更按既有 Core 规则失效/重译，失权或未知不得凭旧稿恢复资格 |
| 普通鼠标：`Capture` / `Session.Observe` | 实际观察到原字段重新获得焦点，取得新的合法快照；不制造虚构 Return 请求，也不强加按键动作期限 | 沿现有 `Observe` 调用 `ConfirmSourceReturn`，与 Tab 路径得到相同产品结果 | 旧捕获不能确认新会话；源文已变时沿 Core 现有失效/重译规则处理，不把合法鼠标回源统一拒绝 |
| browser Replace：`RegenerateEditorAsync` / `CompleteEditorRegenerateCapture` | 真实 Replace 事件冻结原操作期限和稿件版本；旧丢稿意图与实际回源操作分别记账；等待匹配回源 ACK，再 fresh capture | 未再编辑且原动作仍有效时由本操作调用 `Retranslate`；后来有真实编辑时走当前人工稿的普通回源规则 | 明确未派发/已知拒绝且编辑器仍合法，可继续编辑；失权或未知退休。后来稿使旧 Replace 永久失效，但原回源结果仍由原操作收束 |
| owned Keep：`PrepareOwnedLocalReturn` / `ObserveOwnedLocalDraftReturn` | 保持旧 reader 已撤权的确认；真实 Tab 返回原字段并取得精确回源回执；新的合法源捕获须匹配 DormantEdit 基准 | `ConfirmDormantSourceReturn` 恢复人工稿候选；新 binding 经既有重入校验及真实 reader 安装完成后，才可重新提供接受资格 | 未受理且原本地编辑仍合法的失败保留原稿；已消费基准后校验失败沿既有退休，不恢复旧绑定、不回退到普通源猜测 |
| owned Replace：`PrepareOwnedLocalRegenerate` / `CompleteOwnedLocalRegenerate` | 原真实事件创建一次性丢稿意图；先完成旧 reader 撤权、精确回源、新源捕获和 `ConfirmDormantRegenerateReturn`，再确认新 binding/reader 真正安装 | 安装后的再次 fresh capture 经 `ObserveOwnedLocalRegenerateCapture` 核验，才对完整当前源调用 `Retranslate` | 本地稿不变成接受候选；仅绑定成功不启动读取/模型；旧安装回调不得作用于新 opening，失败不重放 Replace |

browser 的 ACK 前晚到草稿按一条固定顺序处理：真实编辑推进稿件版本，旧 Replace 丢稿意图失效；本次回源仍在途中时，只暂存同一编辑器的新稿。精确 ACK 到达后，在同一串行调用中用 Core 的取消回源、更新稿件、重新请求回源操作应用新稿，不在中间发布许可或模型任务。随后新的源捕获按普通人工稿规则确认。ABA 也属于真实再编辑，不能凭文字相等重启旧 Replace。

### 正常关闭先交还责任，再释放接收者

在现有 SessionController 上提供一个明确的异步关闭入口，负责停止新操作、撤许可、消费已经登记操作的回执并返回有界结算摘要。它属于会话 module，不新增全局账本、退出守护进程或统一 Quiet interface。现有 Dispose 保留幂等的最终资源释放与异常兜底职责。

1. 宿主先完成原有退出确认、未保存草稿处理和练习退出条件。用户取消退出时不启动此关闭入口。
2. Runtime 关闭新操作准入并撤许可，停止新的 Capture、模型请求与写回派发；保留原串行事件循环、已派发继续体和 `IInputMonitor.TryRead` 回执消费。停用新操作不等于清空 notice。
3. 原写入记录接收精确终态；在平台原有期限和退出预算内仍不能确认的操作记为 OutcomeUnknown，原目标保持隔离。不延长按键或原生许可，不等待外部用户应用无限退出。
4. Runtime 返回已结算/未知的摘要后，宿主才执行当前输入 Dispose、连接关闭、模型/自有子进程释放和事件循环退出。摘要不包含正文，也不表示远端未知写入已被撤回。

| 实际路径 | 提供事实的现有执行者 | 关闭交还与释放位置 |
| --- | --- | --- |
| Windows 原生源同步接受 | Hook/Broker 的原计划回执及源绑定；具体 source-message 路径提供精确 grant Quiet/进程句柄信号 | `Program.Quit` 在 WPF Dispatcher 仍运行时等待会话关闭入口，再 `app.Shutdown`；`SessionController.Dispose` 不先停掉仍负责结算的循环。Quiet 只用于该原生路径的资源退休，不能替代 Verified |
| Windows 异步写回或直接任务 | 原 `WriteAsync`/`WriteDirectAsync` 调用与 Broker 的原执行记录 | 原继续体向关闭中的结算者交结果；停止或杀掉 Broker 不能证明外部源字段没有写入；按现有原生资源所有权处理未确认部分 |
| 浏览器与 GTK/Qt 合作源 | 原 peer/document/target 对应的 CompletedReceipt、已有撤权确认与连接寿命 | 没有通用 Quiet 就不虚构它。明确终态照常结算，断连仅证明连接结束，缺终态仍为未知；源端继续执行已有撤权、租约失效和父窗口退休规则 |
| Linux 原 direct 调用 | Python Input 中的原调用及 DesktopInput 返回的 WriteReceipt | 原异步调用结果交还前不取消它的任务、不清空 `issued`；超期或断连按未知收束，不重发 direct |
| Linux 宿主正常退出 | Python desktop、DesktopLink、.NET EventLoop 仍在运行的原通道 | 把关闭请求/完成答复放在现有私有通道上；`main.py` 进入清理 finally 前先完成这次交还，随后才 `Input.close`、`DesktopInput.Dispose`、`loop.Quit` 与进程清理；沿现有预算，不另设长时间等待 |
| 异常、通道已断或事件循环不可继续 | 原宿主 finally/Dispose 和原生执行者现有保护 | 不尝试恢复交互；把仍有执行可能的本机记录作为未知处理并撤新许可，平台继续原有安全释放。崩溃后不保证还能收到回执，也不建立自动恢复写入 |

完整计划仅在执行及校验结果所需期间持有，确定终态或转为未知后释放共享侧正文引用。需要等待原生 Quiet/退出才能安全释放的原生缓冲仍由其原所有者管理，不能提前擦除后假装没有在途操作。去重所需的计划/执行者/终态元数据保留到原连接及操作寿命结束；未知隔离保留原目标寿命的无正文事实，沿当前进程的既有隔离策略清理。使用现有在途数量、通知容量和超期机制，既不增加积压命令队列，也不把日志当成权威状态。

## 教程、模型与 UI 技术栈的范围

教程进度移出普通会话状态，保留一个具体的练习协调 module。它发起现有开始、重启、结束动作并观察已核实的结果；真正自有源的安装、捕获、连续性、回源和撤权证明继续由专用 input adapter 管理。移除公共上下文中的教程流程分支须先迁移这组真实证明，不能直接删字段或将自有源当作普通源。

自有源本地草稿继续使用 Core 的 DormantEdit 保存原编辑基准；既有 TextBox 的文字、选区和 Undo 留在本地控件。Keep 在精确回源和新捕获通过后恢复人工稿候选，Replace 消费丢弃意图后才重新翻译，两者均不凭教程进度获得许可。完成保存失败只保留当前 run 的无正文完成事实；关闭、重新开始或真实配置变化清除该事实，旧 run 的回执不能完成新练习。

ModelClient、ModelLoadPlan、Protocol、Python worker、库存锁和原生后端在本轮默认保留。平台宿主继续拥有原生进程、连接和安装路径。模型更换不改变会话和输入 interface；只有发现具体泄漏时才深化相应 module。

现有 WPF、GTK、原生 GTK/Qt 和浏览器 renderer 作为迁移消费者保留。本目标先统一产品语义和呈现 interface，具体 UI 工具包不决定 module 的 depth。此前的 GPUI 选择不被本方案改成另一项选型；任何后续 renderer 替换仍需满足原型和原生锚点要求，本轮不将未验证的框架迁移作为评分收益。

目录在对应责任迁移时建立，不先建空目录或只搬文件。上述文件夹不改变现有项目数量和运行进程。现有显式源码链接、构建资源和发行清单随对应切片更新，不进行独立的大规模目录改名。

## 如何证明 locality 和 leverage 提升

| 代表性变化 | 当前需要理解的内容 | 目标修改范围 |
| --- | --- | --- |
| 调整菜单反馈文案 | 共享呈现以及 Linux/GTK/Qt 等对中文提示的身份比较 | 共享 Presentation；真正布局变化才修改相应 renderer |
| 修正编辑后回源的继续规则 | Capture、Return、Stop、浏览器/教程专用字段与多处回显 | 对应交互操作、Core 产品判定及提供真实证据的 adapter |
| 修正设置保存后的通知失败反馈 | SettingsStore 和两个宿主对 Revision/异常的推断 | 设置提交结果与共享呈现；平台 adapter 仅处理自己的副作用 |
| 增加一种真实输入 adapter | 宿主状态分支、界面身份约定、系统写回能力 | 实际平台 adapter 与其声明能力；不复制会话、模型和产品设置规则 |

以上是实施后的验收目标。只有目录变短、类变多、文件变小或测试数量增加，不算完成。

其中，浏览器回源继续规则的修改在目标中落到对应操作及其输入结果映射：主 Capture 只将匹配结果交给原操作，主 Stop 只退休当前操作，二者不再知道 browser Replace 的内部阶段；原生 adapter 仍核对真实编辑事件与焦点，Core 仍拥有稿件基准。文案变化不再需要修改 GTK/Qt 中的身份比较，通知失败分类不再需要修改两个宿主的提交推断。这样的删除映射才证明 locality 提高。
