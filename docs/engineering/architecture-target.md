# 架构约束与演进准则

本文规定后续架构修改必须保留的产品行为、职责边界和迁移退出条件。当前系统、模块及进程视图见[系统架构](architecture.md)，具体实现语义见[会话合同](session-runtime.md)与[模型运行架构](model-runtime.md)。

架构实施收敛不代表原生交互、模型质量或完整产品验收通过。

## 产品依据保持不变

架构调整的目的，是让每条产品规则有明确的所有者，并减少一次行为修改波及的模块。调整必须保留已有合法路径。安全拒绝不能代替补齐承诺的输入能力，当前实现限制也不能缩小产品范围。

产品依据包括[冻结规格](../product/TypeLay_产品规格_v1.0.md)、[已接受增量](../product/README.md)和[应用支持](../product/application-support.md)。交互与外观以[浮层原型](../design/TypeLay_UIUX_Prototype.html)、[设置与托盘原型](../design/TypeLay_Tray_Settings_Prototype.html)及[设计系统](../design/system/README.md)为准。架构决策仍受 [ADR-0001](../adr/0001-workspace-and-delivery.md)、[ADR-0002](../adr/0002-on-demand-and-direct-write.md)、[ADR-0003](../adr/0003-cross-platform-runtime.md)和 [Linux 原生锚点 ADR](../platforms/linux/adr/0004-native-anchors.md)约束。

| 产品行为 | 后续修改必须保留的结果 |
| --- | --- |
| 用户在原输入框工作。 | 原输入方式、浮层锚点、滚动、多显示器和不抢焦点要求保持。合作组件限制仍是实现边界。 |
| 用户选择自动或按需模式。 | 自动模式跟随输入，按需快捷键开启原字段的持续体验。离开焦点家族仍按原规则结束。 |
| 用户直接替换文本。 | 任务优先使用选区，否则使用当前原框。任务绑定触发源，不预览、不抢焦点、不发送。 |
| 用户继续输入或使用 IME。 | 结构、选区外文本和输入法要求保持。旧结果可以成为预览，不能据此获得新许可。 |
| 用户编辑译文并回源。 | 模型不覆盖人工稿。第一次 Tab 回源，下一次 Tab 才能接受；鼠标回源保留同一产品语义。 |
| 用户接受并撤销。 | 原目标、按次、IME、版本与时效重新确认。源端已执行的回执不触发第二次写入，真实 Undo 保持。 |
| 用户暂停、排除或退出。 | 敏感字段先于正文读取被拒绝。新操作停止后，已派发写入仍由原所有者结算。 |
| 用户更改语言、风格或术语。 | 设置作用范围和人工稿关系保持。技术能力与产品采用分别确认，重构不开放未通过的质量门。 |
| 用户准备本地模型。 | 安装需明确选择，本地推理和无默认历史保持。Index 默认及旧 Argos/Hy 库存遵守已接受规则。 |
| 用户使用设置、托盘和支持管理。 | 即时设置与整体草稿提交各自保留。模型可用、接入连接和当前字段能力分别报告。 |
| 用户完成首次练习。 | 模型准备、真实用户动作和练习完成分别确认。重启、取消、进度保存与撤权条件保持。 |

B-01、B-02、B-03 及模型质量缺口继续由现役平台和产品文档记录。改名、拆文件或抽象接口都不能关闭这些缺口。

## 每项事实只有一个权威所有者

源码目录与依赖见[当前生产边界](architecture.md#生产边界)。下表规定修改时不能混淆的事实。

| 所有者 | 唯一负责的事实 | 其它模块可以持有的内容 |
| --- | --- | --- |
| Core 会话 | Core 保存源快照、候选、人工稿、产品状态和纯判定。 | 原生执行者可以保留执行所需的快照和许可副本，视图控件可以保留即时编辑内容。 |
| Runtime 会话与具体交互 | Runtime 管理异步请求、操作身份、期限、结果代次及副作用安排。 | 宿主提交真实观察和意图，不解释具体操作的内部阶段。 |
| Runtime 写入记录 | 原记录接收实际执行结果，并记录一次终态。 | Core 只把终态应用到仍匹配的当前会话；平台独立证明实际执行事实。 |
| 直接任务 | 任务保留触发时的原字段、选区、配置和阶段。 | 当前前台会话可以独立变化，不能替任务换目标。 |
| 平台输入适配器 | 适配器拥有原生身份、连接、焦点、IME、按次和执行记录。 | 共享逻辑只比较不透明身份，视图只取得冻结事实。 |
| 共享呈现 | 呈现模块生成显示值和交互身份。 | 视图负责控件、布局和真实事件，不根据文案推断权限。 |
| 设置模块 | SettingsStore 拥有已提交值、版本和实际提交结果。 | 视图保留本次草稿，平台副作用适配器报告系统设置的实际结果。 |
| 练习进度 | 协调器记录本次练习已确认的里程碑。 | 自有源绑定、reader 和许可继续由会话及输入适配器管理。 |
| 模型客户端 | ModelClient 拥有连接、请求、冻结加载计划和发布结果。 | worker 提供推理结果及能力；两者都不拥有源字段焦点或写入权限。 |

这些责任不要求每项建立独立项目或常驻进程。现有串行事件循环负责协调，不增加通用工作流、消息总线或第二份状态权威。

## 接口隐藏什么

每个接口服务真实生产消费者。接口应交付可用的结果语义，让调用者无需理解内部回调阶段。

| 边界 | 调用者知道什么 | 实现内部处理什么 |
| --- | --- | --- |
| 宿主与会话 | 宿主提交观察、固定种类的意图和原请求结果，取得呈现。 | 具体操作处理开始、异步等待、回源重验、退休和迟到结果。 |
| 会话与异步输入 | 调用者使用 Capture、Return 和 Write，结果关联原请求。 | 适配器核实句柄、连接、文档和焦点，区分未派发、已知拒绝、失权和未知。 |
| 会话与即时输入 | 调用者消费真实命令通知，并发布或撤销短期许可。 | 源线程确认原按次并同步执行，不能等待模型或用异步 RPC 替代按键所有权。 |
| 呈现与视图 | 视图取得显示值及身份，意图携带实际展示的身份返回。 | 共享模块投影产品状态，原生实现检查控件、IME、几何与事件真实性。 |
| 保存入口与设置 | 调用者提交变更、期望版本、确认和取消状态，取得实际提交版本。 | 设置模块安排准备、最终重验、持久化、通知和副作用结果。 |
| 练习与会话及输入 | 教程发起既有动作，消费属于原 run 和计划的确认里程碑。 | 自有源适配器处理真实绑定与退休，Core 处理源文和草稿基准。 |

共享结果不能用一个成功布尔值抹去不同失败含义。真实证据必须先迁入新所有者，再删除旧字段；消费者仍依赖的证据不能被删除后改为猜测。

## 关键模块的维护约束

### 1. 译文会话模块管理具体交互的寿命

具体操作拥有本次身份、原目标、原期限、回执匹配和退休逻辑。普通回源、浏览器 Replace、源端重译、术语交接和自有源 Keep/Replace 保持各自含义。模型请求、直接任务和已派发写入有独立寿命，不能被一个总状态枚举强制串行化。

操作在 Render 或 await 前登记自身，防止真实 UI 回调重入后旧操作继续派发。操作退休后只收束自己已派发的结果，不能清理后继操作。主 Capture 分派观察，主 Stop 退休当前操作，两者不重新接管浏览器或教程的内部阶段。

修改一个回源分支时，规则应落在对应操作、Core 判定和提供真实证据的适配器。若宿主必须重新拼装专用阶段，说明复杂性已经泄漏回调用者。

### 2. Linux 源字段模块独占平台交互记录

Input 构造、验证和退休 peer、绑定观察、原生操作、返回关联及撤权记录。Overlay 取得不可变的连接与呈现事实，提交具体意图。Overlay 不重新读写 Input 的私有操作字典。

GTK3/4 共用纯协议解码和身份比较，控件及 IME 生命周期保留在各自适配器。Qt 和浏览器保留各自语言及事件线程。共享投影和明确合同维持共同语义，不为跨语言重复引入代码生成框架。

观察身份或断连规则的宿主修改应集中在 Input。原生接收者仍须最终检查身份、焦点、版本和 IME；这些检查由能观察事实的执行者负责，不能因共享层已检查而删除。

### 3. 呈现模块区分显示刷新与交互身份

显示序号只丢弃乱序画面。交互身份关联本次目标与操作，草稿版本记录真实编辑，动作版本关联动作条件。文案、颜色和菜单反馈不能决定操作寿命。

| 变化 | 呈现和交互的处理 |
| --- | --- |
| 文案、颜色或菜单反馈变化。 | 呈现更新显示序号，原操作身份及期限保持。 |
| 当前稿收到精确回显。 | 真实编辑版本未变时同步显示，更新的本地稿不被覆盖。 |
| 用户再次编辑，包括改回原值。 | 草稿版本推进，依赖旧稿的 Replace 意图永久失效。 |
| 当前表单的动作资格被撤销。 | 对应动作单向失效，合法的只读表单可以继续显示。 |
| 源文、配置、模型或窗口事实变化。 | 对应操作按产品规则决定继续或退休，显示刷新不能替代这种判断。 |
| 旧连接、旧视图或旧动作消息晚到。 | 已退休所有者拒绝继续；原已派发写入的回执仍交原结算者。 |

原生适配器可以因真实失活立即退休操作，宿主回显不能复活它。身份不授予读取、编辑、按键消费或写入能力，也不续租。每条连接只解释已协商的协议版本，未知行为字段按严格 schema 拒绝。

### 4. 设置模块提供完整提交结果

设置模块先冻结确认值并校验基线，必要时等待源退休，再重核版本和取消。文件原子替换是提交点。外观、风格、术语与一般设置保留各自影响范围，不能统一改成保存即清空会话。

| 场景 | 保存入口必须取得的结果 |
| --- | --- |
| 等待退休期间取消，或基线版本变化。 | 请求未提交，不继续执行副作用或文件写入。合法草稿按原规则保留。 |
| 登录启动已改变，随后文件保存失败。 | 文件未提交，内存保留旧持久值，系统副作用已发生。界面报告两件事实，不自动补偿或重试。 |
| 登录启动抛错且结果无法确认。 | 文件不进入提交，外部副作用标为未知。 |
| 文件替换成功，通知观察者失败。 | 结果携带真实版本并标明已提交，界面提示通知问题。 |
| 规范化后与持久值相同。 | 仍执行原文件保存并报告失败；成功后不触发无意义的重配或副作用。 |

提交点之后的取消和窗口关闭不能改写保存事实。副作用重试来自新的用户动作，并重新读取当前基线。两个宿主不通过 Revision 差值或异常类型推断提交点。

## 必须通过的交互走查

修改相应责任后，用真实生产入口观察下列结果。测试依据是受影响的用户场景，不能用文件数、测试数或类的大小证明架构改善。

| 场景 | 必须保留的结果 |
| --- | --- |
| 自动预览更新。 | 元数据检查先于正文读取，旧请求不能覆盖新源文。旧预览没有接受资格。 |
| 编辑后两次 Tab，或鼠标回源。 | 人工稿保留，第一次回源零写入，新源确认前没有新许可。 |
| 浏览器重译确认期间再次编辑。 | 新稿保留，旧 Replace 不丢弃新稿、不重发，实际回源仍由原操作收束。 |
| 术语表单引起菜单或提示变化。 | 纯显示变化保留表单，真实源变化仍退休旧操作。 |
| 直接任务期间切换应用。 | 任务只尝试写回触发源，不抢焦点、不改新框、不发送。 |
| 源端同步接受的回执晚到。 | Runtime 只结算原记录，不补写，不复活旧候选。 |
| 写入与暂停、设置变化或断连重叠。 | 新许可撤销，原记录保留，未知结果隔离原目标且不重试。 |
| 教程完成或重新开始。 | 实际撤权确认先于完成或新练习，旧 run 回执不能完成新 run。 |
| 设置已保存但通知失败。 | 反馈保留已提交事实，用户不会因错误结果重复副作用。 |
| 模型切换、准备失败或退出。 | 原所有者验证候选、退出及库存，未知发布不算成功，使用中的模型不被删除。 |

### 回源操作如何交还结果

回源合同区分可继续编辑、确认返回后等待新观察、完成产品确认、失权和结果未知。各路径继续使用原生证据及原期限，不把动作期限施加给整段人工编辑寿命。

| 路径 | 返回与完成条件 | 拒绝和晚到结果的处理 |
| --- | --- | --- |
| 普通 Tab。 | `ReturnFromEditor` 先登记操作并撤许可，再请求回源。精确确认后重新 Capture，Core 用 `ConfirmSourceReturn` 校验原编辑基准。 | 明确未完成返回且原编辑器仍合法时，取消本次回源并继续编辑。失权或未知不能凭旧稿恢复资格。 |
| 普通鼠标。 | Capture 观察到原字段实际获焦并取得合法新快照，Core 沿 Observe 确认回源。 | 旧捕获不能确认新会话。源文改变仍按原 Core 规则处理，不统一拒绝合法鼠标回源。 |
| 浏览器 Replace。 | 真实事件冻结期限和草稿版本，操作等待匹配 ACK 后再捕获。未再编辑且动作仍有效时才 Retranslate。 | 后来真实编辑永久废弃旧丢稿意图，回源后按当前人工稿处理。明确未派发或已知拒绝且编辑器合法时保稿；失权或未知退休。 |
| 自有源 Keep。 | 旧 reader 已确认撤权，真实 Tab 获得精确返回回执，新源匹配 DormantEdit。新 binding 经过重入检查及 reader 安装后，才可能提供接受资格。 | 未受理且本地编辑仍合法时保稿。基准已消费后失败则退休，不恢复旧绑定或猜测普通源。 |
| 自有源 Replace。 | 真实确认创建一次丢稿意图。撤权、精确返回、新源确认及新 reader 安装后，再次捕获通过才完整重译。 | 本地稿不先成为接受候选。旧安装回调不能作用于新 opening，失败不重放 Replace。 |

浏览器回源 ACK 前的后来草稿只暂存在同一编辑器的原操作。ACK 到达后，Runtime 在同一串行调用中依次取消 Core 回源、更新稿件、重新请求回源，中间不发布许可或模型任务。随后新捕获按普通人工稿规则确认。文字改回原值也属于真实再编辑。

### 正常关闭先交还责任，再释放接收者

`ShutdownAsync` 负责停止新操作、撤销许可、接收原回执并返回有界结算摘要。宿主先完成退出确认、未保存草稿处理和练习退出条件；用户取消退出时不启动关闭。

关闭期间，原串行循环、`IInputMonitor.TryRead`、输入连接和已派发继续体保持可用。Runtime 停止新的 Capture、模型请求和写入派发。预算内仍无法确认的原操作记为 `OutcomeUnknown`，不延长原生许可，也不无限等待外部应用退出。

| 实际路径 | 关闭时保留的责任 |
| --- | --- |
| Windows 源端同步接受。 | Hook/Broker 的原计划回执交给结算者。具体 source-message 路径的 Quiet 只负责原生资源退休，不能代替 Verified。 |
| Windows 异步写回与直接任务。 | 原调用交回原执行记录。停止 Broker 不能证明外部字段没有写入。 |
| 浏览器及 GTK/Qt 合作源。 | 原 peer、document、target 对应的回执结束原记录。断连只证明连接结束，缺少终态仍为未知。 |
| Linux 直接任务。 | Input 保留原调用和 issued 记录，直到 DesktopInput 交回 WriteReceipt 或按原预算记为未知。 |
| Windows 正常退出。 | `Program.Quit` 在 WPF Dispatcher 仍运行时等待 ShutdownAsync，随后才调用 app.Shutdown。 |
| Linux 正常退出。 | Python desktop、DesktopLink 和 .NET EventLoop 经现有私有通道完成交还，随后才取消任务、关闭 Input 和退出循环。 |
| 异常退出或通道已断。 | 平台继续现有安全释放，仍可能执行的操作保持未知。崩溃后不保证能收到回执，也不自动恢复写入。 |

写入在发布许可或实际派发前登记。同步回执和异步返回只能使原记录终结一次，Core 当前状态不成为第二份终态权威。会话退休不清除原目标隔离。

完整计划仅在执行和结果校验期间持有。确定终态或转为未知后，共享侧释放正文，留下必要关联与结果事实。原生缓冲由原所有者等待 Quiet 或退出证明后释放。记录使用既有容量和期限，不增加持久操作日志、正文历史或命令队列。

## 教程、模型与 UI 技术栈的范围

练习进度只观察确认结果。真正自有源的安装、捕获、连续性、回源和撤权仍走实际输入适配器。删除公共上下文里的旧字段前，必须确认真实证明已有唯一接收者。完成保存失败可保留本次 run 的无正文完成事实，关闭、重启或实际配置变化会清除它。

ModelClient、ModelLoadPlan、Protocol、worker、库存锁和原生后端各有现役职责。平台宿主继续拥有进程、连接和安装路径。模型切换不改变输入权限，也不要求会话理解原生模型实现。

此前确认的 GPUI 选择保持，本轮架构改造没有实施前端迁移。WPF、GTK、原生 GTK/Qt 和浏览器视图继续作为生产消费者。后续视图替换仍须满足已确认原型及原生锚点要求，未验证的框架迁移不能计作架构收益。

## 源码归属与依赖

Core 保持纯产品规则。Runtime 按 Sessions、Presentation、Settings、Practice 和 Models 组织，Protocol 不反向引用 Core。平台内部的连接、控件及系统副作用留在 `src/windows` 或 `src/linux`。共享浏览器脚本留在 `src/shared/browser`。

这些目录表达已存在的职责，不新增项目、常驻进程或依赖容器。修改归属时同步处理显式源码链接、构建资源和发行清单。测试只依赖生产边界，生产实现不反向依赖测试 runner。完整模块导航见[当前架构](architecture.md#生产边界)。

## 迁移顺序与退出条件

原架构目标已实施，不再维护 M0 至 M6 调度图。后续替换某条生产路径时，仍先确认要保持的用户行为，再按消费者切换，最后删除失去用途的旧实现。实现切换完成与平台验收完成是两件事实。

| 修改的责任 | 旧实现可以退出的条件 | 必要观察 |
| --- | --- | --- |
| 设置提交。 | 两端现役保存入口消费明确结果，不再推断提交点。 | 实际保存、取消、保稿、通知失败及系统副作用部分成功或未知得到区分。 |
| Linux 源字段。 | Overlay 不读写 Input 私有操作字典，每项原生记录只有一个构造和退休位置。 | 真实回源、断连和 peer 更换不会让旧结果更新新视图。 |
| 呈现身份。 | 各视图不再用文案或完整视图相等决定交互寿命。 | 显示刷新、草稿 ABA、源失效和未知协议各自走正确路径。 |
| 具体交互及写入结算。 | 主 Capture/Stop 不解释专用阶段，旧字段和重复结算路径退出。 | 普通及鼠标回源、直接任务切焦点、同步回执和关闭交叠保持原结果。 |
| 练习进度。 | 进度不参与授予权限，普通会话不解释教程步骤。 | 真实开始、编辑回源、完成撤权和重启均绑定原 run。 |
| 目录和发行。 | 无现役消费者的临时转发、旧路径及失效说明删除。 | 受影响构建与发行清单正确，必要搬迁包能够启动、正常退出并保留用户数据。 |

一个切片内，一项状态只有一个写入所有者，同一交互只使用一套身份规则。同步源写入不能通过双写验证。兼容转发只保留到实际消费者切换完成，随后删除。

### 用现有生产入口证明职责已经迁移

验证从实际保存入口、视图意图、输入结果或模型连接进入。共享规则使用现有公开端口回归，真实适配器使用必要的进程或用户路径。旧测试只有在所保护行为已有等效入口，或确无现役行为时才删除。

先复用已有有效证据。只有现有测试不能观察新的职责边界或已知风险时，才增加验证。真实 GUI 使用隔离图形会话，软件合同不能代替物理输入、IME、Undo 或逐页视觉验收。

诊断沿现有 Trace、协议拒绝和原生回执记录责任位置。记录只包含原操作关联、阶段和原因，不含源文、译文或正文指纹。产品规则拒绝、协议不匹配、原生执行结果和环境失联分别报告，未知结果不能改写为确定失败。

## 如何证明修改范围与跨平台复用得到改善

修改是否集中、规则是否被真实消费者复用，应由代表性变更来判断。

| 变更 | 预期修改范围 |
| --- | --- |
| 调整菜单反馈文案。 | 共享 Presentation 负责文案。只有实际布局变化才修改对应视图，原生身份比较不随文案变化。 |
| 修正编辑后的回源继续规则。 | 对应交互操作、Core 判定和真实输入证据映射承担修改，主 Capture/Stop 不增加专用阶段。 |
| 修正保存后的通知失败反馈。 | 设置结果分类及反馈消费者承担修改，两个宿主不恢复提交点推断。 |
| 增加真实输入适配器。 | 新后端实现本机身份、能力和执行合同，不复制会话、模型及产品设置规则。 |

文件变小、目录变短或测试数量增加都不足以证明改善。有效证据是某条规则有唯一修改点，调用者只依赖稳定结果，原生最终检查仍由真实执行者完成。
